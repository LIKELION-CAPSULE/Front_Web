# CAPSULE Web

노트북 앞의 시간을 함께 보내는 AI 메이트 서비스 CAPSULE의 프런트엔드입니다. 11/22 최종 기획에 맞춰 기존 스터디 버전에서 웹 베타로 전환 중입니다. `Front_Web` 안에서 독립적으로 실행하며, 옆의 `Landing_Page`와 의존성·설정을 공유하지 않습니다.

## 로컬 더미 모드 · 2026-11-22

`npm run dev`는 기본적으로 **로컬 더미 모드**로 실행합니다. `.env.local`의 `VITE_DATA_SOURCE=mock`을 사용하며, 실제 백엔드를 확인할 때는 `VITE_DATA_SOURCE=api`로 바꾸고 개발 서버를 재시작합니다. `npm run build`로 만든 운영 빌드는 항상 실제 API를 사용합니다.

더미 모드에서는 로그인된 샘플 계정으로 시작합니다. 실제 채린 Live2D·표정 8개, 연결/재개/종료, 이전 대화, 기록/달력, 프로필, 출석/초대 원장을 이 브라우저에서 확인할 수 있습니다. 오른쪽 아래 **로컬 더미** 도구에서 일반·기록 없음·느린 응답·실패 후 재시도·크레딧 소진·로그인 전 상태로 초기화할 수 있습니다. 개발 UI 검토 패널 링크도 이 도구에 있습니다.

음성/고급 모드 차감과 초대한 친구의 첫 연결 완료는 도구에서 시뮬레이션합니다. 실제 STT/TTS·목소리·립싱크·LLM 응답·다른 기기 동기화는 제공하지 않습니다. 대사는 기존 검토 샘플을 재사용하고, 친밀도/해금은 확정 정책으로 생성하지 않습니다. 남학생은 준비 중 표시만 있습니다. 더미 데이터·복구 캐시·설정은 실제 API 모드와 다른 저장 영역을 쓰며, 더미 코드와 `local-assets/chaerin` 모델은 운영 빌드에 포함하지 않습니다. [설정·범위](docs/LOCAL_MOCK_MODE_2026-11-22.md)를 참고하세요.

아래 API 연동 현황은 **실제 API 모드/운영 빌드 기준**입니다. 로컬 시뮬레이션이 서버 기능의 준비 완료를 뜻하지 않습니다.

## 웹 베타 P0 전환 진행 · 2026-11-22

홈은 서버에 실제로 있는 출시 메이트만 표시하며 기존 9개 룸으로 채우지 않습니다. 메이트 상세(`/mates/:mateId`)에서 목표 시간 선택 없이 연결(`/connect/:mateId`)하고, 기본 SSE 채팅·카메라·보기 전환·종료 후 연결 기록(`/connections/:id`)을 사용합니다. 내 메이트(`/mates/me`)는 실제 연결 이력이 있는 메이트를 보여 주는 초기 화면입니다. 남학생은 백엔드 등록 대기입니다.

11/22 사용자 추가 요청으로 **기존 말포이 제작물을 화면 이름 ‘채린’으로 임시 재사용**합니다. 로그인·홈 배너·카드·상세·기록에 기존 이미지를 표시하고, 홈 배너/사용법 이미지는 메이트 API 목록이 비어도 확인할 수 있습니다. 서버 이름 `말포이 TS`/`말포이`는 채린으로 표시하되 실제 룸/캐릭터/세션 ID와 연결 모델 URL은 유지합니다. 별도 채린 데이터가 있으면 그 항목을 우선합니다. 서버 프롬프트·생성 대사·미연동 기능을 새로 구현한 것은 아니며, 최종 출시 제작물 확정과 구분하는 임시 확인 상태입니다.

설정 모달은 프로필/설정/보안으로 바꾸고 실제 브라우저 기기 선택을 연결했습니다. 로그인 배경은 채린 이미지로 바꾸면서 기존 모자이크 효과를 유지합니다. Document PIP의 작은 창·같은 모델 이동/복귀·최근 대화·종료 정리를 구현했고, Chromium의 실제 PIP와 WebKit의 미지원 안내를 검증했습니다. PIP 안 음성과 실제 서버 Live2D의 장시간 동작은 미검증입니다.

이전 룸·준비·스터디·캡슐 카드 주소는 현재 메이트/연결 기록으로 이동하며 자동으로 연결을 만들지 않습니다. 결제 주소는 친구 초대로 바꿨고, 결제·영수증 원본은 개발용 보관 화면에만 남겼습니다. 실제 서버 보고서·대화 캐시만 계정별로 이전하며 샘플 기록·잔액·패스·일정을 베타 데이터로 사용하지 않습니다. 기록은 캠 측정 시간과 연결 시간을 구분합니다. 기존 스크래치·호버·타이핑·숫자 전환·달력 효과는 유지합니다.

현재 서버의 룸/세션 계약을 재사용하는 전환 단계입니다. 음성·새 친밀도·출석/초대 크레딧·생년월일·호칭/자기소개와 서버 기록 목록/캠 시간 저장은 아직 완료되지 않았습니다. 크레딧·초대 화면은 문서의 구조만 연결했으며 실제 계약 전 수치는 `—`, 코드 복사·보상 요청은 비활성입니다. 아래 기존 시연 설명은 전환 이력입니다. [P0 목표·완료 기준](docs/CAPSULE_WEB_BETA_P0_PLAN_2026-11-22.md)과 [현재 API 계약·미연동 범위](docs/CAPSULE_WEB_BETA_API_GAPS_2026-11-22.md)를 기준으로 진행합니다.

현재 API와의 [상세 대조 결과](docs/API_AUDIT_2026-11-22.md)를 반영해 연결 시작에는 `targetMinutes: 50`을 전송하고, 복구 heartbeat에도 시간 본문을 보냅니다. 이 값은 구형 API의 호환 입력이며 베타 화면의 목표 타이머로 사용하지 않습니다. 목표 없는 서버 생성·종료 판단은 추가 변경이 필요합니다.

가입/온보딩에는 생년월일 입력과 만 14세 검증, 프로필에는 호칭·나에 대해 입력 구조를 추가했습니다. 백엔드 개발 브랜치에도 저장 필드가 없어 **신규 가입·미완료 온보딩은 새 계약 연동 전까지 완료할 수 없습니다**. 생년월일을 버리고 기존 API로 가입시키지 않습니다. 기존 로그인·닉네임/아바타 수정은 유지하며 추가 프로필 필드는 비활성입니다. 전체 신규 저장 흐름은 명시적인 개발용 모의 포트에서만 검증합니다. 새 인증을 시작할 때 이전 계정의 화면 상태와 모델을 해제하고, 오래된 응답이 새 계정을 덮어쓰지 않도록 처리합니다.

메이트 상세의 독립적인 미리보기·목소리 샘플 제어와 메뉴 안 대화 초기화 확인창을 구성했습니다. 현재 API는 연결 전 모델·샘플·초기화를 제공하지 않으므로 **운영에서는 기존 이미지와 효과를 유지하고 샘플 재생·초기화 실행을 비활성화**합니다. 개발용 `mateContract`에서만 이미지 모델·무음 WAV·모의 초기화 응답으로 로딩/재시도·재생 정리·확인창·캐시 보존을 검증합니다. 실제 음성 제작물이나 서버의 대화/기억/친밀도/해금 삭제 연동을 완료한 것은 아닙니다.

서버가 `SESSION_ENDED`를 알렸는데 로컬 진행 상태 때문에 기록 화면에서 다시 연결 화면으로 돌아가던 오류를 수정했습니다. 해당 연결의 상태·모델·미디어/PIP를 정리하고 실제 보고서를 조회하며, 일시적 서버 오류는 연결을 유지합니다. 기존 계정의 늦은 응답이 현재 연결에 영향을 주지 않도록 검사합니다.

추가 확인 결과 현재 백엔드의 TTS 생성은 `null` 반환 상태이고, 연결 종료 후 대화 원문은 요약 후 삭제됩니다. 공개 약관도 본문 준비 중이어서 **신규 가입·카카오 시작에는 서버 약관 전문 게시가 필요**합니다. 사전예약 약관을 서비스 약관 대신 표시하던 fallback을 제거했고 기존 이메일 로그인은 유지합니다. 실제 음성·원문 대화 기록·새 계정 저장을 모두 사용할 수 있는 상태는 아닙니다.

모델 실패 뒤 이미 끝난 임시 연결 ID를 계속 재개하던 오류와 계정 전환 뒤 이전 요청의 작업 잠금이 남던 문제를 수정했습니다. 재개 응답의 ID·화면·계정도 확인합니다. 설정에는 문서의 메이트 음성 토글·안내를 추가했지만 실제 생성/차감 계약 전까지 꺼짐·비활성이며 음성 연동 완료를 뜻하지 않습니다.

11/22 사용자 확인에 따라 음성·이전 대화·크레딧 API는 준비 전으로 유지합니다. 연결 생성/재개가 서버에서 성공하면 모델 준비 실패나 화면 이탈과 관계없이 홈 캐시를 갱신합니다. 늦은 종료 응답은 해당 연결만 정리하며 새 연결의 모델·상태를 보존합니다. 연결 기록의 대화 수에는 전송 대기 메시지를 포함하지 않습니다.

프런트 단독 P0/P1 작업으로 전체 화면 연결/기록의 문서 제목과 본문 포커스를 보완했습니다. 사용자 확인 후 최종 문서의 새 3단계 사용법을 `/?tutorial=1`과 홈의 **사용법 보기**에 추가했습니다. PIP 말풍선 설정은 열린 창에 즉시 반영하며 이 브라우저에서 계정별로 저장합니다. 서버 설정 저장은 아닙니다. 내 기록에는 메이트별 썸네일·기간 내 함께한 시간/횟수, 연도 이동/올해 복귀와 선택 날짜의 가로 스크롤 노출을 추가했습니다. 전체 서버 기록·새 친밀도/해금·음성·크레딧 기능은 계속 연동 대기입니다.

[사용 방법·검토 범위·확장 안내](src/features/review/README.md)를 참고하세요.

## 현재 API 연동

- 2026-11-22 기준 기본 백엔드는 `https://api.capsule.ai.kr`입니다. 브라우저의 `/api/backend/*`는 서버 게이트웨이를 통해 같은 경로의 `/api/*`로 전달합니다. `BACKEND_API_ORIGIN`으로 다른 서버를 지정할 수 있습니다.
- 최신 성공 응답 `{ success: true, data: ... }`는 공통 `ApiClient`에서 한 번 해제해 화면에 전달합니다. 로그인·토큰 갱신·홈·프로필·일정·공부 세션·리포트에 공통 적용하며, 본문 없는 완료 응답도 처리합니다. `{ success: false, code, message, detail }` 오류 정보는 유지합니다.
- 스트리밍 대화는 `reply`의 누적 글을 표시하고 `done`의 원본 또는 감싼 응답을 처리합니다. JSON 응답으로 돌아오는 경우에도 같은 `data` 해제를 적용합니다. 최신 명세는 [공개 OpenAPI](https://api.capsule.ai.kr/v3/api-docs)에서 확인합니다.
- 실제 이메일 인증·회원가입·로그인·로그아웃과 쿠키 기반 토큰 갱신을 사용합니다. 기존 localStorage의 더미 로그인은 읽지 않으며, 미연동 기능의 체험 내역만 서버에서 확인한 계정 ID별로 저장합니다.
- 서버 룸·친구 ID와 선택한 목표 시간으로 공부를 시작하고, `FOCUS/AWAY/RETURN/BREAK`, 1분 heartbeat, 메시지·리포트·일정을 연결합니다. 자리 비움은 서버 계약의 연속 10초 기준이며, 자리 지킴률은 자리 지킴 시간 ÷ 공부 시간입니다.
- 카카오 로그인은 `.env.local`의 `VITE_KAKAO_REST_API_KEY`, `VITE_KAKAO_REDIRECT_URI`를 설정하고 같은 URI를 카카오 개발자 콘솔에 등록합니다. 현재 callback 경로는 `/oauth/kakao`입니다. 배포 환경에도 각각 값을 설정합니다.
- 로컬 개발·미리보기는 `http://localhost:3000`을 사용합니다. 추가 제공 자료의 등록 URI에 맞춰 `VITE_KAKAO_REDIRECT_URI=http://localhost:3000/oauth/kakao`로 설정합니다. [카카오·재설정 후속 반영](docs/KAKAO_LOGIN_REVIEW_2026-11-05.md)을 참고하세요.
- 브라우저는 동일 출처 `/api/backend/*`를 사용하며 Vite 개발/미리보기, Vercel 함수 또는 Cloudflare Worker가 Railway의 `/api/*`로 전달합니다. `BACKEND_API_ORIGIN`은 서버 설정입니다.
- 연결 상태·실제 검증 범위·대기 기능은 [API 연동 기록](docs/API_INTEGRATION_2026-11-05.md)에 정리했습니다. 아래의 기존 시연 안내에는 API 연결 전 데모 동작과 이전 UI 검토 이력이 포함됩니다.

## 이전 스터디 버전 시연 범위 (전환 이력)

아래는 기존 스터디 버전의 시연 기록입니다. 새 베타의 구현·연동 상태는 위 P0 진행 내용과 계획 문서를 기준으로 합니다.

- MVP 이후로 막아 둔 내 기록·친구·크레딧·충전 메뉴와 직접 주소, 룸·친구 블러를 해제했습니다. 서버에 없는 콘텐츠는 기존 9개 룸·19명 친구로 보완합니다.
- 준비 화면에서 함께할 친구와 대화 옵션을 선택합니다. 목표는 기본 50분이며 5~180분을 5분 단위로 조절합니다. 선택한 시간이 시작 요청·타이머·리포트에 반영되고, 목표에 도달해도 수동 휴식 전까지 계속 공부합니다.
- 서버에 있는 룸+친구 1명은 실제 공부 API를 사용합니다. 서버에 없는 룸·친구 및 여러 친구와의 공부는 로컬 타이머·샘플 대화·리포트·캡슐 카드로 연결합니다. 모델 URL이 없는 서버 친구는 기존 이미지를 표시합니다.
- API가 없는 잔액·충전·패스·대화 등급은 체험용입니다. 첫 사용 시 5,000 크레딧을 제공하며 실제 결제는 없습니다. 내 기록은 최근 30일 샘플과 이 브라우저에서 완료한 공부를 표시합니다.
- 더미 부분은 화면에 안내하고 계정별로 저장합니다. **[더미 항목·소스 위치·실제 API 교체 안내](src/features/dummy/README.md)**에서 전체 목록을 확인하거나 `rg -n 'DUMMY_API' src`로 찾을 수 있습니다.

## 공부 레벨과 호감도

두 값은 서로 독립적입니다. 공부 레벨은 친구와 함께 공부한 시간으로 올라가는 **Lv.1~5**이며, 호감도는 상호작용에 따라 오르거나 내려가는 **0~100** 값입니다. 공부 시간·선물 개수·메시지 수에서 호감도를 계산하지 않습니다.

호감도의 초기값과 상호작용별 증감 기준은 백엔드에서 결정합니다. 프런트의 `affection`은 친구 ID별 확정 점수만 보관하며, 서버 친구의 데이터가 없으면 `— / 100`으로 표시합니다. 서버에 없는 친구는 문서화된 체험용 50점을 사용합니다. `SET_AFFECTION`은 서버에서 확정한 점수를 반영하는 경계이며, 자동으로 점수를 적립하는 프런트 규칙은 없습니다. 기존 저장 데이터도 기록·프로필을 유지한 채 이 상태를 추가합니다.

레벨의 현재 600분 단위·그룹 참여 시간 배분은 기존 데모 규칙을 유지합니다. 최종 성장 기준은 백엔드 연동 시 확정합니다. 종료 리포트의 레벨 진행은 해당 세션 종료 시점 기준이며, 별도의 `현재 호감도`는 최신 확정값입니다. 호감도 변화 이력을 받기 전에는 리포트에 세션별 증감값을 만들지 않습니다.

리포트와 친구 화면은 같은 지표를 공유합니다. 제품 아이콘은 앞으로도 [AnimateIcons Lucide](https://animateicons.in/icons/lucide)에서 찾아 공통 `Icon`으로 적용합니다. [공식 소스·선택 기준](src/shared/ui/animate-icons/README.md)을 따릅니다. 리포트 수치는 [Tween UI Number Counter](src/shared/ui/number-counter/README.md)로 각 자릿수가 한 번 위로 회전하며, 숫자·단위의 기준선과 줄 높이를 맞춥니다. 날짜·Lv 단계와 미정값은 유지합니다. Arcade Pixel은 사용자 요청으로 제거했습니다. 캡슐 카드 버튼의 반복 빛 강조를 유지하고, 모션 감소에서는 정적으로 표시합니다. 리포트 상단의 룸명·완료 시각·자리 지킴률은 우측에 묶으며 공부 시간은 제목 아래에 표시합니다.

## 화면 흐름

```text
로그인 → 내 아바타 → 홈 → 스터디룸 상세
  → 목표 시간·친구·대화 옵션 선택 → 공부·대화 → 휴식
  → 종료 리포트 → 캡슐 카드·다음 약속 → 홈
```

| 경로 | 화면과 동작 |
|---|---|
| `/login` | 카카오·더미 계정 시작 화면. 로그인/회원가입 링크로 우측 전체 폼 전환. 회원가입은 비밀번호 확인 아래 닉네임 필수 입력(20자 이내), 약관 2개 필수 동의 및 전문 보기 (`?mode=login`, `?mode=signup`). 로그인 폼의 비밀번호 찾기는 이메일 입력 화면(`?mode=forgot-password`)으로 이동하며, 실제 재설정 메일 발송은 인증 API 연결 후 제공 |
| `/onboarding` | 헤어·의상·외모·배경의 샘플 옵션 선택. 회원가입에서 입력한 닉네임 유지 |
| `/?account=profile`, `/?account=schedule` | 홈 위에 계정 설정의 프로필 또는 일정 탭 표시. 일정에 `&add=1`을 붙이면 목록 카드 안에 일정 입력 폼 표시 |
| `/mypage` | 기존 주소 호환: 홈의 계정 설정 창으로 이동. `#schedule`과 `?add=1#schedule`은 일정 탭·일정 추가로 연결 |
| `/` | 첫 방문/이어하기 홈, 룸 탐색·저장, 진행 중인 세션 복귀 |
| 그 밖의 주소 | 홈으로 이동한 뒤 우측 상단 알림으로 안내. 새로고침 시 같은 안내를 반복하지 않음 |
| `/rooms/:roomId` | 룸 설명과 친구 관계, 공부 시작 |
| `/rooms/:roomId/prepare` | 실제 카메라·마이크 권한 및 로컬 얼굴 감지 확인, 캠 배경 선택(기본·블러·이미지 3종, 미리보기에 즉시 반영) → `?step=goal`에서 목표 시간·대화 옵션 선택 |
| `/study/:sessionId` | 1:1/1:3 공부, 포커스 보기, 타이머·일시정지·채팅·휴식·등급 변경, 하단 메뉴 **배경 바꾸기**로 캠 배경 변경(준비 화면 선택 유지) |
| `/reports/:recordId` | 전체 화면 완료 장면 위 좌측 채린·한마디, 우측 유리 패널의 공부 시간·자리 지킴률·자리 비움·복귀·공부 레벨 진행·현재 호감도. 모바일은 인물·대사·결과를 세로 배치 |
| `/capsules/:recordId` | 카드 색·PNG 저장·공유·날짜/시간 휠로 다음 공부 약속 |
| `/records` | 전체/스터디룸별 시간·이용일·최근 세션, 이전/다음 주·월 탐색 |
| `/characters/:characterId` | 친구별 관계·해금 콘텐츠·공부 시작 |
| `/credits` | 잔액·패스·통합 충전/사용/보너스 내역·샘플 영수증, 우측 상단 충전 버튼 |

`/characters`는 기본 친구 채린의 관계 화면으로 열립니다. 없는 룸·친구·기록은 찾을 수 없음으로 처리합니다.

## 빠르게 체험하기

1. 이메일 또는 카카오로 로그인하고 필요한 경우 아바타 설정을 완료합니다.
2. 원하는 룸에서 공부 시작 → 목표 시간·친구·대화 옵션을 선택합니다.
3. 공부 화면의 **쉬는 시간**으로 10분 휴식을 시작하고, **공부 이어가기**로 복귀합니다. 타이머는 `경과 시간 / 선택한 목표 시간`으로 표시합니다.
4. 대화 횟수 제한은 없으며 대화 등급과 크레딧은 체험용으로 선택·변경할 수 있습니다.
5. 종료 후 캡슐 카드 이미지를 저장하거나 다음 공부 약속을 추가합니다. 크레딧 충전·패스도 더미 상태로 연결됩니다.

헤더의 내 아바타를 누르면 **계정 설정** 창이 열립니다. 좌측의 중앙에 아바타와 닉네임을 배치하고 프로필·일정·보안 탭으로 우측 내용을 전환합니다. 로그아웃은 좌측 하단에 있으며, 작은 화면에서는 메뉴를 상단에 배치합니다. 보안 탭에 바로 보이는 이메일 입력으로 비밀번호 재설정 메일을 요청하고, `CAPSULE을 탈퇴합니다`를 정확히 입력한 뒤 회원탈퇴할 수 있습니다. 탭 전환 중 미저장 프로필과 달력의 주·기간·날짜 선택은 유지합니다. 프로필과 일정은 서버 API로 저장·조회합니다. 일정은 모든 친구가 함께 기억하는 공통 목록이며, 고정된 주간 달력 아래에서 목록만 스크롤해 종류·날짜·시간을 확인합니다. 예정/전체/지난 필터와 일정 추가 버튼은 같은 일정 카드의 하단에 고정합니다. 추가 버튼을 누르면 카드 안의 항목명·입력값 행으로 전환합니다. 종류는 선택 버튼, 날짜·시간은 직접 입력과 기본 선택기를 사용하며 저장·취소 후 목록으로 돌아옵니다. 별도의 마이페이지는 제공하지 않습니다.

공부 화면의 **확대 모드(V)**에서는 친구 카드를 눌러 크게 보기·원래 보기로 전환합니다. **말 걸기 모드(C)**나 헤더 대화 버튼은 오른쪽 공통 채팅 패널을 엽니다. 친구 토글로 상대를 바꾸면 각 대화 이력·입력 중인 내용을 유지하며 영상의 확대 상태는 바뀌지 않습니다. 넓은 화면은 사이드바, 1023px 이하는 배경 스크롤을 막는 드로어로 표시합니다. 공부·휴식에서 같은 패널을 사용하며 새 답장만 타이핑하고 이전 이력은 즉시 표시합니다. 입력창은 입력 시 확장되며 Enter로 전송, Shift+Enter로 줄바꿈합니다. 한글 조합 중 Enter는 전송하지 않습니다. 영상 위 유리 독에서 마이크·카메라·아바타/실제 캠·일시정지·계속·종료를 조작하며 데모 메뉴는 룸 제목 오른쪽에 있습니다. 헤더 시간은 `00:17:23 / 00:50:00` 형식이고 바뀐 숫자만 움직입니다. 자리 지킴률은 50% 미만 빨강, 50~80% 미만 흰색, 80% 이상 초록이며 미측정은 `—`입니다. 움직임 줄이기 설정에서는 패널·타이핑·숫자 효과를 생략합니다.

참고 사이트의 기존 조사로 활동 달력·자리 지킴률 링·공통 로딩을 추가했습니다. 조용히 집중 버튼과 전용 상태는 후속 사용자 요청으로 제거했습니다. 현재 52곳을 재조사한 뒤 메인 히어로의 큰 슬로건과 소개는 방문 상태별로 바꾸고, 우측 하단 대사를 초상화·이름·꼬리 없는 글래스모피즘 형태로 정리했습니다. 확인 범위·접근 오류·적용 판단은 [52곳 재조사 기록](docs/WELCOME_HERO_RESEARCH.md)에 있습니다. 재사용 컴포넌트는 `CompanionGreeting`, 전용 스타일은 `src/styles/welcome.css`입니다. 현재 메인 배너는 [호버 지우기 전환](src/shared/ui/hover-scratch/README.md)을 사용합니다. [채린·수아·다희 전용 가로 이미지](src/assets/welcome-banners/README.md)를 생성했으며, 현재 이미지와 HTML 대사는 하나의 마스크로 함께 지워집니다. 마우스가 지나간 자리에 다음 이미지와 다음 대사가 보이고 면적 40%가 지워지면 나머지를 정리한 뒤 다음 이미지로 순환합니다. 첫 방문·이어하기 문구와 버튼은 HTML로 관리합니다. 모바일·터치·모션 감소에서는 친구 선택 버튼으로 전환합니다. 이전 하프톤 시안은 현재 화면에서 연결을 해제했습니다.

기존 포스터의 잘림을 줄이기 위해 9종 모두 이미지 생성으로 전신 친구/그룹과 독립 배경을 만들었습니다. 메인화면은 [책상 없는 바닥 배경 9종](src/assets/scenes/seated-v1/README.md) 위에 앉은 모습을 보여 주고, 첫 룸에는 채린·수아·다희가 함께 나옵니다. 공부 화면과 기본 리포트에서는 [전신과 책상 레이어](src/assets/scenes/layered-v2/README.md)를 재사용합니다. **원본 포스터 / PNG 마스터 / 웹용 WebP / 투명 제목 이미지**를 분리했습니다. 메인화면 카드의 제목은 원본 서체를 참조한 [제목 이미지 9종](src/assets/room-titles/README.md)을 `RoomTitle`로 표시하고, 실제 이름은 대체 텍스트·검색·상세·기록에서 함께 사용합니다. [에셋 편집 가이드와 미리보기](src/assets/scenes/README.md), [배경/전경 생성 프롬프트](src/assets/scenes/generation-manifest.json), [제목 생성 프롬프트](src/assets/room-titles/generation-manifest.json)에서 교체 방법을 확인할 수 있습니다. `sceneArtwork`에 9종을 등록해 `RoomArtwork`와 Canvas 합성에서 같은 장면 ID로 사용할 수 있습니다.

로그인 히어로에는 랜딩페이지의 스터디룸 포스터 9종을 사용합니다. -10° 격자의 홀수 행은 오른쪽, 짝수 행은 왼쪽으로 흐릅니다. GSAP을 사용하는 [PosterMosaic](src/shared/ui/poster-mosaic/README.md)로 분리했으며, 포스터 목록과 이동 속도·회전은 `src/features/auth/posters.ts`와 컴포넌트 props에서 설정합니다. 모바일 상단 히어로, 일시정지·재생, 모션 감소 설정을 지원합니다.

데스크톱 좌우 영역은 **1.5:1(60%:40%)**이며, 좌측에는 포스터 격자를 보여 줍니다. 포스터는 `contain`으로 원본 이미지 전체를 표시합니다. 우측 폼은 가로·세로 중앙에 배치하며, 내용이 길면 우측 영역 안에서 스크롤합니다.

스터디룸은 **쌀쌀맞은 갸루짝꿍이 나에게만 친절하다! / 전교 1등을 이겨라 / 냥냥이가 날 그렇게 쳐다보면 집중할 수가 없잖아!! / 김상병의 두근두근 비밀연등 / 페보니우스 마법학교 / 모르는 일진이 나한테 말을 건다 / 쥬라기 독서실 / 뚝딱뚝딱 실험실 / 조선시대 야간 학습** 총 9종입니다. 새 6개 룸도 검색·저장·상세·공부·휴식 대화·리포트·캡슐 카드에 연결했습니다. 신규 친구 이름과 소개는 수정 가능한 더미 데이터이며, 전체 19명의 관계·기록을 각 ID로 관리합니다.

기존 룸·친구 ID와 저장 데이터 형식을 유지하므로 기존 브라우저 데이터로도 9종을 바로 볼 수 있습니다. 새 룸의 누적 기록은 실제 데모 세션을 마친 뒤부터 쌓입니다. 개별 인물 화면은 원본 포스터의 표시 영역을 `CharacterArtwork`에서 재사용하고, 룸과 기본 리포트·캡슐 카드는 분리된 배경/전경 레이어를 사용합니다. 채린·수아·다희의 종료 화면과 카드는 새 완료 전용 이미지를 사용합니다.

홈의 첫 방문·이어하기 문구와 룸 목록으로 이동하는 동작은 [홈·기간별 기록 가이드](docs/HOME_AND_RECORDS.md)에 정리했습니다. 내 기록은 주·월·년 선택에 따라 요약·달력·친구 시간·최근 스터디를 함께 바꾸며, 중복 이용일 카드와 MVP에서 제외한 랭킹은 제거했습니다. 기본 닉네임은 `꾸윙젠렝`이며 기존 데모 데이터의 이름도 기록을 유지한 채 이전합니다.

## 구현 경계

실제 카메라·마이크 권한, 영상 미리보기, 마이크 입력 레벨과 MediaPipe Face Landmarker 추론을 연결했습니다. 공부 중에는 Gesture Recognizer와 Object Detector(EfficientDet-Lite2)도 함께 사용해 딴짓·상태를 감지합니다. 준비 화면의 **카메라·마이크 켜기**를 눌러 확인하며, HTTPS 또는 localhost가 필요합니다. 마이크 권한이 없어도 카메라를 사용할 수 있고 카메라 없이 시작할 수도 있습니다. 준비→공부 화면 이동 중에는 같은 장치 연결을 유지하고, 종료·로그아웃·관련 화면 이탈 시 모든 트랙을 해제합니다. 재접속 후 권한 재획득은 사용자가 카메라 켜기를 눌렀을 때 수행합니다.

준비 화면에서 실제 영상으로 장치를 확인합니다. 공부·휴식 화면은 아바타를 기본으로 표시하며 독에서 실제 캠으로 전환할 수 있습니다. 카메라가 꺼진 상태에서 실제 캠 보기를 누르면 카메라 권한을 요청하고, 카메라를 끄면 아바타로 돌아갑니다. 아바타 보기로만 바꾸면 카메라 연결과 별도 숨김 영상의 얼굴 감지·자리 지킴률 측정은 유지합니다. 실제 캠은 같은 스트림을 음소거한 미리보기로 표시합니다. 준비 화면 제목 옆 물음표에서 카메라·마이크 권한의 목적과 로컬 처리·서버 미전송 안내를 확인합니다. 호버·키보드 초점·터치로 열고 Escape·외부 클릭으로 닫을 수 있습니다.

얼굴 감지는 사용자 기기의 GPU/CPU와 Web Worker에서 실행합니다. WebGL GPU 우선이며 추론 초기화가 실패하면 CPU/WASM으로 전환합니다. 준비 화면은 최대 초당 5회 처리하며, 느린 기기에서는 다음 프레임을 대기해 추론이 겹치거나 쌓이지 않습니다. 일시정지·휴식·숨김 탭에서는 추론을 중단합니다. 영상은 메모리에서만 처리하며 서버 전송·녹화를 하지 않고, 마이크는 로컬 입력 확인에만 사용하며 녹음·음성 인식·재생에 연결하지 않습니다.

공부 타이머가 흐르는 동안에는 같은 워커에서 얼굴(초당 10회)·손 제스처(초당 15회)·핸드폰(1초에 1회)을 모델별 주기로 감지합니다. 손·핸드폰 모델은 공부를 시작한 뒤 처음 필요할 때 불러옵니다. 감지 규칙은 **자리 비움**(얼굴 3초 미검출), **졸음**(양쪽 눈 감김 2초), **하품**(입 벌림 1초), **고개 돌림**(좌우 25도 이상 2초), **핸드폰**(3회 연속 검출), **손 흔들기**(1초 안에 좌우 방향 전환 2회)입니다. 기준값과 오버레이 켜기/끄기는 `src/features/media/behavior-constants.ts` 한 곳에서 조정합니다. 감지된 규칙 이름은 내 칸 왼쪽 위에 배지로 표시됩니다. 졸음·하품·손 흔들기·고개 돌림이 새로 시작되면 서버에 동작 이벤트(`DROWSY`·`YAWN`·`WAVE`·`HEAD_TURN`)를 같은 종류당 1분에 한 번 보내고, 응답의 표정과 대사로 친구가 반응합니다. 카메라 꺼짐·휴식·일시정지·숨김 탭에서는 보내지 않으며, 핸드폰과 자리 비움(서버 기준 10초 `AWAY`)은 동작 이벤트로 보내지 않습니다. 동작 이벤트는 상태 이벤트 흐름과 분리되어 자리 비움 반응 강도(1→2→3)를 끊지 않습니다. 서버로는 이벤트 종류와 시각만 보내며 영상과 감지 기록은 저장하지 않습니다.

공부·휴식 화면의 친구 칸은 공부 시작·이어하기 응답의 `character.modelJsonUrl`로 Live2D 모델(Cubism 5)을 그립니다. 공부 시작·이어하기 화면에서 모델과 텍스처를 먼저 준비하고, 준비가 끝날 때까지 기존 화면의 공통 스피너를 유지합니다. 주소가 없거나 준비에 실패하면 이전 화면에서 재시도 안내를 표시하며 다른 캐릭터 이미지로 대체하지 않습니다. `scale`과 `offsetX`·`offsetY`(칸 크기 대비 %)를 적용하고, 칸이 바뀌어도 WebGL 캔버스 하나를 옮겨 쓰며 공부 화면을 떠나면 정리합니다. 표정은 서버가 준 `expression.file`(모델 폴더 기준 경로)만 사용하며, 상태 이벤트 > 대사 > 동작 이벤트 순 우선순위와 최소 유지 시간으로 바꿉니다. 시선은 공부 중(일시정지 포함) 정면에 고정하고 휴식 중에만 커서를 따라가며, 움직임 줄이기 설정에서는 따라가지 않습니다. 조절 값은 `src/features/live2d/live2d-constants.ts`에 있습니다. PixiJS와 Live2D 엔진은 공부 시작·이어하기 때 미리 불러오는 별도 청크로 분리하고, Cubism Core는 `public/live2d/`에서 제공합니다.

MediaPipe의 영상 입력에는 CPU 추론을 쓰더라도 WebGL이 필요합니다. WebGL 자체가 차단된 브라우저에서는 원인을 안내하며 카메라 없이 진행할 수 있습니다. 첫 실제 얼굴 추론이 완료된 뒤 카메라 확인의 다음 버튼이 활성화됩니다.

카메라 관측 기반 집중률은 **얼굴이 보인 시간 ÷ 정상 측정 시간**입니다. 얼굴이 감지되지 않은 유효 구간은 미감지 시간으로 누적해 자리 지킴률을 낮춥니다. 준비 화면, 모델 초기화·오류, 카메라 꺼짐, 일시정지, 휴식, 숨김 탭, 1초를 넘는 프레임 공백은 측정에서 제외합니다. 프레임 수가 아닌 시간으로 계산하고, 공부 중 자리 지킴률 표시·종료 리포트·내 기록에 같은 관측값을 사용합니다. 측정이 없는 새 세션은 `—`로 표시하며 더미 자리 지킴률을 생성하지 않습니다. 이전 샘플 기록은 유지합니다.

측정 누계는 초당 한 번 저장하고, 일시정지·카메라 끄기·종료 시 마지막 유효 구간을 반영합니다. 재접속 시 누계를 이어 가되 오프라인 구간을 추가하지 않습니다. OAuth·LLM/TTS·결제·서버 저장은 후속 연결 대상이며 대화·공부 레벨 계산은 기존 데모 규칙을 사용합니다. 호감도 초기값과 증감 기준은 백엔드에서 확정합니다.

공식 모델 파일·고정 버전·해시·라이선스는 [모델 문서](public/models/README.md)에 있습니다. `npm ci`/개발/빌드 시 설치한 패키지에서 로컬 WASM 실행 파일을 준비하므로 실행 중 외부 CDN에 의존하지 않습니다. 실제 청구가 없는 결제 흐름은 기존과 같습니다.

종료 화면은 룸 이름과 완료 시각을 구분하고, 함께한 친구별 공부 레벨 진행과 현재 호감도를 별도로 표시합니다. 레벨 바는 해당 공부 직전 값부터 공부 시간 증가분만 채우며 레벨 경계를 넘으면 링·빛·입자 효과 후 새 레벨 진행도로 이어집니다. 이후 기록은 과거 리포트의 레벨 변화에 포함하지 않습니다. 레벨은 보라색, 호감도는 하트와 분홍색으로 구분합니다. 채린의 리포트는 [분리 레이어](src/assets/reports/completion-layers-v3/README.md), 캡슐 카드는 [기존 완료 이미지](src/assets/reports/completion-v1/README.md)를 사용합니다. 카드 미리보기와 저장 PNG에는 공식 로고와 홈용 투명 제목 이미지를 사용합니다.

캡슐 카드 미리보기는 `CapsuleCardSurface`에서 포인터를 따라 기울며 사진·로고·공부 시간을 서로 다른 깊이로 보여 줍니다. 홀로그램 반사와 미세한 반짝임을 더하고, 키보드 초점에서는 고정된 입체감을 제공합니다. 터치 화면과 움직임 줄이기 설정에서는 기울기를 생략합니다. 다음 공부 약속은 날짜·시간 휠에서 선택합니다.

캡슐 카드 PNG는 정중앙에 호버했을 때의 그라데이션·반짝임·빛 반사를 고정해 저장합니다. 마우스 위치나 터치·움직임 줄이기 설정에 관계없이 같은 색감을 사용합니다. 파일 공유를 지원하는 브라우저에서는 같은 PNG로 공유 창을 열고, 지원하지 않으면 이미지 저장으로 안내합니다. 복사한 데모 링크의 기록은 이 브라우저 안에만 있으므로 다른 기기와의 동기화는 지원하지 않습니다.

React + TypeScript(strict) + Vite + Tailwind CSS v4를 사용합니다. 공통 UI, 기능 모듈, 페이지와 더미 reducer를 분리했고 페이지는 지연 로딩합니다. 타입 검사·린트·빌드 및 타이머/원장/대화 한도 등의 상태 테스트를 실행할 수 있습니다.

## 참고

초기 구현에서는 피그마를 읽기 전용으로 확인했으며, 원본 프레임의 번호 핀과 메모는 기획 주석이므로 웹 UI에 포함하지 않았습니다. `Landing_Page`의 로고·Pretendard·WebP 포스터·친구 일러스트를 재사용했고, 2026-11-03 통합 기준에 따라 Front_Web의 컬러·서체·컨트롤을 정리했습니다. Landing_Page에 적용했던 변경은 사용자 요청에 따라 원복했습니다. 이번 통일 작업에서 Figma 원본은 수정하지 않았습니다. 에셋 출처와 매핑은 [에셋 문서](src/assets/README.md)에 정리했습니다.

BrowserRouter를 사용하므로 배포 서버에서는 `/rooms/1` 같은 URL도 `index.html`로 연결하는 SPA fallback이 필요합니다. Vercel은 `vercel.json`, Cloudflare Workers는 `wrangler.jsonc`로 설정합니다. API 요청은 SPA fallback과 구분합니다.

### Vercel 배포

`Front_Web` 저장소의 프로젝트 루트에 `vercel.json`과 `api/router.ts`가 함께 있어야 합니다. `dist`만 정적으로 업로드하면 API 함수가 생성되지 않습니다. Vite 개발 미들웨어와 Cloudflare의 Worker 설정도 Vercel에서는 실행되지 않습니다.

| 항목 | 설정 |
| --- | --- |
| Framework Preset | Vite |
| Root Directory | 이 저장소 루트 `.`. 상위 모노레포를 연결했다면 `Front_Web` |
| Build Command | `npm run build` |
| Output Directory | `dist` |
| Production Branch | 현재 프로젝트는 `main` |
| API 함수 | `api/router.ts`, 모든 `/api/*` 요청을 명시적으로 연결 |

Vercel 프로젝트의 Environment Variables에 `BACKEND_API_ORIGIN`, `VITE_KAKAO_REST_API_KEY`, `VITE_KAKAO_REDIRECT_URI`를 설정합니다. 현재 운영 callback은 `https://capsule-front-web.vercel.app/oauth/kakao`이며 카카오 개발자 콘솔에도 같은 주소가 등록되어 있어야 합니다. 로컬의 `.env.local`은 Git에서 제외되며 Vercel로 자동 전송되지 않습니다. 환경변수 변경은 새 배포에서 적용합니다.

함수는 공통 `server/backend-proxy.ts`를 사용해 Authorization·JSON·쿼리를 전달하고 refresh cookie를 현재 도메인의 HttpOnly/Secure 쿠키로 맞춥니다. 브라우저의 API 주소는 계속 `/api/backend/*`입니다. `/api/chat`은 기존 서버 전용 OpenAI 설정을 사용하는 별도 경로이며 정상 공부 대화는 백엔드 `/messages`를 사용합니다.

배포 확인은 `GET /api/backend/terms`의 **200 JSON**, 쿠키 없는 `POST /api/backend/auth/refresh`의 **401 JSON**, `/login`·`/rooms/1`·`/oauth/kakao` 직접 접속의 HTML 응답으로 구분합니다. 초기 refresh 401은 로그아웃 상태의 정상 응답이며, 플랫폼의 `404 NOT_FOUND`나 HTML 응답과 다릅니다.

공식 참고: [Vercel Node.js 함수](https://vercel.com/docs/functions/runtimes/node-js), [Vite SPA 라우팅](https://vercel.com/docs/frameworks/frontend/vite#using-vite-to-make-spas).

### Cloudflare Workers 배포

Git 저장소 루트가 이 디렉터리인 Workers 프로젝트의 설정입니다. 배포할 브랜치에도 `wrangler.jsonc`가 포함되어 있어야 합니다.

| 항목 | Production | Preview |
| --- | --- | --- |
| 브랜치 | `main` | `dev` 등 Production 외 브랜치 |
| Build command | `npm run build` | `npm run build` |
| Deployment / Preview command | `npx wrangler deploy` | `npx wrangler preview` |
| Root directory | `/` | `/` |

`wrangler.jsonc`는 `dist`의 정적 파일을 배포하며, `previews` 설정을 선언해 브랜치별 Preview를 지원합니다. Preview 이름은 현재 Git 브랜치에서 정해지므로 `--name dev`를 공통 Preview 명령에 고정하지 않습니다. 기존 Production 명령의 `--assets ./dist --name capsule-front-web --compatibility-date 2026-10-23` 옵션도 파일의 설정과 같아 유지할 수 있습니다.

`dev`의 **Tracking branch**와 **Preview builds**를 확인한 뒤 변경 사항을 `dev`에 push합니다. 해당 Preview의 **Deployments**에서 최신 커밋의 성공 여부와 실제 URL을 확인하세요. Preview 토글을 켜거나 URL을 활성화한 것만으로 배포가 성공한 것은 아닙니다. 공개 배포에는 Cloudflare Access 설정이 필요하지 않습니다.

설정 참고: [Vite](https://vite.dev/guide/), [Tailwind Vite 설치](https://tailwindcss.com/docs/installation/using-vite), [React Router 설치](https://reactrouter.com/start/declarative/installation). 사용 중인 외부 코드·라이브러리의 상업 이용 검토는 [REFERENCE_COMMERCIAL_USE.md](docs/REFERENCE_COMMERCIAL_USE.md)에 기록합니다.


홈 북마크와 가입·충전 동의 체크박스에는 자체 모션을 적용했습니다. 충전 동의는 회원가입과 같은 `AnimatedCheckbox`를 사용합니다. 계정 설정의 일정은 상단 주간 달력과 하단 목록·우측 하단 추가 버튼으로 구성하며, 일정 표시와 날짜별 조회를 연결했습니다. 기록은 일별 공부 시간 히트맵과 숫자/호가 동기화되는 자리 지킴률 링으로 표시합니다. 공부 시작 시 목표 시간을 고르면 타이머·일시정지·재접속·종료 기록까지 이어집니다. [컨트롤·목표 시간 가이드](docs/INTERACTIONS_AND_STUDY_GOALS.md), [상업 이용과 배포 고지](docs/THIRD_PARTY_NOTICES.md)를 확인할 수 있습니다.

친구별 함께한 시간은 선택한 기간의 누적 시간을 비교하는 SVG 라인차트로 표시하고, 날짜에 호버하면 당일·월별 시간과 누적 시간을 구분해 보여 줍니다. 왼쪽 카드에는 기간별 공부 시간·횟수·친구 수·자리 지킴률과 최근 스터디를 묶고, 오른쪽 카드에는 달력과 선택한 날짜의 상세를 묶었습니다. 날짜 선택 상태는 달력 컴포넌트에서 관리하며, 최근 스터디의 종료 상태 배지는 제거했습니다. 누적 시간 차트는 하단 전체 너비를 사용합니다. 공통 토글은 선택 배경이 슬라이딩합니다. 친구와 날짜·주·월·년에 따라 공부 시간과 자리 지킴률이 달라지는 연중 샘플을 사용하며, 기존 실제 공부 기록은 유지한 채 구형 샘플만 자동으로 이전합니다. 북마크 우측 하단 알림과 내 기록 패널·날짜 툴팁의 외곽선은 제거했습니다.

룸 상세에는 인물과 좌석·배경을 함께 생성한 [완성형 배너 9종](src/assets/room-detail-banners/README.md)을 사용합니다. 제목·소개는 HTML로 수정할 수 있으며, 생성 PNG·WebP·전체 프롬프트를 보관합니다. 도윤·모루·민하준·유리는 룸 상세의 친구 카드와 친구 프로필에서 얼굴 크롭을 공유하며, 프로필에는 별도의 책상 레이어를 표시하지 않습니다. 친구 소개는 해시태그로 표시하고 다음 공부 레벨까지의 시간은 레벨 막대에 호버하거나 포커스하면 보여 줍니다. 공통 토글 외곽선과 PREVIEW 표시는 제거했습니다.
