## 01 · 로그인 (`/login`)

### 무엇이 바뀌었나
로그인 화면에 **Live2D 메이트가 화상통화 창 안에 나오고**, 사용자의 입력에 표정·시선으로 반응합니다(이메일 입력 시 입력창을 봄, 비밀번호 입력 시 눈을 감음 등). 배경과 로그인 폼 배치도 바뀌었지만, 그 부분은 프런트에서만 처리합니다.

### 바뀌지 않는 것 (백엔드 작업 없음)
- 이메일 로그인·회원가입·이메일 인증·비밀번호 찾기·재설정, 카카오 로그인의 요청과 응답은 **그대로** 씁니다.
- 회원가입의 생년월일은 기존에 요청한 계약 그대로입니다. 이번 변경으로 추가된 요청은 없습니다.
- 로그인 화면에서는 카메라를 쓰지 않습니다.

### 요청 1 · 로그인 전에 받을 수 있는 메이트 모델 정보 (필요)
**문제:** 지금 Live2D 모델 정보(`Figure`, `ModelInfo`의 `modelJsonUrl`·`scale`·`offsetX`·`offsetY`)를 주는 API는 아래 세 곳뿐이고, **모두 로그인 토큰(bearer)이 필요합니다.** 로그인 화면은 로그인하기 전이라 이 API들을 부를 수 없습니다.

| 경로 | 인증 | 모델 정보 |
|---|---|---|
| `POST /api/sessions` | 필요 | `Figure` |
| `POST /api/sessions/{sessionId}/resume` | 필요 | `Figure` |
| `GET /api/avatars` | 필요 | `ModelInfo` |
| `GET /api/rooms/{roomId}` | 불필요 | 없음 |

(11/22 13:37 KST 재조회한 OpenAPI 기준)

**요청:** 인증 없이 부를 수 있는 조회 API에 로그인 화면용 메이트 정보를 넣어 주세요. 새 경로든 기존 공개 API(메이트 목록·상세)에 필드를 더하는 방식이든 괜찮습니다.

응답에 필요한 값(예시):

```json
{
  "mateId": 1,
  "name": "채린",
  "ageRating": "ALL",
  "stillImageUrl": "https://…/chaerin/portrait.webp",
  "backgroundImageUrl": "https://…/chaerin/call-bg.webp",
  "model": { "modelJsonUrl": "https://…/chaerin/model.model3.json", "scale": 1, "offsetX": 0, "offsetY": 0 },
  "expressions": {
    "default": null,
    "smile": "files/009.exp3.json",
    "eyesClosedSmile": "files/0xx.exp3.json",
    "sleepy": "files/0xx.exp3.json",
    "sad": "files/0xx.exp3.json",
    "surprised": "files/0xx.exp3.json",
    "playful": "files/0xx.exp3.json"
  }
}
```

- **메이트 선택:** 출시 메이트가 2명이 되면 로그인 화면에 누구를 띄울지 정해야 합니다. 목록으로 주시면 프런트가 접속마다 번갈아 보여 주고, 서버가 하나를 골라 주셔도 됩니다.
- **모델 파일 접근:** `model3.json`이 참조하는 `moc3`·텍스처·`physics`·표정(`exp3`) 파일도 **인증 없이 받을 수 있어야** 합니다. 다른 도메인(CDN)이라면 CORS에서 프런트 주소(운영·dev·`http://localhost:3000`)의 GET을 허용해 주세요. 파일이 바뀔 때 주소가 바뀌는 방식이면 길게 캐시해도 됩니다.
- **표정 의미:** 지금 모델의 표정 파일 8개(`files/004~011.exp3.json`)는 이름만으로는 어떤 표정인지 알 수 없습니다. 위 예시처럼 **표정의 의미(웃음·눈 감은 웃음·졸림·시무룩·놀람·장난)와 파일을 짝지은 정보**를 주시면, 메이트가 늘어나도 프런트를 고치지 않고 반응을 붙일 수 있습니다. 이 정보가 없으면 프런트가 메이트별로 직접 짝을 지어 둡니다. REQUEST.md R04(표정 분류)와 같은 자료입니다.
- **조회만 해야 합니다:** 이 API는 연결 세션을 만들면 안 됩니다. REQUEST.md R03/R04와 같은 원칙입니다.

**이 정보가 없을 때 프런트 동작:** 로그인 화면은 메이트의 **정지 이미지**를 보여 주고, 말풍선 반응만 동작합니다. 로그인 기능에는 영향이 없습니다.

### 요청 2 · 로그인 화면 반응 로그 (선택, PM 결정 후)

## 06 · 연결 기록 (`/connections/:id`)

### 바뀌지 않는 것

- 예전 공부 레벨·호감도 숫자(`levelBefore/After`, `points*`)는 화면에 쓰지 않습니다.

### 요청 (기록 응답에 선택 필드 추가)
프런트는 아래 이름으로 미리 받을 준비가 되어 있습니다. 값이 없으면 해당 칸을 숨깁니다. 이름을 바꾸시면 알려 주세요.

| 필드 | 내용 | 없을 때 화면 | 급한 정도 |
|---|---|---|---|
| `dialogueCount` | 이번 연결에서 나눈 대화 수(사용자 턴 수) | "나눈 대화 수" 칸 숨김 | 12/1 전 필요(PRD R-1 P0) |

| `relation.stageProgress` (0~1) 또는 `relation.stageSeconds` + `relation.stageTargetSeconds` | 현재 단계 안에서의 진행 정도 | 진행 막대 숨김 | 있으면 좋음 |
| 해금 목록 | 이번 연결로 새로 열린 표정·보이스 대사 | 숨김(형식은 상의) | 12/1 이후 가능 |

## 11 · 메이트 모델 교체 (Aliving2D)

### 무엇이 바뀌었나
채린 모델이 **Cubism(`.moc3`)에서 팀 자체 형식 Aliving2D로 바뀝니다.** 모델은 `model.json` 하나와 파츠 PNG들로 이루어지고, Live2D SDK 대신 팀 엔진(`engine.js`, `player.js`)이 그립니다. 표정 8개(`sulky`·`happy`·`contempt`·`yawn`·`angry`·`laugh`·`shy`·`focus`), 모션 2개(`idle`·`talk`), 의상 2벌(`default`·`oc4ad1` 네이비 가디건)이 들어 있습니다.

- 프런트는 **로그인 화면부터** 새 모델로 바꿉니다. `/connect` 등 연결 화면은 아래 계약이 정해진 뒤에 바꾸고, 그때까지는 지금처럼 `model3.json`(Cubism)으로 동작합니다.
- 프런트는 두 형식을 모두 그릴 수 있게 만듭니다. 그래서 메이트마다 형식이 달라도 되고, 서버가 언제 바꾸든 화면이 깨지지 않습니다.

### 엔진 코드는 저장소에 넣지 않습니다
프런트 저장소가 공개 저장소라 엔진 코드(`engine.js`, `player.js`)와 모델 파일을 넣지 않습니다. 로컬 개발은 git에서 제외된 폴더로 확인하고, **운영에서는 백엔드가 엔진 주소를 내려 주면 프런트가 실행할 때 불러옵니다**(지금 Cubism Core를 불러오는 방식과 같음).

참고: 브라우저에서 실행되는 코드라 사용자가 개발자 도구로 내려받을 수는 있습니다. 깃허브에 공개되지 않는 것뿐입니다.

### 요청 1 · 모델 정보에 형식과 엔진 주소 추가 (필수)
메이트 모델 정보를 주는 모든 곳(`Figure`, `ModelInfo`, 01 로그인 요청 1의 로그인 전 조회 API)에 아래 필드를 더해 주세요.

```json

    "format": "aliving2d",
    "modelJsonUrl": "https://…/chaerin/v2/model/model.json",
    "engineUrl": "https://…/engine/v4/engine.js",
    "playerUrl": "https://…/engine/v4/player.js",
```

| 필드 | 내용 |
|---|---|
| `format` | `"cubism"` 또는 `"aliving2d"`. 없으면 프런트는 주소 끝(`model3.json` / `model.json`)으로 짐작합니다 |
| `engineUrl`, `playerUrl` | **버전이 주소에 들어간 고정 주소**(예: `/engine/v4/…`). 내용이 바뀌면 주소도 바뀌어야 합니다. 프런트는 우리 서비스 도메인(API와 같은 출처)의 주소만 실행하고, 다른 도메인이면 정지 이미지로 대체합니다 |
| `reactionsUrl` | (선택) 반응표. 앱에서는 서버가 반응마다 표정 이름을 직접 보내므로, 없으면 프런트는 반응표 없이 동작합니다 |
| `scale`, `offsetX`, `offsetY` | 기존처럼 화면 배치값. Aliving2D는 1280×1280 캔버스 기준이라 Cubism과 값 의미가 다릅니다. 처음엔 비워 두시면 프런트 기본 배치를 씁니다 |

### 요청 2 · 엔진·모델 파일 접근 (필수)
- `model.json`, `model.json`이 참조하는 `parts/*.png`, 엔진 JS 파일은 **인증 없이 GET으로 받을 수 있어야** 합니다(로그인 화면은 로그인 전).
- 다른 도메인(CDN)이면 CORS에서 프런트 주소(운영·dev·`http://localhost:3000`)의 GET을 허용해 주세요. 파츠 PNG는 WebGL 텍스처로 쓰므로 CORS 허용이 없으면 그릴 수 없습니다.
- JS 파일은 `Content-Type: text/javascript`로 내려 주세요.
- 주소에 버전이 있으면 길게 캐시해도 됩니다.

### 요청 3 · 표정 이름 (확인)
반응표(`reactions.default.json` v3) 주석에 따르면 서버는 반응마다 **표정의 한국어 이름**(`live2d_expressions.name` = `model.json`의 `expressions[].label`, 예: `삐짐`)을 보내고, 플레이어가 label로 찾습니다. 프런트도 이 규칙을 따르겠습니다. 다르면 알려 주세요.

### 요청 5 · 엔진: 머리카락 가장자리 깨짐 (엔진 담당, 수정 필요)
화면에서 모델이 원본 텍스처보다 작게 그려질 때(머리카락 텍스처는 캔버스 대비 약 2.9배 해상도) **가는 머리카락 가장자리가 점선처럼 깨지고 붉은 선이 보입니다.** 머리카락이 흔들릴 때 특히 잘 보입니다.
- 원인: `engine.js`가 텍스처를 `TEXTURE_MIN_FILTER = LINEAR`로만 축소하고 밉맵을 만들지 않습니다(188~191행 근처).
- 제안: 파츠 텍스처 업로드 후 `gl.generateMipmap(gl.TEXTURE_2D)` + `TEXTURE_MIN_FILTER = LINEAR_MIPMAP_LINEAR`. 투명 픽셀 색 번짐이 남으면 내보내기 단계에서 투명 영역 RGB를 주변 색으로 채워(알파 블리드) 주세요.
- 바뀐 엔진은 새 버전 주소(예: `/engine/v5/`)로 내려 주세요.

### 요청 6 · 엔진: 대기 모션이 고개 각도를 과하게 흔듦 (엔진 담당, 수정 필요)
`player.js`의 대기 모션(`idle`)을 켜 두면 **시선과 상관없이 고개가 6초 주기로 같은 각도를 크게 왕복합니다.** 마우스를 따라 눈은 움직이는데 고개는 정해진 대로만 움직여 보입니다.
- 측정(시선 고정): `angleX`가 -1.53 ~ +1.83까지 흔들림(모델 범위 ±1 초과). 대기 모션을 끄면(`idle: false`) 시선 0.8에 고개 0.48로 안정(= `headFollow` 0.6, 정상).
- 원인: 4단계(대기 모션 더하기, 208~216행 근처)에서 `base = prev && P[id] === prev.v ? prev.base : P[id]`. 1단계의 `approach()`가 매 프레임 값을 바꾸므로 `P[id] !== prev.v`가 되어, **지난 프레임의 대기 모션 오프셋이 들어간 값이 새 base가 됩니다.** 오프셋이 매 프레임 다시 더해져 약 1/0.06 ≈ 17배로 커집니다.
- 제안: 포즈처럼 "지난 프레임 오프셋 빼기"로 바꿔 주세요. 예) `const base = P[id] - (this.idleLast[id]?.off ?? 0); const off = curveAt(keys, t) * this.idleW; m.set(id, base + off); this.idleLast[id] = { off };` (`talk` 모션의 `angleX/Y`도 같은 방식인지 확인 부탁드립니다.)
- 프런트 임시 조치: 수정된 엔진이 오기 전까지 로그인 화면은 `idle: false`로 만들고, 호흡·깜빡임·두리번거림만 씁니다.

### 이 정보가 없을 때 프런트 동작
엔진 주소가 없거나 받을 수 없으면 메이트를 **정지 이미지**로 보여 주고, 말풍선 반응만 동작합니다. 로그인·연결 기능에는 영향이 없습니다.

### 참고 · 11의 요청 5(머리카락 가장자리)에 대한 추가 관찰
랜딩용 렌더에서 확인한 결과, 밉맵·필터를 바꿔도 머리카락 외곽의 밝은 선이 남았습니다. 파츠 PNG의 반투명 경계에 이미 밝은 색이 들어 있는 것으로 보입니다. 내보내기 단계에서 투명 경계의 색을 안쪽 색으로 채워 주면(edge padding) 앱·랜딩 모두 좋아집니다. 랜딩은 임시로 렌더 후처리(1px 알파 수축 + 경계 색 보정)를 하고 있습니다.
