# 배포 프론트 기준 Figma 와이어프레임

[화면 흐름과 백엔드 전달 정보 열기](https://www.figma.com/design/HpoEbOqfoDUwPq4zvYa6LL?node-id=1122-7722)

- 대상 페이지: **생성 에셋 관리** (`1053:172`). 기존 이미지 에셋 보드는 유지했다.
- 배포 UI 확인: **2026-10-29 밤**, 데스크톱 뷰포트 **1440 × 1000**. 긴 페이지는 전체 내용이 보이도록 프레임 높이를 늘렸다.
- 배포 주소: https://capsule-front-web.boo4246.workers.dev/
- 현재 코드의 동작 설명 참고 커밋: `5199e8f`. 배포 UI를 기준으로 하며 해당 커밋과 배포의 동일성을 보증하는 릴리스 명세는 아니다.
- 편집 가능한 **38개 화면 상태**, 화면 원본 컴포넌트 **38개**, 공통 헤더 포함 원본 컴포넌트 **47개**로 구성했다. 전체 UI를 한 장의 스크린샷으로 붙이지 않았다.
- 일반 텍스트는 **Pretendard**, 숫자용 기존 **JetBrains Mono Variable**을 유지했다. 로컬에 Pretendard가 이미 설치되어 있음을 확인했다. 자동화 환경의 글꼴 목록에 별도로 등록되었다고 주장하지 않으며, 가져온 텍스트 레이어의 원본 글꼴을 보존하고 재사용했다.

## 보는 방법

Figma 목차와 주요 버튼에 화면 이동을 연결했다. 각 화면 상단 제목 영역을 누르면 목차로 돌아온다. 프로토타입은 대표 상태 사이의 이동을 보여 주며 폼 검증·결제·AI 응답·카메라 실행을 Figma 안에서 재구현한 제품 데모는 아니다.

화면 오른쪽에는 진입 조건, 사용자 입력과 검증, 표시/변경 데이터, 처리 결과와 서버 연동 전 협의할 사항을 적었다. 경로 표시는 **프론트 화면 경로**이며 임의의 HTTP 메서드·API 엔드포인트를 정하지 않았다.

## 구현과 연동 설계의 구분

배포본의 인증·결제·대화 응답은 로컬 샘플 동작이다. 실제 OAuth/이메일 인증 서버, PG 승인, AI·음성 서비스 연동 완료를 의미하지 않는다. 촬영 영상·실제 계정·실제 결제 정보는 이번 조사에 사용하지 않았다. 격리된 브라우저에서 샘플 선물·구매 동작만 재현했다.

휴식·공부 완료 화면은 배포본의 데모 조작으로 목표 도달을 재현했다. 화면의 50분은 실제로 50분 동안 공부해 얻은 측정 결과가 아니다. 카메라 미사용 상태와 권한 안내를 조사했으며 실제 카메라 연결 성공·미디어파이프 추론 성능을 검증한 작업은 아니다.

현재 구현에서 확인한 규칙과 운영 시 확정할 정책을 구분해야 한다.

- 친구별 시간은 세션 공부 시간을 참여 인원수로 나누고 반올림해 누적한다. 현재 레벨은 600분마다 오르며 최대 Lv.5다. 이 값을 운영 정책으로 확정한 것은 아니다.
- 카메라 미사용의 집중률은 `—`다. 미감지 관측 구간과 관측 자체가 없는 구간을 구분한다. 얼굴 추론은 브라우저의 MediaPipe Face Landmarker `.task` 모델로 수행하고 YOLO는 MVP에서 제외했다.
- 일정은 사용자 단위의 전역 일정이며 친구별로 복제하지 않는다. 약속일 때만 시간을 저장한다.
- 베이직 대화는 현재 하루 3회, 영업일과 패스 일일 혜택은 한국 시간 05:00 기준이다. 실패·재시도·동시 사용 시 한도 처리와 초기화 정책을 서버와 합의해야 한다.
- 크레딧 상품은 9,900원에 10,395, 19,900원에 20,895 크레딧을 지급하도록 표시·처리한다. 원화 금액, 기본량, 보너스, 총량은 별개 개념이다.
- 현재 끝내기는 별도 종료 확인창을 거치지 않고 결과 화면으로 간다. 매번 공부 준비 1/2로 진입하며 이미 활성 공부가 있으면 그 세션으로 돌아간다.

## 백엔드 설계에서 함께 확정할 내용

Figma 목차의 업무 데이터·상태 변경·협의 사항과 화면별 설명을 함께 읽는다. 아래는 엔드포인트나 DB 스키마가 아닌 업무 요구다.

1. 인증 상태·프로필 설정·약관 버전 및 동의 증빙, 인증 만료 후 원래 화면 복귀.
2. 룸·친구·공개 콘텐츠와 사용자별 관계/해금 정보, 과거 기록의 접근 권한.
3. 공부 생성 시 잔액·패스·일일 혜택 재검증, 활성 세션 경합, 비용 차감과 세션 생성의 일관성.
4. 정지·재개·휴식 전환·새로고침 복구에 필요한 서버 시간/시간대와 경과 시간 기준.
5. 관측·집중·미감지·미측정 구간과 클라이언트 집계 검증 범위. 원본 영상·음성 업로드를 기본 요구로 추가하지 않는다.
6. 종료 시 완료 기록·친구별 시간/해금·활성 세션 해제를 한 번만 확정하고 같은 요청 재시도에 같은 결과를 제공.
7. 세션/친구별 메시지·전송 상태, 스트리밍 중단/실패, 재시도·사용량·과금 소비 단위.
8. 옵션 변경의 차액·패스 혜택·세션 종료와의 경합, 선물 차감·이력·콘텐츠 권한의 일관성.
9. PG 승인 검증·주문/지급/취소·환불·보너스 회수·패스 연장/교체. 현재 샘플 영수증을 실제 승인 증거로 쓰지 않는다.
10. 일정의 날짜/시간대·과거 일정·동시 수정, 카드의 로컬 생성/서버 보관·공개 링크 범위와 만료.

## 화면별 처리 설명

### W01 · 가입·로그인 진입

[Figma 화면](https://www.figma.com/design/HpoEbOqfoDUwPq4zvYa6LL?node-id=1119-2817) · 진입: 로그인 전 진입

- **화면 동작**: 카카오, 이메일 로그인·회원가입, 가입 없이 둘러보기로 분기한다. 진입 전 목적 화면은 next로 복귀한다.
- **필요한 데이터**: 인증 상태, 프로필 설정 완료 여부, 복귀할 화면.
- **배포 상태**: 둘러보기와 로그인은 로컬 샘플 상태를 바꾼다. 실제 카카오 인증·계정 발급은 연결되어 있지 않다.
- **연동·협의**: 인증 수단별 성공·취소·실패, 세션 유지·만료, 비회원 허용 범위를 결정한다.

### W02 · 이메일 로그인

[Figma 화면](https://www.figma.com/design/HpoEbOqfoDUwPq4zvYa6LL?node-id=1119-3319) · 진입: W01 → 로그인

- **입력·검증**: 이메일 형식과 비밀번호 필수 입력. 현재 폼은 브라우저 기본 검증을 사용한다.
- **성공 이후**: 프로필 설정이 필요하면 W04, 완료된 사용자는 원래 목적 화면 또는 W05로 이동한다.
- **배포 상태**: 입력한 이메일·비밀번호를 인증 서버에 전송하지 않는다. 실제 인증이 성공한 화면으로 해석하면 안 된다.
