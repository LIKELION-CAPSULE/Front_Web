# 웹 베타 기능별 외부 요청 사항

기준: 2026-11-22 최종 PRD·화면 수정 지시서, 프런트 11차 임시 채린 시각 자료/이름 매핑 상태. Swagger 재확인 시각: **2026-11-22 13:37:27 KST**.

이 문서는 프런트가 실제 기능을 완료하기 위해 **백엔드 구현·계약, PM의 결정·승인 문구, 디자인/제작물 중 무엇을 기다리는지** 정리한다. 역할 단위 요청이며 개인 담당자나 완료일을 임의로 지정하지 않았다. P0/P1은 원문 우선순위를 따른다.

**현재 API에 맞춘 추가 수정:** 사용자의 API 우선 연동 요청 후 27개 작업을 실제 백엔드 서비스 검증까지 대조했다. 신규 시작은 `targetMinutes: 50`을 보내는 현재 API 호환 방식으로 수정했고, 이력 없는 복구의 heartbeat 필수 본문·인증번호 재전송 60초·Unicode 닉네임·오류 안내도 정정했다. 따라서 아래 14:32 진단 당시의 **“새 연결 시작은 서버 변경 전까지 차단”** 판정은 더 이상 현재 상태가 아니다. 목표 없는 생성·종료 판단이라는 **최종 베타 정책의 서버 변경**은 R09에 계속 남는다. [전체 API 대조·수정·검증 기록](API_AUDIT_2026-11-22.md), [필드 비교 결과](API_AUDIT_2026-11-22.json) 참조.

**사용자 승인 임시 예외:** 화면 확인을 위해 기존 말포이 이미지·모델을 ‘채린’ 이름으로 일단 사용하도록 요청했다. 프런트는 기존 서버 이름을 채린으로 매핑하고 로그인·홈·카드·상세·기록의 이미지를 재사용한다. 홈 배너/사용법 이미지 표시에는 새 API를 요구하지 않는다. 실제 서버 ID·모델 URL·응답 원문·프롬프트는 바꾸지 않는다. R03의 최종 제작물 확정·R04의 대사 검수는 계속 남으며, 이 임시 재사용을 새 제작물이나 서버 캐릭터 설정 변경 완료로 보지 않는다. 첨부 기획 원문은 수정하지 않았다.

## 1. 이번 Swagger 재확인 결과

공통 성공 응답의 `success/data` 구조도 그대로다. `MessageRequest.tts`·`MessageResponse.audioBase64`는 **기존부터 있던 필드**이며 이번에 추가된 음성 API가 아니다. 현재 공개 명세에는 별도 STT·크레딧/초대·이전 대화 조회/초기화 API가 없다.

`GET/POST /api/me/memories`도 기존 **일정 조회/저장**이다. 경로 이름만 보고 새 대화 기억·이전 대화 API로 연결하지 않는다.

공개 [약관 GET](https://api.capsule.ai.kr/api/terms)도 재조회했다. SERVICE 버전 **3**, PRIVACY 버전 **4** 모두 **본문 준비 중**이다. 실제 서비스용 전문 게시가 필요하다.

검증 범위는 공개 OpenAPI·Swagger 설정·약관의 **읽기 전용 GET**이다. 인증 API·SSE·음성·잔액 차감의 실응답을 검증한 결과는 아니다. 개발 중이거나 명세에 반영되지 않은 API까지 없다고 단정하지 않는다. 별도 개발 계약이 있다면 배포 주소/명세/예시 응답을 받아 다시 대조해야 한다. 이전 백엔드 소스 조사 내용은 [API 의존 사항 문서](CAPSULE_WEB_BETA_API_GAPS_2026-11-22.md)의 해당 커밋 기준 근거이며, 이번에 개발 브랜치를 새로 조회한 것은 아니다.

### 최초 진단 · 14:32 KST · 새 연결 `POST /sessions` 400

아래는 수정 전 진단이다. 이후 사용자의 “API에 맞춰” 요청으로 적용한 현재 호환 상태는 위 추가 수정과 R09를 따른다.

- 로컬의 `BACKEND_API_ORIGIN`은 `https://api.capsule.ai.kr`이다. 브라우저의 `http://localhost:3000/api/backend/sessions`는 정상적인 같은 출처 프록시 경로이며, 서버에서 `https://api.capsule.ai.kr/api/sessions`로 전달한다. 로컬 프록시의 공개 약관 GET과 공개 OpenAPI GET은 모두 HTTP 200이다. OpenAPI 전체 내용은 위 재조회 스냅샷과 같다.
- **명세와 실제 구현의 불일치:** `StartRequest`의 OpenAPI `required`에는 `roomId`, `characterId`만 있지만, 현재 `develop`의 [SessionService.start](https://github.com/LIKELION-CAPSULE/Backend_lab/blob/de5aa98f352a173c9ba11c72b0eb27dfce281b15/src/main/java/com/capsule/session/service/SessionService.java#L167)는 `targetMinutes == null`을 거절한다. [SessionErrorCode](https://github.com/LIKELION-CAPSULE/Backend_lab/blob/de5aa98f352a173c9ba11c72b0eb27dfce281b15/src/main/java/com/capsule/session/domain/SessionErrorCode.java)는 이를 HTTP 400 `INVALID_TARGET_MINUTES`로 정의한다. 이번에 공개 GitHub를 다시 조회한 `develop`도 같은 커밋이다.
- 현재 프런트는 목표 시간 선택을 제거하며 `{ roomId, characterId }`만 전송한다. 선택 필드라는 Swagger 표기만으로 생략 가능하다고 판단했던 부분은 위 구현과 충돌한다. 따라서 **기존 연결 API 재사용도 신규 시작 경로는 백엔드 수정 대기(R09)**다. 기존 세션 재개와는 별도다.
- **BE 요청:** 목표 시간 없이 연결을 생성하도록 검증·저장·종료 판정/정산을 베타 정책에 맞추고, 실제 정상/오류 응답과 OpenAPI를 일치시킨다. **PM:** 목표 선택 없음·일반 사용자 무제한은 이미 확정되어 재결정이 필요 없다. **FE:** 적용 후 목표 필드를 생략한 실제 생성·재개·종료·기록을 검증한다.
- 임의의 목표 시간을 숨겨 보내는 우회는 적용하지 않았다. 기존 서버는 목표값을 종료 시 `GIVE_UP` 판단에도 전달하므로, 단순 기본값 추가를 무제한 연결 구현으로 취급할 수 없다.
- 이 분석은 사용자 콘솔의 400, 현재 프런트 요청 코드와 공개 백엔드 소스를 대조한 결과다. 사용자 요청의 실제 오류 JSON/`code`는 아직 직접 확인하지 않았으며, 운영 계정으로 세션 생성 POST를 추가 전송하지 않았다. 진단 원본은 `/private/tmp/capsule-session-openapi.json`, `/private/tmp/capsule-backend-session-{service,controller,errors}.java`에 임시 보관했다.

### 요청별 계약에서 빠지면 안 되는 내용

- **R01/R02:** 가입 시 입력을 버리고 구형 API로 성공 처리하지 않는다. 새 저장 필드·필수 여부·수정 가능 범위·길이/오류·미완료 온보딩 판정과 실제 재조회 응답이 필요하다. 약관은 승인 전문과 동의 버전이 일치해야 한다.
- **R03/R04:** 목록/상세 조회만으로 연결 세션을 만들지 않아야 한다. 미리보기 모델과 연결 모델, 샘플과 실제 답변 음성을 구분해 전달한다. `ReportResponse.closingLine`은 종료 후 응답이므로 자동 종료 전 인사를 대신할 수 없다.
- **R05:** 원문 보존·조회 정책과 함께 대화 기록/기억/친밀도/해금의 **네 범위 초기화**가 필요하다. 중복 실행·진행 중 연결·다른 기기와의 충돌을 어떻게 응답하는지 제공한다. 현재 기기 메시지 캐시는 전체 서버 대화 기록이 아니다.
- **R06:** 지원 오디오 형식·전달 방식·최대 입력·타임아웃·취소/재시도·중복 요청과 오류 응답을 제공한다. SSE를 사용한다면 이벤트 순서와 본문 예시도 필요하다. PIP/창 포커스 상실 때 녹음 중단과 비용 처리를 확인한다. 기존 음성 운반 필드가 있다는 이유로 실제 TTS가 준비됐다고 판단하지 않는다.
- **R07/R08:** 지급/차감/환급/초대 보상은 서버 결과로 표시한다. 중복 요청·자정이 아닌 **오전 5시** 경계·초대 보상 최대치·출석분 만료 후 초대분 유지 사례의 실제 응답이 필요하다.
- **R09:** `presentSeconds`와 `todayStudySeconds`를 새 캠 확인 시간으로 재명명해 쓰지 않는다. 연결 시간/캠 시간의 정의·단위·기간·집계 기준, 로컬 관측 누락 시 표시, 재접속 후 최종 서버값을 구분한다.
- **R10:** 기존 공부 레벨/호감도는 새 친밀도 규칙과 같다고 가정하지 않는다. 해금 레벨과 일시적 분위기를 분리하고, 종료 기록의 이전/이후 값과 현재 상태를 구분한다.
- **R11/R12:** 화면 반응을 위해 임의 주기로 자동 메시지를 보내거나 크레딧을 소모시키지 않는다. 반응 범위·발화 조건과 이를 실행하는 계약이 모두 있어야 연결한다.
- **R13/R14:** 프런트 안내/타이머는 서버 집행을 대신하지 않는다. 경고→정지→초기화, 청소년 일일 제한과 운영 한도의 정상·실패·재접속 사례 및 검증 방법이 필요하다.

## 4. PM·공동 파트의 결정이 필요한 항목만 모아 보기

1. **남학생 설정·콘텐츠 및 메이트 대사:** R03/R04. 기존 남학생 더미 캐릭터로 대체하지 않는다. 임의 세계관·인트로·빠른 답장·인사를 쓰지 않는다.
2. **친밀도 추천값:** R10. 원문의 5단계 `0/1/5/15/40시간`, 하루 인정 상한 `2시간`, 대화 없는 날 `절반 인정`, 단계별 표정 1개/보이스 2개 등은 숫자 추천값으로 표시돼 있다. 구조상 확정된 해금 레벨/분위기 분리·결제 영향 없음과 구분해 최종 적용 수치를 확인해야 한다. 카메라 미사용 시 인정 방식도 정리한다.
3. **분위기·카메라 반응·시선:** R10/R11. 분위기 종류와 표정/말투 매핑, 눈 맞춤·하품 포함 여부, 시선 따라오기 범위를 PM·디자인·개발이 확정한다.
4. **음성/고급 모델과 비용 경계:** R06. 기본/고급 모델과 음성 답변 지연 목표는 원문대로 개발팀 결정 사항이다. PM·BE는 실패·취소·부분 생성이 어떤 과금 결과가 되는지 합의한다. 정상 턴 20/30/50을 다시 정하는 요청은 아니다.
5. **자발적 말 걸기:** R12. 선택지/기본값 외 실제 발화 조건·상한·과금 포함 여부를 정한다.
6. **초대/초기화 경계:** R08/R05. 첫 연결 완료 인정·부정 가입 보상 처리, 진행 중 연결의 초기화 처리·원문 보관 기간을 정한다.
7. **게시·운영·검수:** R01/R13/R14. 서비스 약관 전문 승인, 구체 경고/제재 조건과 안내 문구, 지표 집계/로그 보관 기준·운영 검수 담당을 정한다. 이미 확정된 전연령·관계 상한·3시간 제한·정원/기간은 구현 대상이다.

## 5. 백엔드에서 계약을 전달할 때 필요한 공통 자료

- 개발/검증 서버 주소와 Swagger URL, 배포 버전 또는 해당 커밋, 사용 가능한 시점.
- 기능별 실제 method/path, 인증, 요청/응답 필드의 타입·필수/선택·null 의미·단위, enum과 오류 코드. 현재 공통 `success/data` 적용 여부.
- 정상·빈 데이터·권한/나이/잔액 부족·서버 실패·중복/충돌의 응답 예시. 스트림은 이벤트 순서·완료/오류·재연결 예시.
- 페이지 처리·정렬·시간대/오전 5시 경계·재시도·중복 방지·계정/기기 간 동시 처리 기준.
- 서버 저장 후 재조회와 새 기기 조회 결과, 실제 모델/오디오 접근 방법. 각 파트의 결정·승인 자료와 어떤 버전으로 연결했는지.

프런트의 `BetaAccountPort`, `MateContentPort`, `BetaWallet`, `BetaInvitation`은 현재 UI 작업 경계다. 이 타입을 합의된 서버 필드/경로로 취급하지 말고 실제 계약을 받은 뒤 매핑한다.

**공동 검증 자원:** 실제 Live2D·물리 카메라/마이크·숨겨진 원래 탭의 PIP 장시간 검증은 새 기획 결정 없이 진행할 수 있지만, 접근 가능한 실제 모델/오디오·검증용 계정/서버·장치 환경이 필요하다. 모의 API·이미지 모델·합성 트랙의 브라우저 검사와 구분해 기록한다.

프런트 11차 기준 전체 단위 418개·린트/빌드가 통과했다. 9차 기능 브라우저 158개, 10차 디버그 복귀 26개, 11차 임시 채린 일반 앱/디버그 34개는 진행 계획의 해당 기록에 검증 범위를 별도로 기재한다. 이 수치는 R01~R14가 서버에서 구현됐다는 근거가 아니다. 상세 구현/검증 기록은 [P0/P1 진행 계획](CAPSULE_WEB_BETA_P0_PLAN_2026-11-22.md), 계약 근거는 [API 의존 사항](CAPSULE_WEB_BETA_API_GAPS_2026-11-22.md)을 따른다.

이후 12차 API 호환 수정은 전체 단위 **421개**, 린트·타입 포함 빌드, Chromium·WebKit **12개 격리 브라우저 흐름**이 통과했다. 세션 시작의 목표 시간 누락·이력 없는 복구의 heartbeat 본문 누락을 수정했다. 실제 계정의 세션 생성/재개/종료를 실행한 결과와 구분하며, 최종 베타용 서버 요구 사항은 그대로 남긴다. [API 감사](API_AUDIT_2026-11-22.md) 참조.

이 파일과 API 스냅샷은 저장소의 기존 `docs/*` 정책에 따라 로컬 보관된다. 커밋·푸시·파트별 외부 메시지 발송은 하지 않았다.


## 로컬 확인 모드 추가 · 2026-11-22

사용자 승인으로 `VITE_DATA_SOURCE=mock` 개발 모드를 추가했다. 실제 채린 모델과 표정, 계정/프로필·연결/재개/종료·지속 대화·기록/달력·출석/초대/차감 원장을 브라우저 안에서 시뮬레이션한다. 실제 API 모드는 유지하며 새 서버 경로를 가정하지 않는다. [실행·범위·저장 경계](LOCAL_MOCK_MODE_2026-11-22.md)를 참고한다.
