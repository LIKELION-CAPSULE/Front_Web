# 프런트 기능 버그 점검 · 2026-11-06

현재 사용하는 프런트 경로와 공통 상태·API 계층을 점검하고 추가 문제 9건을 수정했다. 시작 시 린트·빌드·테스트 300개가 통과했으며, 수정 후에는 회귀 테스트 21개를 포함해 321개가 통과했다. 직전 작업의 공부 종료 → 리포트 이동 수정은 이번 9건에 포함하지 않는다. 이후 사용자 요청으로 Playwright Chromium에서도 16개 시나리오를 실행해 모두 통과했다.

## Playwright 추가 검증 · 2026-11-06

사용자가 Playwright 검증을 요청해 연결된 Playwright 도구로 `http://localhost:3000`을 확인했다. 각 시나리오를 새 Chromium 브라우저 컨텍스트에서 실행했다. **16개 통과, 실패 0개, 처리되지 않은 JavaScript 예외 0건**이다.

실제 React 화면과 라우터를 사용하며 API는 기존 개발용 `__review` 모의 응답으로 격리했다. 로그인·가입·종료·채팅·이미지 저장·홈 배너는 화면 조작으로 확인했다. 요청 충돌 사례는 브라우저에서 실행 중인 실제 Provider를 호출하고 API 완료 시점을 제어했다. 캐릭터 모델 수명 검사는 검토용 이미지 stage를 사용했다.

## 확인 범위의 한계

- 최초 점검에서 미확인이었던 브라우저 동작과 PNG 내보내기는 위 16개 시나리오로 추가 확인했다. 모든 화면·해상도·애니메이션 프레임을 비교한 검증은 아니다.
- 실제 계정의 가입·카카오 인증·비밀번호 변경·회원탈퇴와 운영 서버 요청을 새로 실행하지 않았다. 기존 [API 점검 문서](API_FULL_AUDIT_2026-11-05.md)의 실서버 검증 수에 이번 모의 응답 테스트를 더하지 않는다.
- 실제 카메라·마이크 권한, WebGL·Cubism 렌더링, 느린 장치에서의 모델 로딩 성능은 장치별 확인이 남아 있다. 새 60초 제한은 오류 복구 기준이며 성능 측정값이 아니다.
- `/records`, `/characters/*`, `/credits/*`는 현재 앱 라우터가 MVP 준비 화면으로 연결한다. 접근이 막힌 과거 페이지를 현재 서비스 기능으로 집계하지 않았다.

홈의 `refreshError` 잔류 가능성은 재연결 시 `RequireDemo`가 로딩 화면을 렌더링하며 홈을 다시 마운트하는 흐름까지 확인해 독립적인 버그에서 제외했다. 해당 파일에는 이번 점검의 변경을 남기지 않았다.
