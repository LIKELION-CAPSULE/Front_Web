# CAPSULE 통합 디자인 기준

버전 **1.0.7** · 기준일 **2026-11-03 (Asia/Seoul)** · 상태 **Front_Web 전체 화면에 코드 적용**

후속 검수의 스타일 충돌 **7건과 개선안 6개를 반영**했다. [수정 결과와 검증](STYLE_CASCADE_AUDIT_2026-11-03.md#수정-결과와-검증)을 함께 확인한다. 사용자 요청으로 공부 화면 독은 디자인 시스템 적용 전의 유리 재질·색·원형 버튼을 유지하는 명시적 예외다.

이 문서는 Front_Web의 컬러와 타이포그래피를 결정하는 기준이다. Landing_Page는 사용자 요청에 따라 새 디자인 시스템 적용 대상에서 제외하고 기존 디자인을 유지한다. 참고 이미지의 레이아웃·외곽선·안내 문구·기능 정책을 그대로 옮기지는 않는다.

숫자 값과 상태 조합은 [DESIGN_TOKENS.json](DESIGN_TOKENS.json), 사용 이유와 적용 범위는 이 문서에서 관리한다. 두 파일은 함께 수정한다. 이후 사용자 지시가 우선하며, 이 문서와 이전 디자인 기록이 충돌하면 이 문서를 따른다. 적용 전 코드와의 차이 및 유지 방법은 [9. 적용 순서](#9-현재-코드에서-옮기는-순서)에 명시한다.

## 3. 실제 용도 토큰

CSS 이름은 `--color-<이름>`, Figma 이름은 `color/<이름>`으로 대응한다. 예를 들어 JSON의 `primary-hover`는 `--color-primary-hover`, `color/primary-hover`다. 화면마다 `purple`, `lavender`, `accent2` 같은 동의어 토큰을 추가하지 않는다.

### 3.1 배경·글자·구분

| 이름 | 값 | 사용 범위 |
|---|---|---|
| `canvas` | `#0F0E17` | 페이지 전체 바탕 |
| `panel` | `#191823` | 큰 영역의 바탕·평평한 정보 그룹 |
| `surface` | `#292733` | 상호작용 카드·입력·작은 독립 영역 |
| `surface-raised` | `#292733` | 일반 모달·독립 오버레이 본체. 작은 떠 있는 안내/메뉴는 floating 사용 |
| `floating` | `#403E4B` | 툴팁·팝오버·프로필/도구 메뉴. 뒷면의 panel/surface와 구분 |
| `floating-hover` | `#5E5C69` | 떠 있는 메뉴 안의 호버·키보드 포커스 항목과 내부 구분선 |
| `surface-soft` | `#0F0E17` | 패널 안의 눌린 영역·타임라인 트랙 |
| `surface-hover` | `#403E4B` | 일반 카드·목록의 호버 |
| `ink` | `#FAFAFD` | 제목·본문·주요 수치 |
| `muted` | `#CAC9D4` | 보조 설명·항목 이름 |

| `text-disabled` | `#807E8D` | 동작할 수 없는 컨트롤의 글자에만 사용 |

`canvas`와 `panel`은 서로 가깝다. 이 둘의 색 차이만으로 버튼이나 독립 카드를 식별하게 만들지 않는다. **조작 가능한 중립 버튼은 `control`, 독립 카드는 `surface`**를 사용한다. 작은 카드에 다시 채움 카드를 중첩하는 깊이는 2단계까지로 제한한다. 그 이상은 간격·구분선·제목으로 나눈다.

한 영역에서 주요 실행은 한 개를 기본으로 한다. 보조 버튼은 `soft` 또는 `secondary`를 사용한다. 핑크는 ‘더 중요한 버튼’의 색이 아니다. 친구 이름·모든 메시지·일반 공부 통계를 일괄 핑크로 바꾸지 않는다.

### 3.3 의미가 있는 상태

| 상태 | 글자·아이콘 | 바탕 | 표현 예 |
|---|---|---|---|
| 성공 | `success` `#5BE09C` | `success-bg` `#173126` | 체크 + ‘카메라가 연결됐어요’ |
| 경고 | `warning` `#F4B95F` | `warning-bg` `#352A18` | 경고 아이콘 + 상황과 가능한 조치 |
| 오류 | `danger` `#F4AFA8` | `danger-bg` `#3D2028` | 오류 아이콘 + 실패 원인·다시 시도 |
| 정보 | `info` `#8AD0F4` | `info-bg` `#172D39` | 정보 아이콘 + 현재 상태 |
| 관계 변화 | `affection-text` `#F4A9C9` | `affection-soft` `#341925` | 하트 + ‘함께한 시간으로 +10’ |

오류와 핑크를 구분한다. 정보를 전달하는 색에는 항상 문구 또는 아이콘을 함께 둔다. 경고색을 단순 장식에 쓰지 않는다. 시간·집중률·횟수의 판정 기준은 서비스 로직에 둔다. 디자인 문서가 새 임계값을 정하지 않는다. 여러 친구를 구별하는 차트 색은 별도 데이터 시리즈 역할이며, 모든 선을 보라/핑크 두 색으로 강제하지 않는다.

실행 결과·처리 안내는 공통 `FeedbackMessage`에서 상태 색과 아이콘·문구를 함께 적용한다. 기본은 `body-compact` 14/22이며 카메라 영상 위의 조밀한 안내만 `caption` 12/18을 쓴다. 상태 안내에 기본 외곽선을 추가하지 않는다.

| 실제 상황 | 상태 | 적용 |
|---|---|---|
| 프로필 저장·이미지 저장/공유·링크 복사·선물 전송 완료 | 성공 | success + 체크 |
| 크레딧 부족·수동 복사 필요·얼굴 미감지·가상 배경 대체 | 경고 | warning + 경고 아이콘 |
| 이미지 저장 실패·답장 실패·장치 연결/감지 실패 | 오류 | danger + 닫기/실패 아이콘 |
| 카드 생성 중·감지/가상 배경 준비 중·공유 취소 | 정보 | info + 정보 아이콘 |

성공·정보는 `role="status"`, 조치가 필요한 경고·오류는 `role="alert"`로 알린다. 공부 화면의 장치/감지 상태도 같은 색과 아이콘을 사용한다. 단순 검색 결과 개수·시간·선택 상태를 모두 상태색으로 칠하지 않으며, 관계 진전은 별도 affection 의미를 유지한다.

## 4. 외곽선 없이 구분하는 컴포넌트

### 4.1 기본 바탕 선택

| 상황 | 바탕 | 추가 구분 수단 |
|---|---|---|
| 페이지 | `canvas` | 섹션 간격 40px |
| 큰 정보 그룹 | `panel` 또는 바탕 없음 | 같은 제목·정렬, 내부 간격 24px |
| 누를 수 있는 카드 | `surface` | 실행 가능한 제목/아이콘·호버·포커스 |
| 모달·선택창 | `surface-raised` | 오버레이 + `0 16px 48px #00000066` 그림자 |
| 툴팁·팝오버·프로필/도구 메뉴 | `floating` | 공통 FloatingSurface의 popover-shadow. 기본 외곽선 없음 |
| 일반 입력창 | `surface` | 라벨·안쪽 여백·포커스, 입력 예외는 1px 선 |
| 일반 보조 버튼 | `control` | 버튼 크기·일관된 상태 변화 |
| 달력 좌우 이동·닫기(X) | `transparent` | 호버 바탕·키보드 포커스만 |
| 이미지 위 짧은 대사 | 기본 `#191823F2`, 대체 `#191823` | 배경 이미지와 합성한 실제 대비 확인 |
| 공부 화면 독 | 적용 전의 반투명 그라데이션·밝은 원형 버튼·분홍 종료 버튼 | 전용 legacyStudyDock 재질. 24px blur·140% 채도 유지 |

카드를 구분하려고 안쪽 1px 하이라이트·상시 링·얇은 그림자 띠를 두르지 않는다. 필요한 내부 구분선은 유지한다. 기본 간격은 4·8·12·16·24·32·40·48px, 모서리는 컨트롤 12px·카드 20px·모달 24px를 유지한다. 이 문서가 새로운 페이지 레이아웃이나 애니메이션을 정의하지는 않는다.

카드 안에 여러 실행 버튼이 있으면 카드 전체를 하나의 버튼처럼 호버 처리하지 않는다. 각 실행만 구분한다. 부모 카드와 자식 버튼이 같은 색이 되는 조합도 실제 합성 상태에서 확인한다. 단일 실행 카드의 호버 규칙을 여러 조작이 있는 정보 카드에 그대로 확장하지 않는다.

작은 떠 있는 표면은 `FloatingSurface`를 공유한다. 배경은 불투명 floating `#403E4B`, 그림자는 `0 12px 32px #00000066, 0 3px 10px #00000033`이며 --popover-shadow로 생성한다. 일반 모달의 --floating-shadow와 구분한다. 권한 안내·관계 진행률·기록 달력/차트 툴팁·프로필 메뉴·공부 데모 메뉴에 적용한다. 위치·폭·여백은 각 컴포넌트가 정하고 배경/그림자를 중복 지정하지 않는다.

표면 위 글자는 ink 또는 muted를 사용한다. 정적 대비는 각각 10.04:1·6.38:1, 메뉴 항목 호버의 ink/floating-hover는 6.28:1이다. 기존 surface-raised를 전역 변경해 모든 모달을 밝게 만들지 않는다. 공부 독의 툴팁·추가 도구는 전용 재질을 사용한다. 독 툴팁은 기능명이나 짧은 동작명만 사용한다. 예: `카메라 켜기`, `아바타 보기`, `대화 열기`, `10분 쉬기`, `공부 재개`, `공부 종료`. 긴 설명이나 단축키를 덧붙이지 않는다.

반투명 표면은 이미지 위 독과 짧은 대사에 한정한다. 일반 폼·카드·모달에는 불투명 토큰을 우선한다. 유리 효과는 가장 밝은 이미지 장면에서도 글자 대비를 확인하고, 부족하면 불투명 대체색으로 전환한다. 표의 정적 대비 값을 반투명 장면의 검증값으로 사용하지 않는다.

홈 배너의 인사 말풍선은 이미지가 비치는 별도 유리 표면을 사용한다. `panel` 68%에서 `canvas` 62%로 이어지는 그라데이션, 18px 배경 흐림과 140% 채도를 적용하며 기본 외곽선은 두지 않는다. 배경 흐림 미지원 환경은 불투명 `panel`로 대체한다. 홈 효과를 위해 다른 화면의 공통 유리 표면 값을 낮추지 않는다.

공부 독은 사용자가 복원을 지정한 전용 재질이므로 공통 surface·danger 색으로 치환하지 않는다. 기존의 안쪽 빛 반사·11px 툴팁·비활성 opacity 0.5도 이 예외에 포함한다. 종료 버튼은 기본 `#F04E66E8`, 호버 `#FF6278`, 누름 `#D83B54`로 구별한다. 700px 미만에서는 마이크·카메라·추가 도구·대화·쉬는 시간·종료의 44px 버튼 6개를 표시하고 화면/배경은 같은 재질의 추가 도구에 모은다. 독과 추가 도구에는 확대/전체 보기 버튼을 두지 않고 친구나 내 화면을 직접 눌러 확대한다. 팝업은 독 전체를 기준으로 가운데 배치해 320px에서도 잘리지 않게 한다. 대화 아이콘은 상단의 별도 채팅 버튼을 대체하며 실제 채팅 열림·닫힘을 표시한다. 데스크톱 배치와 확대 반응은 유지한다.

### 4.2 선을 남기는 범위

| 범위 | 기준 |
|---|---|
| 카드·패널·배너·모달·일반 버튼 | 기본 선 0px |
| 일정의 종류·이름·날짜·시간 입력 | `input-border` 1px 허용 |
| 로그인·회원가입 이메일/비밀번호/확인 | `input-border` 1px 허용 |
| 내 아바타 만들기 닉네임 입력 | `input-border` 1px 허용 |
| 검색창 | 기본 선 없음. 입력 예외를 검색창 전체에 확장하지 않음 |
| 호버·누름·선택·펼침·키보드 포커스 | 상호작용 강조선 허용. 기본 바탕 구분의 대체로 남용하지 않음 |
| 공부 화면의 말하기·메시지 표시 | 해당 친구/내 화면 안쪽에 `success` 2px 허용. 실제 활동 중에만 표시하며 주변 배치를 밀지 않음 |
| 키보드 포커스 | `focus-ring` 2px, 바깥 간격 4px. 숨기거나 부모에서 잘라 내지 않음 |
| 목록·표·헤더·영수증의 내부 구분선 | 유지. 박스 전체를 감싸지 않음 |
| SVG 아이콘·진행률·차트의 선 | 정보 표현이므로 유지 |

선택된 탭·옵션은 바탕 + 체크/글자 굵기 + `aria-pressed`/radio 상태로 알린다. 색상만 바꾸는 것으로 끝내지 않는다. 조작 시 강조가 생겨도 테두리 두께 때문에 주변 배치가 움직이지 않게 한다.

공부·휴식·확대 화면은 공통 `.is-speaking` 표시를 사용한다. 새 친구 메시지가 출력되는 동안에는 해당 프레임에 초록색 `#5BE09C` 2px 안쪽 선과 `말하는 중` 상태를 표시한다. 내 메시지 전송 직후에는 내 프레임을 잠깐 표시하고, 켜 둔 마이크의 입력 소리가 감지될 때에도 같은 선을 표시한다. 내 화면의 음성/전송 상태는 보조 기술용 문구로 제공한다. 채팅 상대 선택·답장 대기·마이크 켜짐만으로 선을 유지하지 않는다. 읽은 이력을 다시 열어도 표시를 반복하지 않으며, 창 닫기·상대 전환·입력 종료에는 해제한다. 움직임 줄이기에서는 타이핑을 생략하면서 새 메시지의 상태 선은 잠깐 표시한다. 기본 외곽선 규칙이나 키보드 포커스 선과는 별개의 일시적 상태다.

## 5. 버튼과 입력의 상태 규칙

### 5.1 버튼 종류

| 종류 | 기본 → 호버 → 누름 바탕 | 글자 | 용도 |
|---|---|---|---|
| `primary` | `primary` → `primary-hover` → `primary-active` | `on-solid` | 공부 시작·폼의 주 실행 |
| `secondary` | `control` → `control-hover` → `control-active` | `ink` | 저장 보조·취소·일반 도구 |
| `soft` | `primary-soft` → `primary-soft-hover` → `primary-soft-active` | `text-accent` | 맥락상 보조 실행·대화 열기 |
| `ghost` | 투명 → `control` → `control-active` | `muted` | 달력 이동·닫기·가벼운 아이콘 도구 |
| `danger` | `#3D2028` → `#4A242E` → `#572833` | `danger` | 일반 화면의 종료·삭제 조작 |
| `danger-solid` | `#D62332` → `#B51E2B` → `#941927` | `on-solid` | 종료/삭제 확인창의 최종 실행 |

`danger-bg-hover`·`danger-bg-active`·`danger-solid`·`danger-solid-hover`·`danger-solid-active`도 JSON에 별도 토큰으로 둔다. 위험 조작을 빨간 외곽선만으로 표현하지 않는다. 카카오 등 외부 서비스의 공식 버튼은 브랜드 지침을 유지하는 예외다.

기본 버튼은 단색이다. 기존 보라 그라디언트는 통일 작업에서 위 단색 상태로 옮긴다. 색상은 버튼의 종류로, 크기는 밀도로 결정한다. ButtonLink도 동일한 규칙을 사용한다. 같은 종류·크기 버튼의 색·글자 크기를 페이지에서 덮어쓰지 않는다.

### 5.2 버튼 크기

| size | 최소 높이/폭 | 좌우 패딩 | 타이포그래피 | 사용 범위 |
|---|---:|---:|---|---|
| `xs` | 32px | 12px | `button-micro` 12/18·600 | 조밀한 보조 도구에만. 주요 실행에 쓰지 않음 |
| `sm` | 40px | 16px | `button-compact` 14/20·600 | 이미지 저장 등 도구 조작 |
| `md` | 44px | 20px | `button` 16/24·600 | 일반 실행 |
| `lg` | 48px | 24px | `button` 16/24·600 | 로그인·공부 시작·폼 완료 |

최소 높이를 쓰고 고정 높이로 글자를 자르지 않는다. 글자가 두 줄이면 버튼도 높아진다. 큰 버튼을 만들려고 17·19px 같은 임의 글자 크기를 추가하지 않는다. 아이콘 전용 버튼도 같은 크기 체계를 사용하고 접근성 이름을 둔다.

768px 미만에서 공통 xs/sm 버튼도 최소 44×44px 조작 영역을 사용한다. 글자 크기는 역할을 유지한다. 닫기·프로필·모바일 달력 이동·검색 지우기 등 독립 아이콘도 44px 영역을 확보하며 화살표와 X의 기본 바탕은 투명으로 유지한다.

비활성은 `disabled` + `text-disabled`를 사용하며 호버·실행을 막는다. `ghost`의 비활성 바탕은 투명이다. 버튼 전체에 opacity를 낮추지 않는다. 로딩은 기존 폭·글자색을 유지하고 중복 실행을 막는다. 비활성처럼 희미하게 만들어 처리 중 상태를 알리지 않는다.

사용자가 원형을 복원한 공부 독만 전용 재질의 비활성 표현을 사용한다. 이 예외를 일반 Button으로 확장하지 않는다.

### 5.3 입력과 선택

일정·달력의 선택 가능한 최초 날짜는 **2026-01-01**이다. 공통 기준은 `src/shared/lib/date-limits.ts`에서 관리한다. 일정 추가/수정과 캡슐 카드의 날짜 휠에서 2026년 이전 연도는 표시하지 않는다. 마이페이지는 2026년 1월에서 이전 달 이동을 비활성화하고, 이전 연도의 이웃 날짜는 빈 칸으로 둔다. 내 기록도 주·월·년 범위를 2026년부터 제공하며 첫 주는 1월 1일부터 4일까지 표시해 요일 정렬을 유지한다. 제한에 닿은 이동 버튼은 disabled + text-disabled를 쓰고 배경은 투명하게 유지한다. 2026년 안의 지난 일정은 허용하며, 캡슐 카드의 다음 공부 약속처럼 더 늦은 하한이 있는 입력은 그 조건을 함께 적용한다. 이전 저장 데이터는 일괄 삭제하지 않는다.

입력값은 Pretendard `control` 16/24·400, 라벨은 `label` 14/20·500, 도움말·오류는 `body-compact` 14/22·400을 쓴다. placeholder는 `placeholder` 색이며 라벨을 대신하지 않는다. 포커스 때의 강조와 오류 문구를 함께 표시할 수 있어야 한다. 오류가 나도 키보드 포커스를 지우지 않는다.

홈·친구 검색창의 예시 문구는 `body-compact` 14px로 표시하고 실제 입력값은 `control` 16px를 유지한다. 작은 예시 크기를 일반 폼 입력값까지 확장하지 않는다.

로그인/회원가입은 필드 아래 FeedbackMessage 오류와 aria-invalid·aria-describedby를 연결하고 첫 오류 입력으로 포커스를 옮긴다. 브라우저 검증 말풍선에 의존하지 않으며 필수 입력·이메일 형식·회원가입 비밀번호 8자/일치·필수 동의 검사는 유지한다. 키보드 포커스는 입력도 2px·offset 4px를 사용한다.

회원가입의 필수 동의 문구는 44px 조작 영역에서 가운데 정렬하고, 동의 오류 안내 위에는 추가 마진을 넣지 않는다. 이메일 인증 단계는 같은 입력 패널을 교체해 표시한다. 인증번호는 실제 입력 하나와 숫자 칸 6개로 표현하며, 칸에는 surface 바탕·input-border 1px 입력 예외를 적용한다. 입력 숫자는 Pretendard stat 크기(모바일 section-title 크기), 포커스는 focus-ring, 오류는 danger, 완료는 success/success-bg를 사용한다. 이동하는 포커스·오류 흔들림·완료 전환은 움직임 줄이기 설정에서 생략한다. 인증 화면 전체를 둘러싸는 카드 외곽선은 추가하지 않는다.

OTP 성공은 6칸이 중앙으로 합쳐진 뒤 둥근 완료 배지로 펼쳐지고 체크·문구가 나타나는 약 0.6초 전환이다. 완료 배지는 기본 외곽선을 두지 않고 success-bg 바탕과 success 글자·체크로 표시한다. 남은 시간은 이메일과 같은 행의 오른쪽 48px 영역을 사용하며, 입력칸까지 24px을 둔다. 제목→설명은 12px, 설명→이메일 행은 8px, 입력칸→하단 링크 행은 8px, 링크 행→확인용 안내는 4px이다. 전환 전후 이메일/남은 시간 행·입력 영역·44px 조작 행의 높이를 유지해 제목·이메일·로그인 위치가 바뀌지 않게 한다. 움직임 줄이기 설정에서는 최종 상태를 즉시 표시한다.

목표 시간 range는 primary 채움·control 트랙·18px 원형 손잡이와 44px 조작 높이를 사용한다. 기존 5분 단위·5~180분 범위와 키보드 Home/End/방향키 동작을 유지한다.

640px 미만의 대화 옵션 카드는 이름·가격·단위를 표시하고 전체 특징은 선택된 옵션 아래 한 영역에 모은다. 미선택 카드는 panel, 선택 카드는 selected를 사용한다. 데스크톱에서는 기존 카드 안 특징 목록을 유지한다.

선택된 옵션은 `selected` + `selected-text`, 미선택 옵션은 기본 표면 + `ink`를 쓴다. 펼침·선택·호버를 서로 다른 상태로 관리한다. 입력·선택 컴포넌트는 같은 FormField/SearchField/WheelField 안에서 상태를 구현한다.

## 6. 서체와 타이포그래피

### 6.1 서체 사용 범위

| 계열 | 사용 | 사용하지 않는 곳 |
|---|---|---|
| Pretendard | 일반 페이지 제목·홈 배너의 인사 말풍선·룸 설명·실시간 채팅·버튼·입력·숫자·접근성 안내 | 스터디룸 상세 배너의 룸 제목과 명시된 이야기 표현은 Hahmlet 사용 |
| Hahmlet | 스터디룸 상세 배너의 룸 제목·리포트의 한마디·캡슐 카드의 이야기 제목/대표 문장 | 일반 기능 페이지 제목·홈 배너의 인사 말풍선·룸 설명·폼·버튼·도구·계속 읽는 실시간 채팅 |
| JetBrains Mono | 현재 구현 이력과 개발용 표시에서만 유지 가능 | 통일 후 일반 UI·타이머·잔액의 신규 기준으로 사용하지 않음 |

Hahmlet은 룸의 분위기를 소개하는 제목과 한 영역의 대표 문장에 사용하고 설명 전체로 확장하지 않는다. 일반 채팅은 친구가 말하는 내용이어도 Pretendard다. 짧은 대사도 상태/오류/권한 안내라면 Pretendard를 사용한다. Hahmlet은 20px 미만으로 줄이지 않으며, 긴 설명·대화문은 Pretendard 본문 블록으로 전환한다.

**스터디룸 상세 배너의 HTML 룸 제목은 `story-title`을 사용한다.** 기본은 Hahmlet 32/40·700, 640px 미만에서는 26/36·700이다. ‘쌀쌀맞은 갸루짝꿍이 나에게만 친절하다!’처럼 길어도 같은 서체를 유지하고 두세 줄로 자연스럽게 배치한다. 두세 줄은 배치 권장값이며 강제 줄 수 제한이 아니다. 제목을 맞추려고 임의로 작게 압축하거나 말줄임표로 숨기지 않는다. 룸 설명은 Pretendard `body` 16/26·400, 공부 시작 버튼은 Pretendard `button` 16/24·600을 사용한다. 헤더·뒤로 가기·부가 정보도 Pretendard를 유지한다.

홈 포스터 등에 사용하는 공식 룸 제목 이미지와 로고는 원본을 보존한다. 이 에셋을 Hahmlet로 다시 만드는 작업과 상세 배너의 HTML 제목에 서체를 지정하는 작업을 구분한다.

홈 배너의 인사 말풍선은 `home-greeting`을 사용한다. Pretendard 16/24·500, 640px 미만에서는 14/22·500으로 표시하고 현재의 짧은 인사는 한 줄로 유지한다. 대표 대사용 `story-quote`를 적용하지 않는다. 문구 추가 시 320px에서도 줄바꿈·잘림 없이 들어가는 길이로 작성한다.

목표 기본 스택은 `Pretendard, Apple SD Gothic Neo, sans-serif`, 포인트 스택은 `Hahmlet, Pretendard, serif`다. Hahmlet은 공식 Google Fonts 가변 TTF를 수정 없이 자체 호스팅한다. [폰트 배포 기록](../src/assets/brand/README.md)과 [OFL 원문 고지](../public/licenses/Hahmlet-OFL.txt)를 포함하며, 500·700 굵기를 사용한다. `font-display: swap`과 대체 폰트에서도 버튼·제목·내보내기 레이아웃이 유지되어야 한다.

코드 이름은 `--font-sans`, `--font-story`를 사용하고, 숫자 계열은 `--font-sans`를 공유한다. JSON의 `font.numeric`은 다른 폰트 파일이 아니라 숫자 기능 설정이다. Figma에서도 같은 두 서체 계열을 사용한다.

### 6.2 역할별 크기·행간·굵기

단위는 CSS px다. 16/26은 글자 16px, 줄 높이 26px를 뜻한다. 작은 화면은 640px 미만이며 아래에 적은 역할만 축소한다. 본문·입력값·버튼까지 비례 축소하지 않는다.

| 이름 | 서체 | 크기/행간 | 굵기 | 640px 미만 | 사용 |
|---|---|---:|---:|---:|---|
| `hero-title` | Pretendard | 48/60 | 700 | 32/42 | 앱 홈의 대표 제목 |
| `page-title` | Pretendard | 30/40 | 700 | 26/36 | 페이지 제목 |
| `section-title` | Pretendard | 20/28 | 700 | 동일 | 화면 안 주요 구역 |
| `dialog-title` | Pretendard | 20/28 | 700 | 동일 | 모달 제목 |
| `card-title` | Pretendard | 16/24 | 600 | 동일 | 카드 이름·일정 그룹 제목 |
| `body` | Pretendard | 16/26 | 400 | 동일 | 일반 본문·기본 채팅 |
| `body-compact` | Pretendard | 14/22 | 400 | 동일 | 조밀한 설명·폼 도움말 |
| `label` | Pretendard | 14/20 | 500 | 동일 | 입력 라벨·정보 항목명 |
| `control` | Pretendard | 16/24 | 400 | 동일 | 입력값·선택값 |
| `button` | Pretendard | 16/24 | 600 | 동일 | md·lg 버튼 |
| `button-compact` | Pretendard | 14/20 | 600 | 동일 | sm 버튼 |
| `button-micro` | Pretendard | 12/18 | 600 | 동일 | xs 보조 도구 |
| `caption` | Pretendard | 12/18 | 400 | 동일 | 날짜·전송 시각·부가 단위 |
| `stat` | Pretendard | 32/40 | 700 | 동일 | 주요 통계 수치 |
| `timer` | Pretendard | 32/40 | 700 | 동일 | 넓은 시간 표시 |
| `timer-compact` | Pretendard | 22/30 | 700 | 동일 | 공부 헤더의 시간 표시 |
| `home-greeting` | Pretendard | 16/24 | 500 | 14/22 | 홈 배너의 한 줄 인사 말풍선 |
| `story-title` | Hahmlet | 32/40 | 700 | 26/36 | 스터디룸 상세 배너의 룸 제목·카드의 이야기 제목 |
| `story-quote` | Hahmlet | 24/36 | 500 | 22/34 | 리포트·기념 카드 한마디 |

일반 정보는 12px 미만으로 만들지 않는다. 기존의 9·10·11px 상태/시각/대화 조작 글자는 통일 때 역할에 맞춰 12 또는 14px로 올린다. 장식용 영문 표제도 새 기준에서 최소 caption을 사용한다. 카드 밀도가 달라도 같은 역할 제목은 16/24를 유지한다. 밀도는 패딩·간격으로 조절한다.

자간은 Pretendard hero/page 제목 −0.02em, section/dialog 제목 −0.01em, 나머지 0이다. Hahmlet은 0을 기본으로 한다. 한글은 `word-break: keep-all`, 긴 URL·식별자는 `overflow-wrap: anywhere`로 처리한다. 안내·오류·가격·중요 수치를 말줄임표로 숨기지 않는다. 이름·제목의 길이 제한이나 말풍선 줄 수는 기능 요구가 있는 컴포넌트에만 적용한다.

Tailwind 크기 이름은 `--text-<역할>`, 행간은 `--text-<역할>--line-height`에 대응한다. 예를 들어 body는 `--text-body: 16px`, `--text-body--line-height: 26px`다. 굵기·자간은 같은 공통 역할 스타일 또는 컴포넌트에서 함께 묶고 페이지에서 다시 정하지 않는다. Figma는 `typography/body`처럼 같은 역할 이름의 텍스트 스타일로 관리한다.

### 6.3 숫자·단위

타이머·가격·크레딧·집중률·정렬된 통계 수치는 Pretendard에 `font-variant-numeric: tabular-nums lining-nums`를 사용한다. ‘1’과 ‘8’이 바뀌어도 주변 배치가 움직이지 않아야 한다. 본문의 일반 문장까지 숫자 폭 고정을 강제하지 않는다.

경과/목표는 같은 계열·크기를 사용하고 경과는 700·`ink`, 목표는 500·`muted`, 구분자는 `subtle`로 표시한다. 상태에 따른 집중률 색은 기존 판정 기준을 유지한다. 숫자 옆 ‘분’·‘크레딧’ 등 단위는 기본적으로 caption이 아니라 label로 읽히게 한다.

AnimatedClock은 Pretendard의 숫자 폭을 고정하고, 숫자 셀은 `1ch` 너비·`1lh` 높이로 부모 timer 역할의 행간을 따른다. 이전 JetBrains Mono의 `1.35em` 높이는 제거했다. 문서의 timer 40px / timer-compact 30px 행 높이와 내부 애니메이션 높이가 충돌하지 않게 한다. `11:11:11`↔`08:08:08`, 시간 자릿수 증가, 움직임 줄이기 상태를 확인한다.

### 6.4 같은 영역 안에서의 문구 위계

역할은 문구의 목적과 주변 정보를 함께 보고 정한다. HTML의 `p`/`span` 여부나 기존 크기만 보고 일괄 변환하지 않는다. 작은 글자의 최소값 검사와 가로 넘침 검사에 더해, **같은 카드 안에서 대표 제목과 설명·날짜·상태를 직접 비교한다.**

| 내용 | 역할 | 기준 |
|---|---|---|
| 독립 구역 제목 | section-title | 20/28·700. 예: 함께 여는 콘텐츠 |
| 카드의 대표 이름·콘텐츠 제목 | card-title | 16/24·600. 예: 내일도 와라, 손 흔들기, 상품 이름 |
| 내용을 이해하는 데 필요한 설명·혜택 | body-compact | 14/22·400. 날짜용 caption으로 줄이지 않음 |
| 분류·날짜·열림 조건·전송 시각 | caption | 12/18·400. 제목보다 크거나 굵게 표시하지 않음 |
| 입력·선택값 | control | 16/24·400. 입력 라벨 14px보다 클 수 있음 |

- 해금 콘텐츠는 제목 16px, 날짜·조건 12px로 구분한다. 날짜와 조건은 보조색, 성공색은 ‘열림’ 같은 상태 단어에만 사용한다.
- 보조 설명은 같은 카드의 대표 제목보다 크게 표시하지 않는다. 계층이 같을 때는 굵기·색·간격으로 구분할 수 있다. 날짜와 상태를 14–16px로 키워 카드 제목보다 강조하지 않는다.
- 가격·집중률·타이머 같은 핵심 수치와 대표 대사는 해당 영역의 주요 내용이다. 일반 보조 문구로 취급해 축소하지 않는다. Hahmlet 사용 범위도 유지한다.
- `cn()`은 JSON의 모든 글자 역할을 `tailwind-merge`의 `theme.text`에 등록한다. `text-caption text-muted`처럼 크기와 색을 함께 써도 두 속성이 남아야 한다. 새 역할을 추가할 때 병합 회귀 테스트와 실제 계산 스타일을 함께 확인한다.

## 7. 화면에서 함께 적용하는 규칙

| 영역 | 컬러 | 글자 |
|---|---|---|
| 헤더·내비게이션 | 기본 `muted`, 선택 `text-accent` | label. 잔액·날짜도 최소 12px |
| 홈 | UI 바탕은 뉴트럴, 실행만 보라. 인사 말풍선은 전용 유리 표면 | hero/page 제목은 Pretendard, 인사 말풍선은 home-greeting. 기존 룸 제목 이미지는 보존 |
| 스터디룸 상세 | UI 바탕은 뉴트럴, 실행만 보라 | 배너의 룸 제목은 Hahmlet story-title. 설명·버튼·헤더는 Pretendard |
| 준비·권한 확인 | 입력은 surface, 주 실행 primary, 연결 상태는 상태 색 | 제목 page/dialog, 라벨 label, 값 control |
| 공부·휴식 | 타이머 ink, 목표 muted, 독은 지정 반투명 표면 | timer-compact, 일반 대사·채팅 body |
| 리포트 | 지표는 ink, 관계 증가만 affection | 제목 page-title, 수치 stat, 대표 한마디만 story-quote |
| 캡슐 카드 | 팔레트 범위의 효과, 로고·그림 원본 유지 | 핵심 데이터 Pretendard, 이야기 제목·대표 문장만 Hahmlet |
| 기록·친구·마이페이지 | 같은 panel/surface/control 역할 | 같은 위계 제목은 같은 타이포그래피 토큰 |
| 크레딧·패스·상점 | 가격은 ink, 실행 primary/soft | 숫자 tabular, 주요 가격 stat 또는 별도 명시된 가격 역할 |

화면이 MVP 범위에서 제외되어 있어도 기존 서비스 화면에 같은 원칙을 적용할 수 있다. 이 표가 화면을 시연 동선에 다시 포함하라는 뜻은 아니다. 가격 등 별도 크기가 필요하면 페이지 한 곳에서 임의 지정하지 말고 역할·사용처·반응형 값을 토큰에 추가한다.

홈을 포함한 일반 화면과 룸 상세는 공통 `SiteHeader`를 사용한다. 바탕은 canvas, 하단 구분선은 1px이며 안쪽 최소 높이는 82px다. 768px 미만은 로고/계정 60px + 내비게이션/현재 위치 44px + 상단 여백 8px로 112px를 공유한다. 하단 선을 포함한 실제 기본 높이는 각각 83px·113px다. 로고 폭은 132px, 768px 미만 118px로 통일한다. 룸 제목이 길어져도 현재 위치 영역만 말줄임 처리하며 계정 영역이나 헤더 높이를 밀어내지 않는다.

리포트 통계는 StatCard의 responsive-row 변형이 내부 패딩·값 마진을 소유한다. 480px 미만에서는 패딩 12/16px·값 위 마진 0·라벨/값 중앙 정렬, 그 이상에서는 세로형을 사용한다. 리포트 사진은 900px 미만에서 4:5 비율을 따르고 오래된 전역 min-height를 사용하지 않는다.

룸 상세 헤더에서 로고—세로 구분선—홈의 두 간격은 768px 이상에서 각각 24px로 맞춘다. 홈·화살표·룸 이름 사이의 경로 간격은 별도 묶음에서 16px, 480px 미만에서는 10px로 유지한다. 작은 화면은 기존처럼 구분선을 숨기고 경로를 두 번째 행에 배치한다.

크레딧 내역은 768px 미만에서 날짜/내용·우측 변동액·보조 잔액을 묶은 목록, 그 이상에서 표를 사용한다. 필터와 결제 내역 열기는 같은 데이터를 공유한다. 공부 종료는 독·헤더 모두 같은 확인창을 거쳐 저장하며 취소하면 세션을 유지한다. 확인창에는 실제 공부 누적 시간을 `시:분:초`로 표시하고 쉬는 시간은 제외한다. 종료 확인창의 제목은 중앙 정렬하고 X 버튼과 중복 저장 안내 문구는 두지 않는다. 처음 열면 공부를 계속하는 버튼에 초점을 두며 Escape·바깥 클릭으로도 취소한다. 리포트의 비집중 시간 항목은 `자리 비움`으로 통일한다.

공부 독의 커피잔 아이콘은 `쉬는 시간`이며 누르면 실제 공부 시간을 보존하고 10분 휴식으로 전환한다. 휴식 중에는 같은 자리가 재생 아이콘의 `공부 이어가기`로 바뀌어 일찍 복귀할 수 있으며, 10분이 끝나면 안내창 없이 자동으로 공부를 재개한다. 같은 목표·옵션·세션으로 공부 누적 시간부터 재개하며 휴식 화면의 별도 이어가기·종료 버튼은 두지 않는다. 목표 달성 후 재개한 공부도 실제 시간에 더한다. 일시정지는 제공하지 않는다.

카메라를 끄면 헤더와 같은 원형 얼굴 아바타를, 켠 상태의 아바타 모드에서는 원 없는 기존 일러스트를 표시한다. 원형 아바타는 기본 96px·640px 이상 112px, 다른 화면 확대 중 작은 칸에서는 48px로 표시한다. 친구 이미지와 내 화면 모두 클릭·Enter·Space로 확대/복귀하며, 내 화면 확대 시 원형 아바타는 144px·640px 이상 176px로 커진다. 내 화면도 공통 focus-tile 배치와 확대/축소 아이콘·키보드 포커스를 사용하고 모바일에서는 확대된 칸을 헤더 아래에 표시한다. 휴식 중 내 썸네일을 누르면 메인 영상 크기로 확대하며 친구들은 썸네일로 모은다. 다시 누르거나 Escape로 이전 친구 화면에 복귀하고, 친구 썸네일을 눌러 해당 친구로 바꿀 수도 있다. 영상 DOM·보기 모드·배경·대화 상대와 초안은 유지한다. 캠 배경 선택은 카메라가 켜졌을 때만 가능하며 선택한 배경은 아바타 모드에도 적용한다. 배경 선택으로 실제 카메라 보기를 강제하지 않는다. 카메라가 꺼지면 선택 배경은 숨기고 설정만 유지한다. 배경 선택창의 중복 제목·안내·미리보기 버튼은 두지 않는다. `.study-dock-popover`는 독과 같은 그라데이션·24px blur·140% 채도·안쪽 반사를 쓰고 기본색만 `#262532D9`로 짙게 한다. 선택창을 연 동안 독 확대를 멈추고 작은 화면에서는 팝오버 내부 스크롤을 사용한다. 기존 독 본체의 유리 재질과 색은 유지한다.

이미지 위 글자는 이미지의 밝기 변화까지 확인한다. 필요하면 지정된 뉴트럴 스크림으로 가독성을 확보한다. 그림 위에 색상을 그대로 놓고 일반 패널의 대비 계산을 통과했다고 간주하지 않는다.

## 8. 대비 기준과 계산값

일반 텍스트는 최소 4.5:1을 기준으로 한다. 이 문서는 사용처에 따른 혼동을 줄이기 위해 버튼·캡션에도 같은 기준을 적용한다. 굵은 16px 글자는 큰 글자 예외가 아니다. 반올림하기 전 비율로 통과를 판정한다. [W3C 텍스트 대비 설명](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

필수 아이콘·선택 표시·컨트롤 식별 정보는 인접색과 3:1 이상으로 구분한다. 모든 카드 바탕끼리 3:1이어야 하는 것은 아니며, 이 조건을 충족하려고 상시 외곽선을 추가하지 않는다. [W3C 비텍스트 대비 설명](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)

다음은 HEX 값의 sRGB 상대 휘도를 계산한 **목표 토큰의 정적 값**이다. 구현·반투명 장면·실제 글꼴 렌더링을 검증한 결과는 아니다. 전체 조합과 원시 비율은 JSON의 `contrast.cases`에 둔다.

| 조합 | 대비 | 판정·용도 |
|---|---:|---|
| ink / canvas | 18.40:1 | 본문 통과 |
| muted / panel | 10.71:1 | 보조 설명 통과 |
| subtle / surface | 5.90:1 | 캡션·placeholder 통과 |
| text-accent / panel | 9.68:1 | 링크·선택 글자 통과 |
| 순백 / primary | 4.68:1 | 기본 버튼 통과. 순백 유지 |
| 순백 / primary-hover | 7.23:1 | 호버 버튼 통과 |
| 순백 / primary-active | 9.74:1 | 누름 버튼 통과 |
| ink / control-hover | 6.28:1 | 중립 버튼 호버 통과 |
| text-accent / primary-soft-active | 5.37:1 | 보조 버튼 누름 통과 |
| affection-text / affection-soft | 8.66:1 | 관계 변화 문구 통과 |

| input-border / surface | 3.69:1 | 허용된 입력 테두리 식별 통과 |
| ink `#FAFAFD` / primary | 4.49:1 | **일반 글자 불통과. 순백과 바꾸어 쓰지 않음** |

버튼의 정상·호버·누름을 각각 검증한다. `opacity`로 버튼 전체를 흐리게 하거나 흰 글자에 투명도를 주면 이 표의 대비를 보장하지 못한다. 실패 조합의 사용을 글자 굵기·그림자로 보완했다고 간주하지 않는다.

## 9. 현재 코드에서 옮기는 순서

### 9.1 적용 전과 적용 결과

| 적용 전 | 적용 결과 |
|---|---|
| canvas `#0C1017`, panel `#141923` | canvas `#0F0E17`, panel `#191823`, 조작 카드에는 surface `#292733` |
| brand-solid `#8051CC`와 여러 보라 그라디언트 | primary `#7E54F6`의 단색 상태 세트 |
| brand / brand-strong / focus 용도가 혼재 | 채움 primary / 글자 text-accent / 포커스 focus-ring 분리 |
| 버튼 크기에 따라 12·13·14·15px | xs 12 / sm 14 / md·lg 16px, 굵기 600 |
| section-title 18/28 | 20/28·700 |
| control 15/20 | 16/24·400 |
| 타이머 JetBrains Mono | Pretendard + tabular-nums, 숫자 애니메이션 함께 조정 |
| 룸 상세 배너 제목이 기본 UI 서체를 사용 | Hahmlet story-title 32/40·700, 작은 화면은 26/36·700. 긴 제목은 자연 줄바꿈 |
| 대사에 전용 명조 없음 | 특별한 대표 문구는 Hahmlet, 일반 채팅은 Pretendard |
| 채팅·상태·시각의 9~11px 글자 | 역할에 따라 caption 12 또는 body-compact 14px |
| white/65 등 임의 투명 글자 | 읽어야 하는 정보는 muted/subtle의 불투명 색 |

새 `surface`의 의미는 기존 `--color-surface` 사용처와 항상 같지 않다. 단순 값 치환 전에 큰 패널·일반 카드·버튼·입력 중 어떤 역할인지 확인한다. 기존 `line`은 구분선과 입력 테두리·상태 강조로 분리한다. `brand-line` 같은 과거 테두리 토큰을 새 상시 외곽선으로 되살리지 않는다.

### 9.2 적용 단위

1. **토큰**: `npm run tokens:sync`로 JSON에서 `src/styles/design-tokens.css`와 `src/shared/design/tokens.ts`를 생성한다. `index.css`에서 불러오며, `npm run tokens:check`로 생성물 차이와 47개 정적 대비 조합을 검사한다. Figma도 같은 이름/값으로 맞춘다. 기존 별칭이 필요하면 이전 기간에만 새 용도를 가리키게 하고 중복된 독립 값으로 남기지 않는다.
2. **공통 컴포넌트**: Button/ButtonLink의 종류·크기·상태, Panel, PageHeading, FormField, SearchField, WheelField, Tabs, Dialog부터 옮긴다. 현재 Button에 없는 danger/로딩 표현은 공통 컴포넌트에서 정의한다.
3. **독립 CSS**: 채팅·독·타이머·리포트·차트·결제 등 기능 CSS의 직접 지정 색과 글자 크기를 역할 토큰으로 옮긴다. hover·active·disabled·focus도 같은 변경에 포함한다.
4. **이미지·카드 출력**: 이미지 위 대사, 캡슐 카드 DOM과 Canvas/PNG에 같은 색·서체·텍스트 역할을 연결한다. Hahmlet도 로딩 후 내보낸다. 화면과 저장 이미지가 서로 다른 폰트로 나오면 미완료다.
5. **정리**: 이전 별칭과 직접 지정 값을 재검색한다. 실제 사용이 끝난 서체/의존성만 정리하고 에셋·라이선스 이력은 보존한다.

`@theme` 값만 바꾸면 전체가 통일된다는 전제는 두지 않는다. 현재 버튼 그라디언트, 채팅 보내기 버튼, 말풍선, 입력창, 타이머·집중률 등에는 직접 지정 값이 남아 있다.

새 토큰과 다르게 보여야 하는 상황은 공통 컴포넌트의 문서화된 variant로 만든다. 한 페이지의 `text-[17px]`, HEX, 투명도를 임시로 추가해 해결하지 않는다. 공식 에셋·외부 브랜드·데이터 차트·예술 효과처럼 의도적인 예외는 범위와 이유를 남긴다.

카드용 서체가 로드되지 않으면 깨진 글자나 빈 문장으로 저장하지 않는다. 다시 시도하거나 미리보기와 내보내기 모두 같은 Pretendard 대체 서체를 사용한다. 캡슐 카드의 표현을 바꿀 때도 기존 데이터·PNG 저장 동작은 유지한다.

## 10. 디자인 통일 작업의 완료 조건

아래 항목은 이후 변경에서도 지켜야 할 검수 기준이다. 이번 코드 적용의 실제 확인 범위와 남은 별도 검수는 12장에 기록한다. Figma 파일 수정과 브라우저별 접근성 인증을 이 체크리스트로 대신하지 않는다.

- CSS·Figma·JSON의 토큰 이름과 값이 일치한다. 문서 예외 이외에 새로운 직접 색상/글자 크기가 없다.
- 같은 종류·크기 버튼의 색·글자·호버·누름·비활성·로딩이 모든 화면에서 같다.
- 기본 외곽선이 되살아나지 않았고 보조 버튼은 배경과 구분된다. 달력 화살표·닫기는 기본 배경이 없다.
- 입력 외곽선 예외와 내부 구분선은 유지된다. 키보드 포커스가 충분히 보이고 잘리지 않는다.
- 작은 글자·placeholder·실패 안내를 실제 화면에서 읽을 수 있다. 색만으로 상태를 구분하지 않는다.
- 타이머·통계·잔액이 바뀌어도 숫자 폭과 주변 배치가 흔들리지 않는다.
- Hahmlet의 용도·최소 크기를 지키며 모든 실시간 채팅을 명조로 바꾸지 않았다.
- 스터디룸 상세 배너의 룸 제목은 story-title을 사용하고, 긴 제목과 작은 화면에서도 전체 제목을 읽을 수 있다. 설명·버튼·헤더는 Pretendard다.
- 이미지 위 독/글자와 유리 효과는 실제 가장 밝은 장면에서 대비를 확인했다.
- 폰트 로딩 전·후와 실패 시, 긴 이름·금액·오류 문구·200% 확대에서도 정보가 잘리지 않는다.
- 지원 화면 폭에서 주요 제목·폼·버튼이 가로로 넘치지 않는다. 작은 화면에서도 본문을 줄이지 않는다.
- 리포트·캡슐 카드 미리보기·저장 PNG가 같은 문구·데이터·색·서체를 사용한다.
- 사용하지 않는 폰트·별칭 정리를 끝냈고 도입한 폰트의 배포 고지를 반영했다.

이후 검증 결과에는 커밋·대상 화면·화면 폭·상태·실패/예외를 함께 기록한다. 디자인 통일로 공부 시간·대화 횟수·카메라 권한·기록 삭제 같은 도메인 동작이 바뀌면 안 된다.

## 11. 근거와 변경 기록

문서 작성 시 47개 용도 색, 18개 글자 역할, 6개 버튼 종류의 참조를 확인했다. 정적 대비 47개 조합 중 허용 조합 43개는 기준을 충족하고 사용 금지 예 4개는 기준 미달임을 확인했다. 문서와 JSON의 기본 팔레트·글자 크기/행간/굵기를 대조했다. 이것은 토큰 검증이며 실제 화면 적용·시각 검증·회귀 테스트 완료를 뜻하지 않는다.

## 12. 코드 적용 기록 · 2026-11-03

기준 커밋 `85debe6` 위의 로컬 변경이다. 배포·커밋·Figma 파일 수정은 포함하지 않는다. 기능 정책·가격·크레딧 계산·얼굴 감지 판정·기록/채팅 데이터 흐름은 유지한다.

### 적용 범위와 유지 방법

- Front_Web: 로그인/회원가입/약관, 아바타 만들기, 홈, 스터디룸 상세 9종, 목표·옵션 설정/일정 팝업, 공부/휴식/채팅/옵션 변경, 리포트/캡슐 카드, 내 기록, 친구/선물·보이스, 마이페이지/일정, 내 크레딧/상품/결제·영수증, 빈 화면/오류 화면.
- 공통 Button/ButtonLink는 6개 종류·4개 크기와 명시적인 비활성/로딩 상태를 공유한다. 카드/모달은 기본 선 없이 표면 색을 사용하고, 입력 예외·구분선·선택/호버/키보드 강조는 유지한다.
- CSS `type-역할`은 서체·크기·행간·굵기·자간을 함께 적용한다. 640px 미만에서 hero/page/story 제목·대표 대사와 홈 인사 말풍선의 지정 토큰만 바뀐다. 같은 제목 크기를 페이지에서 다시 지정하지 않는다.
- Hahmlet은 story-title/story-quote의 허용된 문구에만 사용한다. JetBrains Mono의 런타임 의존성·font-face·타이머 사용은 제거하고 과거 라이선스 고지는 보존했다.
- 캡슐 카드는 360×600 아트보드를 화면 폭에 맞춰 전체 축소하고, PNG는 720×1200으로 출력한다. 이미지 높이·본문 위치·대표 문장 크기는 `capsule-card-layout.ts`에서 공유한다. 고정 출력물의 글자 역할은 아트보드 기준이며, 작은 화면에서 UI 폼의 글자를 줄이는 규칙이 아니다.
- Landing_Page에 적용했던 공통 토큰·스타일·버튼 로딩 속성·README 변경은 사용자 요청에 따라 기존 상태로 원복했다. 생성된 `src/design-tokens.css`를 제거하고 Front_Web 토큰 생성 명령의 랜딩 출력도 제거했다. 이후 `tokens:sync`와 `tokens:check`는 Front_Web 내부 생성물만 대상으로 한다.

### 의도적으로 유지한 예외와 별도 검수

공식 로고·룸 제목 이미지·일러스트, 아바타 파츠 색, 차트 데이터 시리즈, 영수증의 인쇄 용지, 홀로그램/광원 재질은 일반 UI 팔레트 치환 대상이 아니다. 차트는 서로 구별되는 데이터 색을 유지하고, 히트맵 단계는 새 팔레트의 밝기 차이로 구별한다.

정적 토큰 대비와 위의 Chromium 화면 확인을 모든 브라우저·모든 확대 비율·모든 실제 카메라 장면의 검증으로 확대 해석하지 않는다. 실제 브라우저 200% 확대와 장치별 최종 검수, Figma 변수/컴포넌트 동기화는 별도 확인 범위다.

### 실행 검사

### CSS 초기화 순서 · v1.0.7

공통 컴포넌트가 계층 CSS를 초기 진입 때 가져올 수 있으므로 main.tsx는 전역 index.css를 컴포넌트보다 먼저 import한다. theme/base/components/utilities 순서가 먼저 등록돼야 하며, 컴포넌트 계층이 먼저 생겨 preflight가 나중에 기존 패딩/버튼 배경을 덮는 상황을 막는다.
