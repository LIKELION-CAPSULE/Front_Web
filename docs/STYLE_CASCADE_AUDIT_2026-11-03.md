# 스타일 우선순위 전수 검수와 디자인 개선 제안

검수일: **2026-11-03 · Asia/Seoul**  
대상: **현재 로컬 Front_Web의 코드와 Chromium 화면**  
상태: **스타일 충돌 7건·개선안 6개 반영 및 로컬 검증 완료**

## 판단 요약

의도한 규칙이 다른 선언에 밀리는 항목 **7건**을 확인했다. 우선 수정할 곳은 **모바일 캡슐 카드, 리포트 통계 카드, 휴식 화면의 주요 버튼**이다. 기본 화면의 명시적인 글자 역할에서는 추가 누락을 발견하지 못했지만, 배치와 상태별 스타일에는 충돌이 남아 있었다.

원인은 단순한 부모/자식 관계가 아니다. 일반 선언에서는 **계층 밖 CSS가 계층 안 CSS보다 우선**하고, 현재 구성에서는 **utilities가 components보다 우선**한다. 같은 계층에서는 상세도와 선언 순서가 작용한다. 선택자를 더 길게 쓰거나 파일 끝으로 옮기는 것만으로 해결되지 않는 충돌이 있다.

아래의 재현 결과는 수정 전 관측 기록이다. 현재 적용 상태와 검증은 마지막 수정 결과 절을 따른다.

기본 글자 검사는 명시적 클래스를 기준으로 한다. 그 클래스를 사용하지 않는 영역, transform/zoom 후의 물리 크기, 네이티브 컨트롤의 내부 모양까지 통과 판정한 것은 아니다. 상태별 배치와 이미지는 별도로 확인했다.

실제 촬영·음성 인식·외부 결제·LLM 응답 품질은 스타일 검수 대상에 포함하지 않았다. 장치 실패는 검수 브라우저에서 권한 거절을 모사했다. 결제·공부 동선은 격리된 체험 컨텍스트에서 확인하고 종료했다. 화면 확인은 로컬 개발 서버 기준이며 Safari/Firefox·실기기 터치·운영 빌드의 CSS 결합 순서는 별도 확인 대상이다.

## 수정 전 재현한 규칙 7건

### F1 · 우선 · 모바일 캡슐 미리보기와 PNG 배치 불일치

- 의도: 360×600 아트보드, 패딩 28px, 사진 높이 224px. 미리보기는 전체를 축소하고 PNG는 같은 좌표를 2배로 출력.
- 실제 390/320px: 줌 적용 전 카드 높이 약 580px, 패딩 24px, 사진 약 240px. 데스크톱은 600/28/224로 정상.
- 원인: [고정 아트보드 규칙](../src/features/reports/capsule-card-layout.css)은 components 계층, [기존 모바일 규칙](../src/styles/index.css)은 계층 밖이라 기존 값이 이긴다.
- 영향: 사진 아래 여유·카드 높이가 달라진다. PNG는 [공유 배치 값](../src/features/reports/capsule-card-layout.ts)의 600/224를 사용하므로 모바일 미리보기와 저장 결과가 다르며 stage 예약 높이도 어긋난다.
- 제안: 이전 모바일 카드 높이/패딩/사진 규칙을 정리하거나 고정 아트보드 외부로 범위를 제한. 카드 내부는 한 규칙이 소유하고 축소는 stage에서 처리한다. !important 추가는 권하지 않는다.

### F2 · 우선 · 모바일 리포트 통계의 여백·정렬 무효

- 의도: 479px 이하에서 카드 패딩 12px 16px, 값의 위 마진 0.
- 실제 390/320px: 패딩 20px 12px, 값의 위 마진 12px, 카드 높이 94px. 라벨과 값의 세로 중심도 어긋남.
- 원인: [리포트 모바일 규칙](../src/features/reports/report-completion.css)이 components 계층이라 [StatCard](../src/shared/ui/Panel.tsx)의 p-panel-compact·px-3·mt-3 유틸리티에 밀린다.
- 제안: StatCard에 세로/가로 배치를 명시하는 variant를 두고 패딩과 값 마진을 함께 정의. 부모 CSS가 내부 유틸리티를 다시 덮는 구조를 피한다.
- 보조 검증: 검수 브라우저에서만 의도값을 임시 적용하자 카드 높이가 **94→66px**, 세 카드 합계 84px 감소. 비교 후 새로고침해 임시 스타일을 해제했다.

### F3 · 보통 · 작은 리포트 사진의 비율이 최소 높이에 밀림

- 의도: [리포트 전용 규칙](../src/features/reports/report-completion.css)은 min-height 0, 모바일에서는 4:5 비율.
- 실제 320px: 폭 240px, 높이 360px. aspect-ratio는 4/5로 남지만 min-height가 높이를 강제.
- 원인: [계층 밖 전역 모바일 규칙](../src/styles/index.css)의 min-height 360px가 우선한다.
- 제안: 전용 비율 규칙이 크기를 소유하도록 이전 min-height를 정리. 브라우저 임시 비교에서 해제 시 높이가 **360→300px**로 변함을 확인하고 원복했다.

### F4 · 우선 · 휴식 화면의 주요 버튼이 16px에서 12px로 축소

- 의도: [휴식의 두 Button](../src/pages/StudyPage.tsx)은 공통 기본 lg, button 역할 16/24 사용.
- 실제 390px: ‘목표 정하고 공부 이어가기’, ‘오늘은 여기까지’ 모두 12/18, 패딩 10px 13px.
- 원인: [699px 이하 전역 규칙](../src/styles/index.css)이 계층 밖에서 type-button을 덮는다.
- 영향: 48px 높이의 실행 버튼 안에서 글자만 작아져 일반 시작/완료 버튼과 비율이 다름.
- 제안: 두 실행은 16px 유지. 좁은 화면은 줄바꿈·가로 폭으로 조정하고 별도 전역 font-size는 제거한다.

### F5 · 보통 · 장치 버튼의 모바일 전용 크기가 미적용

- 소스 의도값: [장치 모바일 버튼](../src/features/media/media.css)은 12px, 최소 높이 36px, 패딩 6px 10px.
- 실제 320px 권한 실패 상태: 두 버튼 모두 14px, 최소 높이 40px, 패딩 8px 16px.
- 원인: components 선언이 Button sm의 유틸리티와 type-button-compact에 밀린다.
- 판단/제안: **현재 14px/40px가 디자인상 나쁜 값이라는 뜻은 아니다.** 공통 기준과 터치 편의상 현재 값을 유지하고 무효 선언을 지우는 편을 우선 권한다. 12px 복구를 자동 수정 목표로 삼지 않는다.

### F6 · 보통 · 입력 키보드 포커스가 공통 2px 대신 1px

- 의도: [공통 포커스](../src/styles/index.css)와 디자인 시스템은 2px·바깥 간격 4px.
- 실제: 이메일 로그인에서 Tab으로 이동한 입력은 focus-visible=true, outline 1px, offset 4px.
- 원인: [form-input:focus-visible](../src/styles/interactions.css)의 components 선언이 base의 공통 포커스를 덮는다.
- 제안: 입력도 포커스 두께 2px로 통일. 일반 카드/버튼의 상시 외곽선을 추가하는 작업과는 별개다.

### F7 · 보통 · 종료 독의 누름 색이 호버에 가려짐

- 의도: 종료 버튼 active는 danger-bg-active #572833.
- 실제: 마우스로 누른 채 :active=true를 확인해도 hover 색 #4A242E.
- 원인: [종료 버튼 hover](../src/features/session/study-dock.css)가 같은 상세도의 active 바로 뒤에 있어 두 상태가 함께 성립하면 이긴다.
- 제안: active를 hover 뒤에 두거나 hover 조건에서 active를 제외. 버튼 상태 선언의 순서를 함께 정리한다.

## 잠재 충돌과 유지 구조

[Dialog 기본 클래스](../src/shared/ui/Dialog.tsx)는 모든 presentation에 p-6·sm:p-8·rounded-3xl을 붙인다. [sheet/popover 규칙](../src/styles/index.css)은 components 계층이라 패딩/모서리를 유틸리티에 덮일 수 있다. 현재 호출부에 이 presentation을 전달하는 사용처는 없어 **재현한 7건에는 포함하지 않았다.** 추후 사용 시 presentation별 기본 클래스를 함께 선택해야 한다.

계층 밖 선언 자체를 모두 오류로 분류하지 않는다. 검색 예시 14px, 탭의 선택 바, 룸 그림 배치, 휠, 영수증은 용도에 맞는 예외를 포함한다. CSS 파일을 한 번에 components로 감싸면 이들까지 달라질 수 있다.

권장 순서:

1. F1/F2/F4처럼 화면이나 저장 결과가 달라지는 항목부터 수정.
2. StatCard·Button·Dialog의 변형이 내부 크기와 간격까지 소유하도록 정리. 같은 속성의 페이지 CSS/유틸리티 이중 지정 제거.
3. 계층 밖 반응형 규칙을 해당 컴포넌트 가까이 이동하고 필요한 예외를 명시.
4. 변경 영역의 hover/active/disabled/focus-visible과 320/390/768/1440px 재확인.
5. 고정 출력물은 DOM 너비·높이·사진 좌표를 내보내기 상수와 비교. 최소 글자 크기·문서 넘침 검사만으로 대신하지 않음.

## 정상 확인한 영역과 후속 기준

- 검색 예시 14px/입력값 16px, 검색어 지우기 후 포커스 유지. 공통 헤더와 기본 제목/본문/캡션 역할.
- 기록 기간 이동·현재 기간 복귀, 친구 전체 선택/해제. 북마크 burst의 장식용 돌출은 페이지 넘침을 만들지 않아 오류로 분류하지 않음.
- 일정 종류/날짜/시간은 하나만 펼쳐지고 즉시 반영. 바깥 클릭 닫기·배경 스크롤 잠금 정상.
- 회원가입 체크·약관 창, 결제 동의 전 비활성 색, 영수증 출력/분리 정상. 밝은 인쇄 용지는 의도된 재질.
- 채팅은 데스크톱 우측 패널, 390/320px에서 viewport 안쪽 모달. 3회 재열기에도 composer 50px·textarea 24px 유지. 옵션 모달은 전체 화면 중앙.
- 캡슐의 움직임 줄이기 설정에서 transform none. 대표 문장의 서체/크기는 유지되며 F1은 글자 토큰이 아닌 배치 충돌.
- 정적 변수 대조 결과 필수 변수의 미정의 누락은 발견하지 못함. JSX/JS의 인라인 공급도 포함해 판단.

카드의 화면/PNG 배치, 통계 정렬, 휴식 버튼과 종료 누름 색을 아래 결과로 다시 대조했다. 다른 브라우저와 실기기 터치 검수 범위는 구분해 기록한다.

## 수정 결과와 검증

## 추가 반영 · 툴팁과 떠 있는 메뉴의 배경 구분

사용자 요청에 따라 전용 floating `#403E4B`·floating-hover `#5E5C69`와 popover-shadow를 추가하고 `FloatingSurface`로 표면 처리를 공유했다. 적용 범위는 카메라/마이크 권한 안내, 친구 관계 진행률, 기록 달력/차트 툴팁, 프로필 메뉴, 공부 데모 메뉴다. 외곽선은 추가하지 않았으며 일반 모달의 surface-raised와 복원한 공부 독의 전용 재질은 유지했다.

기존 표면의 중복 배경/그림자 선언은 제거했다. 차트의 보조 글자는 muted로 조정했고 메뉴 내부의 호버/키보드 포커스는 floating-hover로 구분한다. 공부 데모 메뉴 내부 버튼은 surface를 사용해 새 메뉴 바탕과 같은 색이 되지 않게 했다.

공통 CSS를 연결하는 과정에서 components 계층이 전역 스타일보다 먼저 등록되는 초기 로딩 문제가 발견돼 main.tsx의 전역 CSS를 첫 import로 고정했다. 개발 브라우저의 stylesheet 순서와 빌드 CSS의 properties/theme/base/components/utilities 순서를 확인했다. 초기 로딩에서 페이지 패딩과 기본 버튼 배경이 preflight에 밀리지 않는지 재검증했다.

검증:

- 1440/390/320px에서 실제 안내/차트/달력 툴팁을 열어 배경 rgb(64,62,75), 그림자, 외곽선 0, 화면 내 배치와 닫기를 확인했다. 관계 진행률·프로필 메뉴·공부 데모 메뉴도 직접 열어 확인했다.
- 프로필 메뉴 항목의 호버는 rgb(94,92,105), 공부 데모 메뉴의 내부 버튼은 rgb(41,39,51), 공부 독은 기존 반투명 그라데이션과 blur 24px·saturate 140%를 유지했다.
- 전역 로딩 순서 보정 후 기본 44개 URL × 1440/390px = **88개 조합**에서 글자 역할 **2,892개**, 페이지 컨테이너 패딩과 주요 버튼 배경을 대조했다. 추가 누락·페이지 가로 넘침 0건.
- ink/floating 10.04:1, muted/floating 6.38:1, ink/floating-hover 6.28:1. 추가한 3개 조합을 포함한 정적 대비 50개 중 허용 46개 통과, 금지 예시 4개는 실패 조건 유지.
- `npm run lint`, `npm run build`, `npm test` **100/100**, `npm run tokens:check`, `git diff --check` 통과. 실제 캡처로 표면의 분리와 기존 버튼/여백 유지를 함께 확인했다.
