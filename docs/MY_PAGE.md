# 마이페이지와 통합 일정

프로필 메뉴의 `내 아바타 바꾸기`를 `마이페이지`로 바꾸고 `/mypage`를 추가했습니다. 로그인 이후 접근할 수 있으며 공통 헤더와 본문을 사용합니다.


## 제목 행의 보기 전환 · 2026-11-05

`마이페이지` 제목과 같은 행에 AnimateIcons Lucide UserRound / CalendarDays 아이콘 토글을 배치합니다. 공통 `Tabs`의 iconOnly 옵션을 사용하고 버튼은 각각 44×44px입니다. 기본은 프로필·아바타이며, 다른 버튼은 달력과 일정 목록을 함께 보여줍니다. 선택 상태는 `aria-pressed`, 조작 대상은 `aria-controls`, 아이콘의 이름은 숨긴 레이블로 제공합니다. Enter/Space로도 선택할 수 있습니다.

프로필 화면의 `section[aria-labelledby="profile-heading"]`은 유지합니다. 두 영역은 마운트를 유지한 채 선택하지 않은 쪽만 `hidden`으로 숨기므로, 화면을 전환해도 저장 전 닉네임·아바타, 달력의 월·선택 날짜·기간을 보존합니다. 숨긴 화면은 표시와 키보드 탐색에서 제외됩니다. 공통 Tabs는 숨긴 영역의 선택 배경을 0 크기로 측정하지 않고, 다시 보이면 현재 버튼 위치에 즉시 맞춥니다.

`/mypage#schedule`은 일정 화면으로 열립니다. `add=1`도 일정 화면과 편집기를 함께 열며, 저장/닫기 시에는 add만 제거하고 `#schedule` 및 next 등의 기존 쿼리를 보존합니다. 보기 토글은 URL의 hash를 바꾸고 현재 페이지의 스크롤을 강제로 일정 위치로 이동시키지 않습니다.

헤더의 프로필 메뉴에서는 사용자 이름 구분선과 첫 마이페이지 항목 사이를 8px 띄워 호버·포커스 배경이 선에 붙지 않게 했습니다.

## 가입 단계·아바타·계정 설정 · 2026-11-25

### 가입(`/onboarding`) 두 단계
- 1단계 「프로필 만들기」: 아바타·닉네임, 생년월일(계정에 없을 때만). 2단계 「초대 코드」: 건너뛸 수 있다. 이미 초대 코드가 등록된 계정은 1단계에서 바로 시작한다(단계 표시 없음).
- 2단계는 같은 경로의 `?step=2`다. 브라우저 뒤로 가기와 「이전」 버튼이 1단계로 돌아가며 입력값은 그대로다.
- **저장 시점**: 마지막 단계까지 서버에 아무것도 보내지 않는다. 끝낼 때 ① 입력한 초대 코드가 있으면 확인(`validateReferralCode`) → ② `completeOnboarding` 한 번으로 닉네임·아바타·생년월일·코드를 함께 저장 → ③ `reload` 후 `next`(없으면 홈)로 이동. 기존 호출 순서와 같다.
- **실패**: 코드 확인 실패는 2단계에 머물며 입력칸에 오류를 보여 준다. 저장 실패는 알림을 띄우고 모든 값을 유지한다(다시 누르면 재시도). 「건너뛰기」는 코드 없이 같은 저장을 한다.
- **중복 제출 방지**: 「시작하기」를 누르면 코드 확인을 시작하기 전에 잠금과 로딩 표시가 걸린다(`onboarding-submit.ts`). 확인 중의 두 번째 「시작하기」, 「건너뛰기」, 「이전」은 무시된다. 저장 직전에 화면을 떠났거나 로그인 계정이 바뀌었으면 저장하지 않는다.
- **새로고침·중간 이탈**: 닉네임과 고른 아바타는 이 탭의 `sessionStorage`(`capsule-onboarding-draft:v1`, 사용자 ID로 구분)에 남는다. 생년월일은 개인정보라 남기지 않으므로, 생년월일이 필요한 계정이 2단계에서 새로고침하면 1단계로 돌아간다. `?ref=` 코드는 기존 7일 저장소에 있어 2단계에 다시 채워진다. 저장이 끝나면 초안을 지운다.
- 2단계에는 채린 정지 이미지와 유리 말풍선이 닉네임으로 인사한다: 「○○, 반가워! 친구한테 받은 초대 코드가 있으면 알려 줘.」 / `?ref=`로 왔을 때 「○○, 반가워! △△님이 초대해 줬구나. 코드만 확인하면 바로 시작이야.」 혜택은 「친구를 초대하면 둘 다 크레딧 1,000」 + 「받은 초대 코드를 넣고 첫 연결을 마치면 나와 친구 모두 받아요.」
- 1단계 아바타 이름 아래 인사: 닉네임 입력 전 「닉네임을 알려 주면 인사할게요.」, 입력 후 「안녕, ○○! 이 모습으로 함께할게요.」

### 아바타 고르기(`AvatarDial`, 가입 1단계와 계정 설정 프로필 탭 공용)
- 고른 아바타 하나만 Live2D(Cubism)로 불러온다. 썸네일 줄은 정지 이미지다. 가운데가 선택이며 크기와 보라 빛으로 표시한다(테두리 없음). 클릭, 좌우 방향키·Home/End, 좌우 스와이프로 고른다.
- 무대는 어디서나 4:5다. 모델 뒤에 보라 방사형 후광을 두고, 허리 아래는 무대(모델이 아니라 그 바깥 틀)의 마스크로 바탕에 녹인다. 모델의 색·모양은 바꾸지 않는다(라이선스).
- 바꿀 때 새 모델이 그려지면 280ms에 걸쳐 나타나고, 그다음 이전 모델(WebGL 컨텍스트·텍스처·ticker)을 해제한다. 160ms 안에 다시 바뀐 선택은 모델을 만들지 않는다. 동시에 최대 두 개.
- 새로 고른 모델을 불러오지 못하면 이전 모델을 바로 해제하고, 고른 아바타의 썸네일(없으면 기본 이미지)과 「다시 시도」를 보여 준다(`avatar-preview-state.ts`).
- 텍스처: 엔진이 Pixi `Assets`(URL 캐시)로 올린 텍스처는 그 모델을 쓰는 마지막 무대가 해제될 때 `Assets.unload`로 지운다(`live2d-stage.ts`, 모델별 참조 수). 6종을 돌고 나가면 남는 텍스처가 10장(약 160MB) → 0장.
- 움직임 줄이기: 썸네일 줄은 즉시 이동하고, 무대는 정지 썸네일을 보여 준다(Live2D를 불러오지 않음).
- 목록이 비면 「기본 아바타」 아래에 「선택할 수 있는 아바타가 없어요. 기본 아바타로 시작해요.」를 일반 흐름으로 둔다(이전에는 두 글자가 겹쳤다). 이때 `avatarId` 없이 저장한다.
- 아래에 표기 의무 문구 「본 서비스의 아바타 캐릭터에는 주식회사 Live2D의 저작물이 이용되었습니다.」(목록에 Live2D 모델이 있을 때).

### 아바타 구도 값(백엔드 `GET /api/avatars`의 `model`)
무대(4:5) 안에서 모델 전체를 contain으로 맞춘 뒤 `scale`배 하고, 중심을 무대 너비·높이의 `offsetX`·`offsetY` %만큼 옮긴다. 아래 값은 눈높이를 무대 높이의 약 36%, 허리까지 보이게 맞춘 값이다(로컬 mock `src/features/local-demo/local-avatars.ts`와 같다).

|---|---|---|---:|---:|---:|
| 히요리 | `hiyori_pro_t11.model3.json` | PRO(파라미터 70, 2048×2) | 2.35 | 0 | 60 |
| 하루 | `haru_greeter_t05.model3.json` | 안내(단일) | 2.64 | 0 | 81 |
| 나토리 | `natori_pro_t06.model3.json` | PRO(단일, 4096 텍스처) | 3.3 | 0 | 107 |
| 치토세 | `chitose.model3.json` | PRO(단일) | 2.2 | 0 | 54 |

- **썸네일**(`thumbnailUrl`): 머리와 어깨가 들어간 정사각 투명 PNG(로컬 생성물은 504×504). 썸네일 줄 원, 헤더 아바타, 움직임 줄이기 때의 무대 정지 이미지로 쓴다. 로컬은 `scripts/capture-avatar-thumbnails.mjs`가 위 구도 무대에서 잘라 만든다. 파일이 없거나 실패하면 지금처럼 실루엣/기본 일러스트로 대체한다.
- 모델 파일은 저장소에 넣지 않는다. 운영 번들에는 로컬 경로가 들어가지 않는다(로컬 목록은 개발 전용 `local-demo`에만 있다).

### 계정 설정 모달
- 프로필·설정·보안 구성은 그대로다. 모달 전체를 홈 말풍선 유리 재질로 바꾸고(흐림 미지원 시 불투명 `panel`), 사이드바는 더 어두운 색조로 나누며 선을 없앴다. 입력칸은 테두리 없이 `surface` 채움 + 포커스 링만 쓴다.
- 프로필 탭: 왼쪽(좁으면 위)에 가입과 같은 `AvatarDial`, 오른쪽 유리 패널에 프로필 제목·닉네임·호칭·나에 대해와 저장 버튼을 둔다(아래 고정 저장 막대와 그 위 구분선은 없앴다).
- 설정 탭: 조작할 수 없는 「대화 비용」 칩(기본 채팅·보이스·고급·보이스+고급 단가)을 뺐다. 설정 화면은 바꿀 수 있는 것만 두고, 비용은 연결 화면의 대화 모드 선택과 크레딧 화면에서 알린다.
- 레이어: 모달은 네이티브 `<dialog>`의 `showModal()`이라 브라우저 최상위 레이어에 뜬다. 홈 위에서 모달 가운데 지점의 최상단 요소가 모달 안인지 1440·1280·390px에서 확인했다(z-index 문제 없음).

## 프로필

닉네임과 헤어·의상·외모·배경을 편집하고 저장합니다. 저장 전에는 미리보기만 바뀌며 `되돌리기`로 저장된 상태를 복원할 수 있습니다. 빈 닉네임은 저장할 수 없습니다. 저장하면 공통 헤더 아바타와 프로필 이름에도 반영됩니다.

`features/profile/components/AvatarCustomizer`와 `avatar-options.ts`를 가입 직후 `OnboardingPage`와 마이페이지의 `ProfileEditor`가 함께 사용합니다. 가입의 초기 아바타 설정 흐름도 유지합니다.

## 일정

`ScheduleManager`는 나의 시험·목표·약속을 `state.memories`의 공통 목록으로 관리합니다. 한 번 등록한 일정은 모든 캐릭터가 함께 기억하며, 일정에 `characterId`를 저장하지 않습니다. 목록의 캐릭터 필터·캐릭터 표시와 편집기의 기억할 캐릭터 선택을 제거했습니다. 일정 추가·수정·삭제는 기존 `MEMORY`/`DELETE_MEMORY` 액션을 사용하며, 편집기는 `features/schedule/components/MemoryEditor.tsx`에 있습니다.

일정 영역의 `#schedule`은 왼쪽 `ScheduleCalendar`와 오른쪽 `ScheduleListPanel`을 배치하는 그리드입니다. 두 컴포넌트는 각각 독립된 배경과 여백을 가진 카드로 표시하며, `ScheduleManager`가 선택 날짜·기간·편집 상태를 공유합니다. 목록·기간 탭·추가·수정 버튼은 `ScheduleListPanel`, 일정 편집은 `MemoryEditor`가 담당합니다. 연도·월을 직접 고르거나 이전/다음 달로 이동하며, 오늘 버튼으로 서울 기준 현재 날짜를 선택합니다. 일정이 있는 날짜에는 점을 표시하고 같은 날에 여러 일정이 있으면 개수를 표시합니다. 날짜를 누르면 오른쪽에 해당 날짜의 일정을 표시하며, `전체 일정 보기`나 기간 탭으로 날짜 선택을 해제합니다. 선택한 날짜에서 추가하면 편집기의 날짜가 미리 채워집니다. 수정·삭제 결과는 달력에 즉시 반영되며, 화면 너비가 1024px 미만이면 달력 아래에 목록을 배치합니다.

달력의 외형은 사용자가 지정한 [coss Calendar Dropdown Navigation](https://21st.dev/@coss.com/components/calendar/dropdown)과 [공식 가이드](https://coss.com/ui/docs/components/calendar)를 참고했습니다. 월·연도 순서의 드롭다운, 양쪽 탐색 화살표, 일요일 시작 요일, 흐린 이웃 달 날짜와 밝은 선택 날짜를 기존 컴포넌트에서 구현했습니다. 이웃 달의 날짜를 누르면 해당 달로 이동하며 선택 날짜와 일정 목록을 함께 바꿉니다. coss 소스나 DayPicker 패키지를 추가하지 않았으며 기존 저장·편집·일정 표시를 유지합니다.

- `예정`: 오늘과 이후 날짜, 시간순
- `전체`: 예정 일정을 먼저 표시한 뒤 최근 과거 일정부터 표시
- `지난`: 어제까지의 일정, 최근 날짜·시간순

날짜 비교는 서울 기준 날짜를 사용합니다. 시간 없는 시험·목표는 종일로 표시합니다. 약속에만 시간을 입력합니다. 필터·정렬은 `features/schedule/schedule-data.ts`에서 관리합니다. 실제 알림·캘린더 연동·서버 동기화는 연결하지 않았습니다.

일정 추가·수정의 종류는 `WheelSelectField`, 날짜와 약속 시간은 공통 `DateTimeWheelField`로 선택합니다. 휠을 조작하면 입력값이 즉시 바뀌며, 종류·날짜·시간 중 하나만 펼쳐집니다. 하단에 선택값을 중복 표시하지 않고, `완료`와 Escape는 선택값을 유지한 채 휠만 닫습니다. 일정은 `저장하기`를 누를 때 저장합니다. 마우스 휠·터치 스크롤·방향키·Home/End·PageUp/PageDown을 지원하며, 월·연도 변경 시 말일을 자동 보정하고 윤년을 반영합니다. 캡슐 카드의 다음 공부 약속에도 같은 즉시 반영·단일 펼침 동작을 적용하고 과거 날짜 선택은 제한합니다. 외형은 [Kokonut UI Wheel Picker](https://kokonutui.com/docs/inputs/wheel-picker)를 참고한 자체 구현이며, 일정 조회용 월간 달력은 기존 드롭다운 탐색을 유지합니다.

예정 일정에는 날짜 기준 `D-X`를 추가하고 오늘 일정은 `D-DAY`로 표시합니다. 지난 일정에는 카운트다운을 표시하지 않습니다. 지난 시험·목표·약속 샘플 3개는 `features/demo/sample-schedule.ts`에서 만들며, 기존 저장 데이터에도 한 번만 추가합니다. `scheduleSampleVersion`으로 이전 완료를 기록해 사용자가 수정하거나 삭제한 샘플을 새로고침 때 되살리지 않습니다. 달력의 화면 제목은 생략하고 접근성 이름과 연·월 선택·오늘 버튼은 유지합니다.

## 화면 연결

캐릭터 화면의 `함께 기억하는 일정` 영역과 `일정 관리` 링크는 제거했습니다. 일정은 마이페이지에서 관리합니다. 과거의 `/mypage?character=캐릭터ID#schedule` 링크로 접근해도 공통 일정 전체를 표시합니다.

현재 공부 준비 화면의 일정 추가는 같은 `MemoryEditor`를 준비 화면 안의 모달로 엽니다. 기존 `/mypage?add=1&next=...#schedule` 진입도 계속 지원하며, next는 기존 `safeReturnPath` 검증을 따릅니다. 예전 링크에서 저장하면 전달된 룸의 첫 일정 질문 완료 처리를 유지하고, 돌아가기 링크로 이전 화면에 복귀할 수 있습니다. 캡슐 카드에서 만든 다음 공부 약속도 캐릭터 지정 없이 동일한 공통 목록에서 관리합니다.

기존 저장 데이터는 `migrateSharedSchedule`로 이전합니다. 일정 ID·종류·제목·날짜·시간과 다른 사용자 데이터는 보존하고, 이전 `characterId` 연결만 제거합니다. 일정 개수는 그대로 유지하며, 새 공통 일정 형식도 새로고침 후 복원됩니다.
