# 반응형 컨트롤·히트맵·목표 시간

## 홈과 회원가입

- 홈 북마크는 저장 즉시 상태를 바꾸고 아이콘이 작게 튀어 오른 뒤 돌아옵니다. 저장할 때만 작은 광선을 표시합니다. 네이티브 버튼이므로 Space/Enter도 같은 동작을 합니다. 모션 감소 설정에서는 변형 애니메이션을 생략합니다.
- 북마크 저장·해제에는 우측 하단 알림을 표시하지 않습니다. 다른 기능의 알림은 각 기능에서 계속 사용합니다.
- 저장한 룸에는 별도 검색 결과 수나 `모든 룸 다시 보기` 버튼을 표시하지 않습니다. 빈 화면의 점선 외곽선과 배경도 제거했습니다. 원래 필터 버튼으로 모든 룸으로 돌아갈 수 있습니다.
- 이어서 공부하기는 왼쪽 재생 아이콘만 유지합니다. 첫 방문의 룸 둘러보기는 아래 화살표를 유지합니다.
- 약관 동의는 실제 `<input type="checkbox">` 위에 자체 CSS/SVG 체크 모션을 겹칩니다. required·FormData·폼 초기화·키보드 동작은 네이티브 입력을 사용합니다. 약관 보기 버튼은 체크 상태를 바꾸지 않습니다.

컴포넌트는 `shared/ui/BookmarkButton.tsx`, `AnimatedCheckbox.tsx`, `control-motion.css`입니다. 새 애니메이션 패키지는 추가하지 않았습니다.

### 회원가입 이메일 인증

가입 정보와 두 필수 약관을 확인하면 오른쪽 452px 입력 영역을 `EmailVerificationForm`으로 바꿉니다. 로고·포스터 모자이크는 유지합니다. 6자리 입력 시 자동 확인하며 인증하기 버튼은 표시하지 않습니다. 인증 완료 후 `로그인`을 눌러야 온보딩으로 이동합니다. 로그인·게스트 진입은 기존 흐름을 유지합니다. `가입 정보 수정`은 입력한 이메일·비밀번호·약관 선택을 복원하고 진행 중인 인증 확인을 취소합니다. 비밀번호는 임시 폼 DOM에만, 인증 대상 이메일은 컴포넌트 메모리에만 남으며 새로고침하면 사라집니다. 인증 정보는 로컬 저장소나 네트워크로 보내지 않습니다.

[affectUI OTP Input](https://www.affectui.com/components/otp-input)의 칸별 숫자·이동하는 포커스·오류 흔들림·완료 표현을 참고했습니다. 외부 패키지나 예제 소스를 추가하지 않고 공통 `VerificationCodeInput`과 CSS로 구현했습니다. 보조 기술에는 6개 입력 대신 실제 텍스트 입력 하나를 제공하며 `inputMode="numeric"`·`autocomplete="one-time-code"`를 사용합니다. 6자리 자동 확인, 전각 숫자/공백/하이픈이 들어간 번호 붙여넣기, 방향키·Home/End·Backspace 수정, 오류 연결, 성공 후 다음 버튼 포커스 이동을 지원합니다. 모션 감소 설정에서는 이동·흔들림·반짝임을 생략합니다.

정답 확인 시 기존 입력칸을 즉시 교체하지 않고 같은 DOM에서 전환합니다. 숫자가 사라지고 6칸이 중앙으로 모인 뒤 초록색 완료 배지가 펼쳐지며 체크가 그려지고 완료 문구가 나타납니다. 전체 전환은 약 0.6초입니다. 이메일/남은 시간 행·입력 영역·하단 조작 행의 높이를 유지해 제목과 이메일·로그인 위치가 위아래로 뛰지 않게 했습니다. 완료 후 `로그인`은 가운데 배치한 배경 없는 밑줄 텍스트로 표시합니다. 입력은 보조 기술·키보드 조작에서 제외하고 성공 알림은 한 번만 제공하며 로그인으로 초점을 옮깁니다. 움직임 줄이기 설정에서는 합치기·펼치기·체크 그리기를 생략하고 최종 완료 배지를 바로 표시합니다.

인증 화면 간격은 가입 정보 수정 행→제목 12px, 제목→설명 12px, 설명→이메일 행 8px, 이메일 행→입력칸 24px, 입력칸→하단 조작 행 8px, 하단 조작 행→확인용 안내 4px입니다. 남은 시간은 별도 행 대신 이메일 오른쪽의 48px 영역에 배치합니다. 인증 완료 시 해당 영역을 숨기되 폭은 유지해 긴 이메일의 줄바꿈이 변하지 않게 합니다. 하단 링크의 44px 조작 높이는 유지하고 오류 안내는 입력칸 아래 8px에 표시합니다. 320·390·768·1440px에서 긴 이메일·오류·완료 상태와 가로 넘침, 성공 전환 전후 위치 유지를 확인했습니다.

**현재는 화면 확인용 인증입니다.** 인증메일 발송·코드 검증·계정 생성 API가 없으므로 고정 확인 번호 `123456`을 사용합니다. 화면 하단에는 `화면 확인용 인증번호는 123456이에요.`를 가운데 정렬하며 실제 메일은 발송하지 않습니다. 제목은 `이메일 인증`, 설명은 `하단의 이메일로 전송된 6자리를 입력해주세요`, 그 아래에 사용자 이메일을 표시합니다. 입력 위의 중복 라벨과 재전송 질문은 제거하고 재전송 버튼은 가운데 정렬합니다. 10분 유효 시간·30초 재전송 대기는 프런트 미리보기 값이며 확정 보안 정책이 아닙니다. `email-verification-preview.ts`를 실제 서비스로 교체할 때는 서버가 발급한 인증 식별자·만료 시각·재전송 가능 시각을 사용하고 서버의 인증 결과로 가입을 완료해야 합니다. 프런트의 성공 상태나 고정 번호를 실제 이메일 소유 확인으로 사용하지 않습니다. 임의의 API 주소는 만들지 않았습니다.

약관 행은 44px 조작 영역을 유지하면서 체크박스와 문구를 가운데 정렬하고, 오류 안내 위의 8px 여백을 제거했습니다. 글자와 오류 안내의 실제 간격은 1440·390·320px 화면에서 11px로 확인했습니다.

## 일정·달력의 날짜 범위

일정과 캘린더는 **2026년 1월 1일부터** 설정합니다. `shared/lib/date-limits.ts`의 연도·날짜·월 기준을 공유하고, 날짜 휠의 연도 목록·최소 월/일·계정 설정 달력의 이전 주 이동에 적용합니다. 2026년 1월 앞에 걸쳐 나오는 2025년 날짜는 선택 가능한 버튼 대신 빈 칸으로 표시합니다. 계정 설정의 카드 입력과 목표 설정의 일정 팝업은 공통 `MemoryForm`을 사용하며, 새 일정의 초기 날짜를 하한으로 맞춥니다. `MEMORY` 저장 처리도 2026년 이전 날짜를 거부합니다. 기존 저장 데이터는 삭제하거나 일괄 변경하지 않으며 2026년 안의 지난 일정은 계속 등록할 수 있습니다.

내 기록의 주·월·년 범위도 같은 하한을 적용합니다. 기간 이동이 하한을 넘으면 최초 기간으로 제한하고 이전 주/달 화살표를 비활성화합니다. 2026년의 첫 주는 목요일 1월 1일부터 일요일 1월 4일까지로 잘라 주중 위치를 보존하며, 이전 연도의 기록은 이 기간 집계에 포함하지 않습니다. 캡슐 카드의 다음 공부 약속은 기존의 오늘 이후 제한과 공통 하한 중 더 늦은 날짜를 따릅니다. 윤년·월말 보정과 시/분 입력은 유지합니다.

## 기록 시각화

[Bklit Heatmap Chart](https://bklit.com/docs/components/heatmap-chart)의 기여도 셀·툴팁·범례 상호작용을 참고해 자체 `StudyHeatmap`을 구현했습니다. 공부 횟수나 고정 세트 개수가 아닌 **실제 공부 시간**으로 색 단계를 정합니다. 0, 30분 미만, 30분 이상, 1시간 이상, 1시간 30분 이상의 5단계입니다.

주·월은 해당 날짜를 달력 방향으로 배치하고, 년은 모든 날짜를 주별 열/요일 행으로 표시합니다. 윤년도 지원합니다. 연간 차트는 화면이 좁을 때 패널 안에서 가로 스크롤합니다. 셀에 포인터나 포커스를 두면 날짜·시간을 표시하며, 범례를 가리키면 같은 색 단계가 강조됩니다. 선택한 날짜의 실제 기록을 상세 영역에 표시합니다. 방향키·Home·End로 날짜를 이동할 수 있고 미래 날짜는 선택하지 못합니다.

[UI Beats Progress Ring](https://uibeats.com/docs/component/progress-ring)의 숫자와 호가 함께 도착하는 방식을 참고해 기존 SVG 링을 확장했습니다. 숫자·호를 하나의 RAF 값으로 갱신합니다. 표시값 변경 중 다시 바뀌면 현재 값에서 이어지고, 모션 감소 설정에서는 즉시 최종값을 표시합니다. 집중률은 실제 집중 시간 / 공부 시간이며 목표 달성률과 혼동하지 않습니다.

구현은 `features/reports/heatmap-data.ts`, `components/StudyHeatmap.tsx`, `study-heatmap.css`, `shared/ui/ProgressRing.tsx`입니다. 도입 판단과 조건은 [상업 이용 점검](REFERENCE_LICENSE_AUDIT.md)에 정리했습니다.

## 캐릭터별 라인차트와 샘플 기록

[Bklit Line Chart](https://bklit.com/docs/components/line-chart)의 다중 선·날짜 가이드·툴팁 상호작용을 참고해 SVG 기반 `CompanionTimeChart`를 구현했습니다. 별도 패키지나 레퍼런스 소스는 추가하지 않았습니다. 캐릭터 버튼으로 선을 켜고 끄며, 최초에는 함께한 시간이 많은 3명을 표시합니다. 주·월은 일별 시간, 년은 월별 시간을 보여 줍니다. 가로로 스크롤하는 캐릭터 목록은 선택 기간에 기록이 있는 친구들을 표시합니다.

포인터와 방향키·Home·End로 날짜를 살펴볼 수 있습니다. 선은 선택 기간의 시작부터 각 날짜까지 쌓인 **누적 시간**을 표시합니다. 주·월은 일별 누적, 년은 월별 누적이며, 차트 하단에 `이번 주/이번 달/올해 누적`을 표시합니다. 툴팁은 해당 날짜·월의 공부 시간과 그때까지의 누적 시간을 나란히 보여 줍니다. 예를 들어 월요일 2시간, 화요일 1시간을 공부했다면 누적선은 2시간→3시간입니다. 이전 기간의 시간을 더해 평생 누적처럼 보이게 하지 않습니다. 여러 캐릭터와 함께한 실제 세션의 시간은 기존 방식처럼 인원수로 나누어 합산하고, 미래 날짜·월은 측정값 없이 남깁니다.

시간 차트의 집중률 표시는 제거했습니다. 집중률은 사용자의 집중 시간 / 공부 시간이며, 선택한 기간·룸의 기록을 시간으로 가중 계산합니다. 현재는 더미 측정값이고 소수점 한 자리까지 표시합니다.

기록 상단은 왼쪽의 `StudyActivityPanel`과 오른쪽의 집중률·최근 스터디로 구성했습니다. 왼쪽 카드에는 공부 시간·횟수·함께한 친구와 달력을 합쳤습니다. 상단 `RecordSummary`에서 기간 요약과 선택한 날짜의 시간·횟수·집중률을 세로선으로 나눕니다. 달력 선택 상태는 `StudyActivityPanel`이 관리하고 `ActivityHeatmap`은 전달받은 날짜를 표시합니다. 선택 날짜가 새 기간을 벗어나면 오늘로 표시합니다. 오른쪽 `FocusSummary`는 선택 날짜에 영향을 받지 않는 기간 전체의 집중률을 보여 주며, 최근 스터디가 그 아래에 옵니다. 캐릭터별 누적 시간 차트는 두 열 아래의 전체 너비를 사용합니다. 내용 영역이 900px 이하이면 요약·달력→집중률→최근 스터디→누적 차트 순서로 쌓입니다. 스터디룸별 보기에도 같은 구성을 적용합니다.

공통 `Tabs`는 선택 버튼의 실제 위치와 너비를 측정해 하나의 배경 표시자를 이동시킵니다. 글자 길이·폰트 로딩·창 크기·줄바꿈에 맞춰 갱신하며, 모션 감소 설정에서는 즉시 바꿉니다. 달력의 `종료한 공부 기록 기준` 문구는 제거했습니다.

`features/demo/sample-records.ts`는 올해 1월부터 현재 날짜까지 재현 가능한 샘플을 만듭니다. 휴식일과 일별 시간 차이, 캐릭터별 집중 성향, 월별 변화, 최근에 자주 만난 소수의 친구를 반영합니다. 최근 기간의 친구 수와 시간도 누적 기간과 달라집니다. 요약 카드·일별 상세·히트맵·라인차트는 모두 이 기록을 집계하므로 별도의 화면용 숫자를 끼워 넣지 않습니다. 새 공부 종료의 더미 집중률도 고정 92% 대신 같은 측정 규칙을 사용합니다.

저장된 구형 `sample-숫자-숫자` 및 중간 시안 `sample-v2-` 레코드만 `sample-v3-` 샘플로 이전합니다. 직접 공부한 `session-` 기록, 크레딧, 프로필, 저장한 룸과 진행 중 세션은 유지합니다. 업데이트 후 새로고침하면 이전 샘플도 바뀝니다.

내 기록의 요약·달력·차트·최근 스터디 패널과 룸 선택 카드의 외곽선, 주·월·년 달력 날짜 툴팁의 외곽선을 제거했습니다. 좁은 화면에서는 긴 누적 시간의 단어가 중간에 끊어지지 않도록 표시합니다.

## 목표 시간

공부 화면은 `SessionTimer`로 `00:17:23 / 00:50:00`처럼 경과 시간 / 목표 시간을 상단 오른쪽에 표시합니다. 공부·휴식·확대 배치에서 위치가 같으며, 휴식에는 남은 시간을 표시하고 화면을 세로로 스크롤해도 상단에 유지합니다. `SessionFocus`는 같은 헤더에 실제 집중률을 표시합니다. 50% 미만 빨강, 50~80% 미만 흰색, 80% 이상 초록으로 구분하며 미측정은 회색 `—`입니다. 작은 화면에서는 집중률과 타이머를 헤더 두 번째 줄에 함께 배치합니다. 장식용 집중 상태 배지와 타이머 중복 표시를 제거했습니다. 카메라를 끈 원형 아바타는 기본 96px·640px 이상 112px, 다른 화면 확대 중 작은 칸에서는 48px로 표시합니다. 내 화면을 확대하면 144px·640px 이상 176px로 커집니다. 별도의 자리 안내 캡션은 표시하지 않습니다.

`StudyDock`은 영상 영역 위에 겹치는 반투명 유리 캡슐이며 아이콘은 원형 버튼으로 표시합니다. 마이크·카메라·아바타/실제 캠 전환·캠 배경·대화 열기/닫기·쉬는 시간·종료를 조작합니다. 휴식에는 커피잔을 재생 아이콘의 `공부 이어가기`로 바꿉니다. 이 버튼으로 휴식을 일찍 마칠 수 있으며, 10분이 지나면 안내창 없이 자동으로 공부를 재개합니다. 휴식 화면의 별도 `목표 정하고 공부 이어가기`·`오늘은 여기까지` 버튼은 제거했습니다. 대화 아이콘은 공부·휴식 모두 표시합니다. 상단의 별도 채팅 버튼과 말 걸기 모드는 제거했습니다. 대화창 열림은 배경과 작은 표시로 구분하고, 호버/키보드 초점 안내는 `마이크 켜기`·`카메라 보기`·`배경 변경`·`대화 열기`·`10분 쉬기`·`공부 재개`·`공부 종료`처럼 짧은 동작명만 표시합니다. 연결 중은 `연결 중`, 카메라가 꺼진 배경 도구는 `카메라 필요`로 표시합니다. 긴 부연 설명과 툴팁의 단축키 표기는 제거하고 단축키 동작 및 접근성 속성은 유지합니다. 독 내부에서는 좌우 화살표·Home·End로 연결 중이거나 사용할 수 없는 버튼을 건너뛰며 초점을 옮깁니다. 마우스가 가까워지면 아이콘과 이웃이 부드럽게 커지며, 터치와 모션 줄이기 설정에서는 크기를 고정합니다. 모바일 독은 마이크·카메라·추가 도구·대화·쉬는 시간/공부 이어가기·종료 6개를 바로 표시하고 화면/배경은 추가 도구에 모읍니다. 독과 추가 도구의 확대/전체 보기 버튼은 제거하고 화면을 직접 눌러 확대합니다. 추가 도구 팝업은 독 전체를 기준으로 가운데 배치합니다. 대화 입력창은 공통 오른쪽 채팅 패널 하단에 배치합니다. 데모 조작은 룸 제목 오른쪽 메뉴로 열고 Escape·외부 클릭·항목 선택으로 닫습니다.

일시정지 기능은 제공하지 않습니다. 커피잔 아이콘의 `쉬는 시간`은 `TAKE_BREAK`로 실제 공부 경과를 `studySeconds`에 보존하고 10분 휴식을 0초부터 시작합니다. 전환 전에 얼굴 감지 누적값을 반영하고, 휴식 시간은 공부 시간·집중률에 더하지 않습니다. 중도 휴식은 목표를 달성한 기록으로 바꾸지 않으며, 종료 리포트·관계 증가·대화 문맥도 실제 공부 시간을 사용합니다. 데모 메뉴의 휴식 전환도 같은 동작을 사용합니다. 홈에서 진행 중 공부로 돌아와도 타이머를 멈추지 않습니다. 구형 저장본의 정지된 공부는 이어서 시작 안내와 단방향 `RESUME_SESSION`으로 복원합니다. `다시 공부를 시작할까요?` 안내는 공부 단계의 `runningSince`가 null인 구형 저장본이나 URL에 `resume=1`이 있을 때만 표시합니다. 현재 홈·룸 상세·준비 화면의 정상 진입 링크에는 이 쿼리를 붙이지 않습니다. 완료된 채 멈춘 구형 휴식은 다음 tick에서 공부로 전환하고 멈춰 있던 오프라인 시간은 공부에 더하지 않습니다.

**MVP/API 연동 예정 정책 — 2026-11-03 결정:** `다시 공부를 시작할까요?`는 비정상적으로 종료된 공부에 다시 진입할 때 표시합니다. MVP 기능 축소와 백엔드 API 연결 단계에서 현재 데모 복원 조건을 이 정책으로 교체합니다. 비정상 종료 판정과 복원 정보는 해당 연동 단계에서 구체화합니다.

휴식 중 `공부 이어가기`는 `CONTINUE_STUDY`로 같은 세션의 실제 공부 누적값에서 타이머를 재개합니다. 10분이 끝나면 `TICK`이 같은 전환을 자동으로 수행하며 `break-finished` 안내는 표시하지 않습니다. 늦게 실행된 tick은 휴식 종료 경계를 계산하고 10분을 초과한 부분만 공부 경과에 반영합니다. 목표·대화 옵션·카메라·메시지·크레딧은 유지하며 새 세션 생성이나 추가 차감은 없습니다. 공부 화면으로 돌아올 때 채팅은 닫고 기존 대화 상대와 초안은 보존합니다. 목표 도달 여부와 관계없이 사용자가 `쉬는 시간`을 눌러야 휴식을 시작합니다. 목표를 채운 뒤에도 공부 시간을 계속 누적하며 타이머·집중률·종료 리포트에 반영합니다. 여러 번 쉬거나 새로고침해도 휴식 시간은 공부·집중 측정·리포트에 포함하지 않습니다. 종료 확인창은 현재까지의 실제 공부 누적 시간을 `시:분:초`로 표시하고 휴식 중에는 이 값을 고정합니다. 제목 `공부를 마치시겠습니까?`는 중앙 정렬하며 X 버튼과 저장/리포트 이동 안내 문구는 제거했습니다. 처음에는 `아니, 더 할거야` 버튼에 초점을 두며 Escape·바깥 클릭도 공부를 종료하지 않고 창만 닫습니다. 리포트의 비집중 시간 항목은 최신·구형 기록 모두 `자리 비움`으로 표시합니다.

캠 배경은 카메라가 켜져 있을 때만 선택할 수 있습니다. 선택창을 열거나 배경을 골라도 현재 아바타/실제 카메라 표시 모드를 유지하며, 실제 카메라로의 전환은 별도 보기 버튼으로만 실행합니다. 아바타 모드에서는 이미지 배경을 일러스트 뒤에 표시하고, 블러는 부드러운 장식용 배경을 표시합니다. 아바타 뒤에 실제 카메라 영상을 렌더링하지 않습니다. 실제 카메라 보기에서는 기존 로컬 MediaPipe의 블러·이미지 합성을 사용합니다. 카메라를 끄면 원형 아바타로 돌아가며 선택한 배경은 숨기되 설정은 유지합니다. 방 전체 배경이나 친구의 장면에는 적용하지 않습니다. 선택창의 중복 제목·안내·카메라 켜고 미리보기 버튼은 제거하고 접근성용 범례만 유지합니다. 팝오버에는 독과 같은 반투명 그라데이션·24px 흐림·140% 채도·안쪽 빛 반사를 적용하며, 글자 가독성을 위해 독보다 짙은 기본색을 사용합니다. 선택창에서는 독 확대 반응을 멈추고 작은 화면에서는 내부 스크롤을 사용합니다. 라디오 방향키 선택·Escape·외부 클릭 닫기를 지원합니다.

친구 이미지나 내 화면을 누르면 해당 화면을 크게 보고 다시 누르면 원래 배치로 복귀합니다. 나를 포함해 2명·3명·4명 모두 확대 시 한 화면이 영상 영역을 채우고, 나머지는 오른쪽 아래에서 독 위에 작은 썸네일로 표시합니다. 썸네일은 기존 가로·세로의 1.5배인 최대 180×120px이며 좁은 화면에서는 서로 겹치지 않도록 함께 줄어듭니다. 작은 친구 썸네일에는 이름만 표시합니다. 아바타·실제 카메라 모드 모두 내 화면 확대를 지원하며 `focus=self`로 구분합니다. 친구 확대에서 내 화면으로 전환하거나 그 반대도 가능합니다. 확대해도 카메라 스트림·보기 모드·배경 설정·채팅 상대는 바꾸지 않습니다. 모바일·태블릿에서는 확대된 화면이 고정 헤더 아래에 보이도록 스크롤 위치를 맞춥니다. V 단축키는 선택된 대화 상대를 확대하거나 현재 확대를 닫습니다. 대화 아이콘(C)은 친구를 한 번 더 누르는 단계 없이 공통 오른쪽 채팅 패널을 바로 열고 닫습니다. 대화 상대는 패널의 친구 탭에서 고르며 친구 이미지 클릭으로 상대가 바뀌지 않습니다. 대화 상대와 확대 영상은 독립적입니다. 친구별 초안은 상대 전환·패널 닫기 후에도 유지하고, 대화 이력과 선택한 상대는 새로고침 후 복원합니다. 조용히 집중을 켜면 대화창을 닫으며, 대화창을 다시 열면 조용히 집중을 해제합니다. 독의 aria-expanded·aria-pressed는 실제 채팅창 상태를 따릅니다.

휴식 중 내 캠/아바타 썸네일도 클릭·Enter·Space로 메인 영상 크기로 확대하고 다시 누르거나 Escape로 이전 친구 화면으로 돌아갑니다. 확대 중에는 모든 친구를 썸네일로 표시하며, 친구 썸네일을 누르면 해당 친구 화면과 기존 대화 흐름으로 복귀합니다. 내 화면을 확대해도 채팅 상대를 바꾸지 않고 기존 친구 선택을 보존합니다. 내 영상 요소는 같은 DOM에 유지하고 CSS 배치만 바꿔 카메라 재연결·권한 재요청 없이 확대/축소합니다. 아바타 표시 모드·선택 배경·마이크의 말하기 표시·휴식 타이머·채팅 초안도 유지합니다. 휴식이 끝나거나 공부를 일찍 재개하면 내 화면 확대 상태도 공부 화면으로 이어집니다.

`SessionChatPanel`은 공부·휴식에서 하나만 사용합니다. 넓은 화면은 영상 옆 사이드바, 1023px 이하는 오른쪽 모달 드로어로 열립니다. 드로어는 Escape·바깥 클릭으로 닫고, 배경 스크롤과 초점 이탈을 막으며 닫을 때 열었던 버튼으로 초점을 돌립니다. 이전 이력은 바로 표시하고 새 친구 답장만 `TypingMessage`로 출력합니다. 읽은 메시지를 다시 선택해도 효과를 반복하지 않습니다. 글자 출력 간격을 늘려 이전보다 조금 느리게 표시하며, 긴 문장은 길이에 따라 간격을 조정합니다. 말풍선 위에는 친구 이름·실제 전송 시각, 내 메시지 아래에는 전송 상태를 표시합니다. 기존 메시지에 없는 시각은 만들지 않습니다. 둥근 입력창은 입력할 때 확장되며 Enter 전송·Shift+Enter 줄바꿈·한글 조합 중 오전송 방지를 지원합니다. 무료 대화 한도와 옵션 변경·차액 결제는 기존 상태 로직을 사용합니다. 옵션 변경 창은 드로어 위치와 무관하게 화면 전체 중앙에 열리며, 부족 안내도 중앙 정렬합니다.

타이머의 `AnimatedClock`은 바뀐 숫자만 위·아래로 움직이고 흐림을 더합니다. 공부 경과 시간은 위로, 휴식의 남은 시간은 아래로 전환하며 구분자·고정 목표는 움직이지 않습니다. 움직임 줄이기 설정에서는 패널·타이핑·숫자 전환을 즉시 반영합니다. 참고 화면은 [SmoothUI Sidebar](https://smoothui.dev/docs/primitives/sidebar), [Kokonut Typing Text](https://kokonutui.com/docs/texts/type-writer), [unlumen Animate Digits](https://ui.unlumen.com/components/animate-digits), [AI Chat Input](https://cdn.21st.dev/easemize/ai-chat-input/default/bundle.1783271974589.html), [Message With Header And Delivery Status](https://21st.dev/@sean0205/components/c-message-3)입니다. 디자인·동작을 참고해 프로젝트의 React·CSS·native dialog로 구현했습니다.

말하는 사람은 Discord처럼 프레임 안쪽의 초록색 2px 선으로 표시합니다. 채팅의 `TypingMessage` 시작/완료/정리 이벤트를 메시지 ID별로 집계해 해당 친구만 표시하고, 단순 선택 상태의 보라색 테두리는 제거했습니다. 동시에 출력되는 메시지 하나가 끝나도 나머지 메시지의 표시는 유지합니다. 대기 중인 LLM 응답은 표시하지 않고 실제 답장이 도착해 출력될 때 표시합니다. 출력 완료 후 240ms 뒤 해제하며, 움직임 줄이기에서는 완성 문장을 바로 보여 주고 선만 800ms 유지합니다. 닫기·상대 전환으로 출력이 취소되면 즉시 해제하고, 읽은 이력은 다시 표시하지 않습니다. 내 메시지 전송 후에는 내 프레임도 잠깐 표시합니다. 공부·확대·휴식의 큰 프레임과 작은 썸네일 모두 같은 상태 스타일을 사용합니다.

내 음성 표시는 `useMicrophoneActivity`가 이미 허용된 마이크 스트림만 분석합니다. Web Audio의 RMS 입력 크기를 50ms 간격으로 확인하고 시작 0.025·유지 0.015·해제 지연 300ms로 음절 사이의 깜빡임을 줄입니다. 마이크를 켠 무음 상태는 표시하지 않으며 끄기·연결 해제·탭 숨김에는 해제합니다. 장치 권한을 추가 요청하거나 녹음·재생·서버 전송하지 않고, 스트림 교체·화면 종료 때 분석 노드와 AudioContext를 해제합니다. 입력 크기 감지는 음성 인식이나 사람 목소리 판별이 아닙니다. 현재 친구의 실제 음성 재생은 연결되어 있지 않으며, 향후 재생 이벤트도 같은 말하기 상태에 연결해야 합니다. 채팅창의 샘플 음성 메시지는 기존 체험 동작을 유지합니다.

V/C는 키보드의 물리 위치(`KeyV`·`KeyC`)를 기준으로 한글·영문 배열에서 같은 기능을 실행합니다. 입력 필드·편집 영역의 글쓰기·조합 중 입력에서는 실행하지 않습니다. C는 모바일 채팅 드로어에서도 편집 중이 아니면 닫기를 지원합니다. 옵션 변경 등 다른 모달이 떠 있으면 단축키를 차단하며, V는 공부 중 모달이 없을 때만 실행합니다. 키를 누르고 있을 때의 반복 이벤트는 무시합니다. Escape는 대화창, 확대 화면 순서로 닫으며 독에 초점이 있을 때는 설명 툴팁을 닫습니다. 채팅 열기/닫기와 레이아웃 변경은 크레딧을 사용하지 않고 기존 메시지 차감·한도 규칙을 따릅니다.

시각적 참고는 [UI Beats Dock](https://uibeats.com/docs/component/dock)의 포인터 접근 확대와 [Animate UI Lucide Icons](https://animate-ui.com/docs/icons/lucide-icons)의 아이콘 모션입니다. 기존 `Icon`과 CSS로 구현했으며 관련 패키지나 예제 코드를 가져오지 않았습니다.

시작 화면에서 슬라이더로 **5~180분, 5분 단위**의 목표를 정합니다. 기본값은 50분입니다. 범위와 기본값은 `features/session/study-goal.ts`, 슬라이더는 `StudyGoalPicker.tsx`에서 관리합니다.

`START.targetMinutes`를 검증해 `activeSession.targetSeconds`에 저장하고, 타이머는 경과 0초부터 시작합니다. 재접속 시 같은 목표를 복원합니다. 현재 MVP 시작은 항상 3분 목표를 저장합니다. 목표에 도달해도 자동 전환하지 않으며 경과 시간을 계속 표시합니다. 쉬는 시간 버튼을 눌렀을 때만 10분 휴식으로 전환합니다. 휴식이 끝나면 같은 목표와 공부 누적 시간을 유지하며 자동으로 재개하고, 독의 `공부 이어가기`로 일찍 복귀할 수도 있습니다. 새 목표를 임의로 만들지 않습니다.

종료 시 실제 공부 시간과 목표 시간을 각각 `StudyRecord.studySeconds`, `targetSeconds`에 저장합니다. 중도 종료는 실제 경과만 기록하고, 목표 직후 타이머 tick 전에 종료하더라도 목표 달성으로 판정합니다. 리포트와 최근 기록에서 목표를 볼 수 있습니다. 예전 기록에는 알 수 없는 목표를 새로 지어 넣지 않고, 예전 진행 중 세션은 50분을 호환 기본값으로 사용합니다.

준비 화면은 단일 목표·대화 옵션 설정입니다. 기존 `?step=goal`·`?step=set` 등 단계가 붙은 링크도 같은 화면을 표시하며 목표·옵션 전달은 유지합니다. 충전 후 돌아오거나 최근 공부를 다시 시작할 때도 설정값을 복원합니다. 요금은 기존 데모 옵션을 유지하며 시간 비례 요금 등 새 가격 정책은 추가하지 않았습니다. 실제 결제는 연결하지 않았습니다.

목표 설정 화면의 돌아가기는 공통 `OverlayPage`의 내용 창 안쪽 왼쪽 위에 배치하며 룸 상세로 돌아갑니다. 제목은 `목표 시간을 정해요`입니다. 룸 제목·친구 초상화와 이름은 `OverlayPage.headerAside`로 같은 상단 행의 오른쪽에 모읍니다. `headerClassName="mb-0"`으로 상단 행의 아래 여백을 없애며 다른 오버레이의 간격은 유지합니다.

목표 설정에서는 대화 옵션 다음에 목표 시간 슬라이더를 배치하고, 보유 크레딧과 유효한 패스 이름 또는 `없음`을 표시합니다. 만료된 패스는 이용 중으로 표시하지 않습니다. 단계 배지는 없으며 시작 버튼은 `시작하기`입니다. 실제 크레딧 차감과 패스 혜택은 기존 계산을 사용합니다.

카메라·마이크 확인 화면은 제거했습니다. 장치 권한은 공부 화면 독의 카메라·마이크 버튼을 누를 때 각각 요청합니다. 설정 화면 진입·시작 버튼·다음 세션 진입은 이전 장치 사용 여부와 무관하게 권한을 자동 요청하지 않습니다. 거부해도 공부는 계속할 수 있고 독에서 다시 요청할 수 있습니다. 준비 전용 `DeviceCheck`·`CameraPreview`·`DeviceCheckItem`·`DeviceCheckStatus`·`MicrophoneMeter`와 전용 CSS를 제거했습니다.

공부 헤더의 물음표는 카메라의 얼굴 감지·집중 시간 측정과 장치별 켜기/끄기, 영상·소리의 로컬 처리·서버 미전송 안내를 담습니다. 호버·키보드 초점·터치로 열며 Escape·외부 클릭·초점 이탈로 닫습니다. 공부·휴식은 아바타를 기본 표시하고 독에서 실제 카메라 미리보기로 전환합니다. 카메라가 꺼져 있으면 헤더의 공통 `Avatar`와 같은 원형 얼굴 구도를 쓰고, 카메라를 켠 아바타 모드에서는 원 없는 기존 일러스트를 표시합니다. 아바타로 바꿔도 켜 둔 카메라와 공부 중 숨김 영상의 얼굴 감지는 유지하며, 카메라 자체를 끄면 원형 아바타로 복원합니다.

목표 설정은 대화 옵션 위에 `일정` 제목과 `+ 일정 추가`를 항상 표시합니다. 기존 시험 일정이나 이전 답변 여부로 숨기지 않으며, 저장한 뒤에도 새 일정을 계속 추가할 수 있습니다. 준비 화면에서 `MemoryEditor` 팝업을 열어 종류·이름·날짜·시간을 입력합니다. 저장·취소·닫기·외부 클릭·Escape에도 목표 시간과 대화 옵션을 유지합니다. 팝업은 공통 모달의 배경 스크롤 잠금을 사용합니다. 일정은 같은 공통 목록에 저장해 모든 친구와 계정 설정의 일정 탭에서 공유합니다.

홈의 최근 공부 이어하기·룸 상세·친구 화면에서 새 공부를 시작하면 목표 설정으로 바로 진입합니다. 진행 중인 세션이 있으면 해당 공부 화면으로 이어 가며, 휴식 후 재개도 같은 세션 안에서 처리합니다. 카메라·마이크 스트림은 활성 공부 화면에서만 유지하고 종료·다른 페이지 이동 시 해제합니다.

크레딧 부족 안내는 시작 버튼 아래에서 가운데 정렬합니다. 안내의 충전 링크는 선택한 목표·옵션으로 돌아오는 경로를 유지하며, 별도의 `크레딧 · 패스 보기` 링크는 표시하지 않습니다.

최신 작업은 단위 테스트 33개, 격리된 Chromium 브라우저 검사 39개, ESLint 및 프로덕션 빌드가 통과했습니다. 브라우저에서는 주·월·년의 요약·달력 통합, 날짜 선택과 상단 상세 연결, 기간 집중률 유지, 오른쪽 집중률·최근 스터디 순서, 하단 전체 너비 차트, 기간 밖 선택의 오늘 표시, 스터디룸 필터와 320~1440px 배치를 확인했습니다.

최신 검증 결과는 [`src/features/reports/overview-validation.json`](../src/features/reports/overview-validation.json)에 저장했습니다. 기존 `summary-validation.json`, `line-chart-validation.json`, `refinement-validation.json`, `validation.json`은 이전 작업 당시의 결과입니다. 실제 모바일 기기와 다른 브라우저 엔진은 이번 검사에 포함하지 않았습니다.
