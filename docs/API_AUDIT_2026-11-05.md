## 최신 명세와 반영한 변경

직전 스냅샷과 의미 단위로 전체 비교한 결과 **`RoomDetail.bannerUrl` 선택 string 추가 한 곳**만 바뀌었다. 신규 API·경로·요청 필드 변경은 없다. [원본 스냅샷](BACKEND_OPENAPI_2026-11-05.json)·[API 사전](BACKEND_API.md)·[연동 기록](API_INTEGRATION_2026-11-05.md)을 갱신했다.

`RoomDetail.bannerUrl` → `StudyRoom.bannerUrl` → 상세 배너 이미지로 연결했다. 서버 배너가 있으면 우선 사용하고, 기존 명세처럼 값이 없으면 이전 이미지 표시를 유지한다. 목록 thumbnail과 상세 banner는 별도다. 브라우저에서 서버 배너의 실제 이미지 로드(2167×726)를 확인했다.

화면 검증에서 서버가 제공한 숫자 ID의 캐릭터가 공부 준비 화면에서 “MVP 이후”로 가려지는 문제도 확인했다. 서버 캐릭터를 이용 가능하게 표시하고 준비/홈의 작은 아바타에 실제 profileImageUrl을 사용하도록 수정했다. 신규 Live2D 런타임을 추가한 것은 아니다.

### 명세와 실제 응답의 차이

| API | Swagger | 실제 서버 | 프런트 처리 |
|---|---|---|---|
| 상태 이벤트 저장 | 200 | **201** | 공통 client의 2xx 처리로 정상 |
| 로그아웃 | 200 | **204, 빈 본문** | JSON 파싱을 강제하지 않아 정상 |

원본 OpenAPI에 서버와 다른 성공 상태를 임의로 덮어쓰지 않았다. 백엔드에서 Swagger를 실제 상태에 맞추면 문서와 자동 생성 클라이언트의 혼선을 줄일 수 있다.

## 실제 브라우저 확인

- 이메일 로그인 200 후 홈·실제 룸/캐릭터/일정이 표시됐다. 새 상세 배너는 실제 원격 이미지로 로드됐다.
- UI로 세션 7을 3분 목표로 생성해 201, 첫 FOCUS 이벤트 201, 인사 반응 200을 수신했다. QUICK 메시지도 실제 200이었다.
- 실제 1분 경과 후 heartbeat는 `{studySeconds:60,presentSeconds:60}` → 204였다.
- 서버 캐릭터의 준비 화면 MVP 가림은 0개이며, 실제 서버 아바타 이미지 로드도 확인했다.
- F5 후 refresh 200과 사용자/홈/일정/아바타/룸 조회 200으로 인증을 복구했다. 같은 세션의 resume 200 후 1분 타이머부터 복구됐고 FOCUS 중복 저장은 없었다.
- 휴식 진입 BREAK 201과 반응 200, 휴식 중 누적 `{studySeconds:71,presentSeconds:71}`의 heartbeat 204를 확인했다. 이후 재복구·종료 200과 서버 완료 대사·정산이 리포트에 표시됐다.
- 리포트를 F5로 다시 조회해 200과 완료 화면을 확인했고, UI 로그아웃 204 후 F5해도 로그인 화면으로 남았다.
- 익명 상태·로그아웃 후 refresh의 예상된 401 리소스 로그 외에 브라우저 JavaScript 예외는 없었다. 개발 서버가 파일 변경으로 재로딩된 구간은 실제 이어하기로 복구했으며, 장시간 운영 검증으로 간주하지 않는다.

## 실계정 검증 조건과 남은 항목

- 프로필 PATCH는 기존 닉네임·현재 아바타 값을 유지해 전송했다. 새 아바타로 바꾸는 온보딩 전체 절차를 실계정으로 반복한 것은 아니다.
- 정상 가입 검증이 남은 API: 2번 인증 메일 요청, 3번 유효 코드 확인, 4번 신규 가입. 이미 가입한 계정의 로그인 성공을 신규 가입 성공으로 간주하지 않는다.
- 6번 카카오는 빈 입력의 SOCIAL_AUTH_FAILED만 확인했다. 실제 사용자 인가·callback 교환은 별도 확인이 필요하다.
- 26번 비밀번호 재설정은 잘못된 입력의 INVALID_PASSWORD만 확인했다. 25번 요청·메일 도착 성공과 실제 비밀번호 변경 성공을 구분한다.
- DROWSY/YAWN/WAVE/HEAD_TURN은 새로운 사전 대사·호감도 정책의 배포 확인 대기 상태다. 이번 OpenAPI에서도 EventRequest.type은 enum 없는 string이며 reaction 설명은 LLM으로 유지된다. [정책 검토](STATE_AND_INSTANT_ACTION_REVIEW_2026-11-05.md) 참고.
- 다른 브라우저 이어하기의 presentSeconds 누락, 리포트의 목표 시간 누락, 일정 수정·삭제/대화 이력 조회 API 미제공은 그대로다.
- 서버 에셋 매핑 확인 필요: 말포이/밤의 호그와트 도서관 레코드가 현재 `profileImageUrl: .../characters/kang-study.webp`, `bannerUrl: .../room-detail-banners/night-detail-banner-v1.webp`를 반환한다. 파일은 정상 로드되지만 신규 말포이 전달본 이미지와의 연결은 백엔드 데이터에서 확인해야 한다. 프런트는 서버 URL을 그대로 표시한다.
- 테스트 목표 일정 `API 연결 확인 · 2026-11-05` 1건을 실제 저장했다. 삭제 API가 없어 계정에 남는다. 테스트용 공부 세션 5·7은 모두 종료했다. 공부 기록·서버의 관계 정산은 실제 데이터에 반영된다.
