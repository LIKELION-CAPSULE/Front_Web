### 「사용법 보기」 서비스 투어 (2026-11-25)

하단 푸터의 「사용법 보기」(2026-11-25 홈 개편 병합 뒤, 어느 화면에서든)는 **서비스 전체를 한 번에 도는 투어**를 엽니다. 「채린」 커서 하나가 실제 화면 위에서 기능을 짚고, 투어 컨트롤러가 화면을 옮깁니다: 홈 → 메이트 상세(첫 메이트) → **연습 통화** → 내 메이트 → 내 기록 → 계정 설정(모달) → 마무리. 2026-11-26 사용자 결정으로 29단계를 **11단계**로 줄였습니다(홈 2, 메이트 상세 1, 연습 통화 3, 내 메이트 2, 내 기록 1, 계정 1, 마무리 1). 한 단계가 여러 곳(마크)을 차례로 짚습니다. 챕터 선택은 없고, 언제든 그만볼 수 있으며, 자동으로 뜨지 않습니다. 예전 `/?tutorial=1` 주소는 투어 첫 단계로 바꿔 엽니다.

- 코드: `src/features/tour/` — `tour-steps.ts`(단계·마크 정의·화면 주소, 의존성 없음), `ServiceTour.tsx`(컨트롤러, 지연 청크), `tour-motion.ts`(커서 경로·속도·밝은 영역 스프링 수치, 의존성 없음), `tour-spotlight.ts`(밝은 영역: 가림막·모서리 조각을 transform으로만 움직임), `TourLayer.tsx`(잠금·top layer, 메인 번들), `TourLayout.tsx`(`TourLayout`은 투어 화면 표시, `TourOverlay`는 `?tour=`가 있으면 즉시 잠그고 컨트롤러 청크를 불러 화면 위에 띄움 — App의 라우트 Suspense 바깥), `tour-placement.ts`(채린 말풍선 위치), `TourCallPage.tsx`(연습 통화), `tour-start.ts`, `tour-layer.css`·`service-tour.css`. 라우트는 `src/app/App.tsx`의 `TourLayout` 아래에 있습니다.
- 잠금은 `TourLayer` 한 곳이 소유합니다. `?tour=`가 주소에 생기는 첫 프레임부터 앱을 `inert`로 막고 스크롤을 잠그며, 컨트롤러 청크를 받는 동안에는 「사용법 불러오는 중 · 그만보기」 패널을 띄웁니다(Esc도 됨). 그래서 로딩 중에도 실제 「연결하기」(`connectMate`)나 카드가 눌리지 않습니다. 해제는 투어가 끝나거나 주소에서 `tour`가 빠져 언마운트될 때 한 번만 하고, 다른 곳이 포커스를 가져가지 않았으면 원래 포커스로 돌려줍니다.
- 메이트가 없으면(서버가 메이트를 주지 않음) 「사용법 보기」가 비활성입니다. 투어 주소로 직접 들어오면 「메이트를 불러오지 못해서 사용법을 보여 줄 수 없어요 · 닫기」만 보이고 기다리거나 이동하지 않습니다.
- 커서: ReactDrops Showcase Pointer(`src/shared/ui/showcase-pointer/`, 라이선스는 [상업 이용 기록](REFERENCE_COMMERCIAL_USE.md)). 이름표 「채린」, 로고 보라 `#8053F2`, 이름표 안에 채린 아바타. 투어 지연 청크에서만 불러옵니다(gsap 포함).
- 주소: 단계는 `?tour=<단계 id>`로 주소에 남습니다. 새로고침하면 같은 단계에서 이어집니다. 모르는 단계 id는 처음부터 시작합니다.
- 화면 이동: 같은 화면 안의 단계는 대사를 읽을 시간이 지나면 스스로 넘어갑니다. **화면을 옮기는 것은 사용자가 「다음 · 〈다음 화면〉」/「이전」/「이 화면 건너뛰기」를 누를 때뿐**이고, 컨트롤러가 `navigate(replace)`로 옮깁니다. 커서의 누름은 이동하지 않습니다.
- 마크와 밝은 영역: 한 단계는 마크 여러 개(대상 선택자·짚는 위치·동작·누름 미리보기)를 차례로 짚습니다. 마크들을 합친 영역이 화면의 30% 이하이면 한 영역으로 밝히고 커서만 그 안을 옮겨 다니며, 더 넓으면 밝은 영역이 커서와 함께 마크마다 옮겨 갑니다. **밝은 영역과 커서는 같은 프레임에 함께 출발**합니다.
- 움직임(2026-11-26 사용자 결정 「좀 더 자연스럽게」, `tour-motion.ts`): 커서는 화면 가운데 쪽으로 살짝 휘는 3차 베지어 곡선으로 움직이고(휘는 폭 = 거리 × 0.12, 최대 110px), 속도는 minimum-jerk(출발 가속·도착 감속)입니다. 이동 시간은 거리에 따라 300~800ms(`260 + 110·log2(1 + 거리/40)`)입니다. 가리키기만 하는 마크는 멈추지 않고 평균 속도의 0.45배로 지나가며 다음 이동이 같은 속도·방향으로 이어지고, 누르기·입력·마지막 마크·되돌아가는 급한 꺾임에서만 멈춥니다. 누른 뒤에는 220ms만 쉽니다. 밝은 영역은 motion `spring`(visualDuration = 이동 시간 × 0.2, bounce 0.1)으로 커서의 진행을 쫓아가서, 커서 도착 때 3~4px 뒤에 있다가 17~50ms 안에 1px 이내로 맞춰지고 넘치지 않습니다. 대상이 화면 밖이면 스크롤과 커서 이동이 동시에 시작합니다: 스크롤이 끝난 뒤의 위치를 먼저 재서 그쪽으로 출발하고, 끝부분은 지금 대상 위치로 휘어 들어가며, 스크롤이 더 길면 커서가 대상에 붙어 함께 움직입니다(스크롤 때만 다시 잼). 채린 말풍선은 커서가 첫 마크에 닿을 때 opacity와 5px 떠오름으로 나타나고, 단계가 바뀌면 140ms에 사라집니다. 쉬는 커서는 1~2px로 느리게 흔들립니다(움직임 줄이기에서는 없음). 커서는 단계 사이에도 그대로 남아 이어서 움직입니다. 투어(`TourOverlay`)는 `App.tsx`의 주소별 라우트 Suspense 바깥에 있어서 화면이 바뀌어도 사라지지 않습니다(예전에는 주소가 바뀔 때마다 약 300ms 사라졌음). 다음 화면이 불러와지는 동안 커서와 밝은 영역은 제자리에 있다가 첫 마크가 나타나면 이어서 움직입니다. 투어는 `TourLayout` 화면(로그인한 사용자의 화면)에서만 시작하고, 주소에 `tour`가 있는 동안 유지됩니다. 계정 모달이 열리고 닫힐 때만 레이어가 다시 마운트되며, 이때도 커서는 마지막 자리에서 이어집니다.
- 움직임 비용: 밝은 영역은 가림막 4장(위·아래는 translate, 좌·우는 translate+scaleY)과 18px 모서리 조각 4개를 정수 픽셀 transform으로만 움직여 매 프레임 다시 그리지 않습니다. 보라 테두리·글로우는 크기가 바뀔 때 한 번만 그리고, 이동 중에는 숨겼다가 도착하면 보입니다(opacity). 매 프레임 측정하는 루프는 없습니다: 스크롤·크기 변경·`ResizeObserver` 신호에만 다시 재고, 대상 기다리기는 `MutationObserver`(+ 들어오는 애니메이션이 끝날 때까지), 모달 열림·닫힘은 `MutationObserver`로 압니다.
- 대기·건너뜀: 화면에 들어간 뒤 단계의 첫 마크(`data-tour`)가 나타날 때까지 기다립니다(기본 4초, 지연 로드 화면·내 메이트 캡슐 붓기·내 기록 보드는 6~9초). 나머지 마크는 그때 화면에 있는 것만 짚습니다. 시간 안에 없으면 진행 방향(다음/이전)으로 그 단계를 건너뜁니다. 진행 방향은 history state(`tourWay`)로 화면 사이에서도 유지됩니다.
- 기능 플래그: 친밀도·표정 마크는 `resolveMateFeatures`가 꺼져 있으면(운영 기본) 빠지고, 그 단계는 기능 이름이 없는 대체 대사(`sayWithout`)를 말합니다. 단계 수는 운영·개발 모두 11입니다.
- 계정 설정: 컨트롤러가 `?account=profile`로 모달을 열고(한 단계에서 프로필·설정·보안 탭을 함께 밝히고 차례로 짚음), 끝나거나 건너뛰면 주소에서 지워 닫습니다. 투어가 연 모달은 배경 클릭·Esc로 닫히지 않습니다(`AccountSettingsDialog`의 `locked`). 그 밖의 경로로 모달이 닫히면 `closeAccountRequest`가 `tour`도 함께 지워 투어가 끝납니다(모달을 다시 여는 일이 없음). 모달은 네이티브 `<dialog>`(top layer)라서, 투어 레이어는 `popover="manual"` 요소로 만들고 모달이 열려 있으면 그 안으로 옮겨 모달 위에 보이게 합니다. 이때는 `#root` 대신 모달 내용(`.account-settings-window`)을 `inert`로 막습니다. 탭은 전환하지 않고 탭 버튼만 짚습니다.
- 누름은 보여 주기용입니다. `onCursorPress`는 로컬 미리보기 칩(채린 말풍선 바로 아래)만 띄우고 `onCycle`에서 지웁니다. 클릭·포인터·마우스 누름 이벤트를 보내지 않고, 이동·연결·재생·제출을 실행하지 않습니다. 연습 통화의 채팅 입력에는 커서가 글자를 입력하지만(네이티브 setter + `input`), 보내기는 하지 않습니다.
- 진행 중에는 앱을 `inert`로 막고 스크롤을 잠급니다. 흐림·커서 레이어는 포인터를 통과시키고, 투어 패널만 조작할 수 있습니다. 컨트롤러가 대상을 화면 안으로 부드럽게 스크롤합니다(움직임 줄이기에서는 즉시).
- 패널: 「캡슐 사용법 n / N」 + 화면 이름 칩, 「그만보기」(Esc), 「이 화면 건너뛰기」(그 화면에 단계가 더 남았을 때: 다음 화면의 첫 단계로), 「이전」, 「다음」. 화면이 바뀌는 「다음」은 「다음 · 내 메이트」처럼 다음 화면을 함께 적습니다. 연습 통화에서는 아래쪽 도크·채팅 입력을 가리지 않게 패널이 위로 올라갑니다.
- 그만보기: 투어를 연 화면(sessionStorage `capsule-tour-origin`, 없으면 홈)으로 돌아가고 「사용법 보기」에 포커스를 돌려줍니다. 계정 모달에서 그만보면 모달도 닫힙니다.
- 마무리: 「이제 만나러 가 볼까?」 + 「메이트 만나러 가기」(홈 메이트 목록으로 스크롤·포커스) / 「다시 보기」(첫 단계부터).
- 검사: `scripts/check-service-tour.mjs`(로컬 목 모드 개발 서버 + Playwright)가 실제 브라우저에서 투어 전체(일반·움직임 줄이기)를 돌며 합성 click·pointer·mouse·submit 이벤트, 앱 API 호출(쓰기, 세션·연결·이벤트·리액션·메시지·크레딧), `getUserMedia`·PIP를 감시해 0건인지 확인합니다. 느린 청크 로딩, 잘못된 `?tour`, 빈 메이트 목록, 로그아웃 상태, 계정 모달(세 탭을 한 단계에서 밝히고 짚음 → 마무리, 배경 클릭 포함), 「이 화면 건너뛰기」(다음 화면 첫 단계, 마크 여러 개, 밝은 영역과 커서가 같은 프레임에 출발), 그만보기·Esc·주소 이탈 뒤 inert·overflow·포커스 복귀, 단계마다 말풍선이 컨트롤을 가리지 않는지도 봅니다.
- 접근성: 단계마다 `aria-live`로 「n/N, 화면. 채린: …」을 알립니다. 패널의 「다음」(마무리에서는 「메이트 만나러 가기」)에 포커스가 갑니다.

  - 날짜 선택: `selectCapsuleDay`가 그날과 그날의 기록을 넘깁니다. 기록이 있는 날을 누르면 내 메이트의 캡슐과 같은 기록 카드(`CapsuleRecordCard`, 네이티브 모달, 수집형 카드 — `MY_MATES_CAPSULE_SCENE.md`의 「기록 카드」)가 열리고, 그날 연결이 여럿이면 카드 안에서 이전·다음으로 넘깁니다. 「연결 기록 보기」는 `/connections/:id`로 갑니다.
  - 좁은 화면: 년 잔디는 가로 스크롤하며, 선택한 날(기본은 오늘)이 보이게 시작합니다.
- **채린 코멘트**: 요약 카드 위에서 선택한 기간과 메이트의 사실만으로 말합니다. 생성 함수는 [mate-comment.ts](../src/features/records/mate-comment.ts)입니다. 밤과 새벽이 섞이면 「늦은 시간」이라고 말하고, 한 시간대만 말할 때는 그 시간대의 실제 횟수를 씁니다.

### 2026-11-25 내 메이트 기준으로 정리

- **유리 블록**: 기간 탭 묶음, 이동 버튼, 메이트 칩, 요약 카드, 달력, 그래프, 최근 연결, 빈 상태가 모두 홈 말풍선 재질을 씁니다(`panel` 68% → `canvas` 62%, 18px 흐림, 140% 채도, 외곽선 없음, 흐림 미지원 시 불투명 `panel`). 채린 코멘트 말풍선은 원래 같은 재질입니다.
- **블록 언어**: 내 메이트 「함께한 시간」 열과 같습니다. 여백 16px 20px, 모서리 18px, 제목은 작은 아이콘 + 13px 굵은 `muted` 글자(`records-block-title`). 블록 안에는 상자를 겹치지 않고 얇은 구분선과 간격으로 나눕니다(선택한 날 요약, 기록 행).

- **캡슐 시간대 색**: 연결 시작 시각의 시간대(`timeBand`)를 따릅니다. 색은 브랜드 캡슐(채린 테마 `tintHalfShade`)을 내 메이트 캡슐과 같은 이동값(`capsuleBandTheme`)으로 옮긴 값입니다(`capsuleBandFill`, 새벽은 푸르게, 저녁은 분홍 쪽, 밤은 진하게). 메이트와 관계없이 한 팔레트를 씁니다.
  - 여러 시간대가 섞인 날은 **가장 오래 함께한 시간대** 하나를 씁니다. 같으면 먼저 시작한 연결의 시간대입니다. 2톤은 쓰지 않습니다(연 보기 캡슐이 13×7px라 두 색을 구분하기 어렵습니다).
  - 툴팁에 시간대를 적습니다(「저녁」, 섞이면 「주로 저녁」). 범례에는 시간대 색을 따로 싣지 않습니다. 한 보라 안의 작은 차이라 범례가 길어지기만 해서입니다.
  - 그래프의 날짜 막대도 그날 캡슐과 같은 색입니다. 달 막대(연 보기)와 범례 점은 기준 보라입니다. 카메라 시간은 막대 안쪽의 가는 흰 막대로 남깁니다.
- **기념 캡슐**: 함께한 시간이 이정표(1·3·5·10·20·30·50·100시간, `capsule-moments.ts`)를 넘긴 연결이 있는 날은 캡슐 끝에 작은 흰 별을 답니다. 메이트마다 전체 기록으로 셉니다(내 메이트와 같은 `capsuleKeepsakes`). 툴팁과 선택한 날 요약에 「함께한 지 n시간」이 나오고, 그런 날이 보이는 기간에만 범례에 「기념」이 붙습니다. 별은 캡슐이 차오른 뒤 나타나며, 움직임 줄이기에서는 바로 보입니다.
- **요약 카드**: 주 지표(함께한 시간)는 30px, 나머지는 24px이고 카메라 시간은 13px 보조 줄입니다. 960px 미만에서 카드가 3개면 주 지표가 첫 줄 전체를 씁니다.

  - 이제 무대의 높이÷너비(`--board-ratio`, `@property` 등록)가 기간 모핑과 같은 0.85초(`BOARD_MORPH_MS`), 같은 ease-in-out으로 전환됩니다.

  - 비율은 위 높이 제한(`boardStageCap`)을 이미 반영한 값이라, 제한에 먼저 닿아 앞부분에서만 움직이는 일이 없습니다.
  - 같은 비율을 쓰는 방안((a))은 2D의 주 3.4와 월 1.3 차이를 없앨 수 없어 택하지 않았습니다.
  - 연 보기에는 선택한 날 요약이 없어서, 그 줄도 같은 0.85초로 접혔다 펼쳐집니다(`records-day-detail-slot`, 연에서는 `inert`).
  - 움직임 줄이기에서는 바로 바뀝니다. `@property`를 지원하지 않는 브라우저도 바로 바뀝니다.
- 키보드·스크린리더 목록은 보드 위쪽 끝에 두었습니다(시각적으로 숨김). 방향키 이동은 `focus({ preventScroll: true })`라 페이지가 튀지 않고, 포커스 링은 보드 무대에 보입니다.

### 2026-11-25 주·월 2.5D 「유리 기둥」 (확정)

2.5D 보드에서 세워 꽂은 알약이 「모은 캡슐」로도 「막대그래프」로도 읽히지 않는다는 평가에 따라 「유리 기둥」·「엇갈려 쌓기」 비교 시안을 만들었고, **유리 기둥으로 확정**했습니다(사용자 결정, 2026-11-25). 날짜마다 투명한 유리 기둥을 세우고 그 안에 캡슐을 눕혀 채웁니다. 기둥 높이로 양을 비교합니다. 비교용 DEV 스위치(`?pillars=`)와 엇갈려 쌓기 시안은 지웠습니다.

- **적용 범위**: 주·월의 2.5D. 2D(누운 칩)는 그대로입니다. 연 보기는 2D가 기본이고, 연 2.5D는 기존 세운 기둥을 그대로 씁니다(365개 기둥은 점 무늬처럼 보여 높이 비교가 안 되고, 열두 달 보드는 위에서 볼 때 가장 잘 읽힙니다).
- **모듈**: `capsule-board-pillars.ts`(규칙, 테스트 `tests/capsule-board-pillars.test.ts`), 장면은 `capsule-board-scene.ts`, 「가장 긴 날」 칩은 `CapsuleBoard.tsx`.
- **높이 규칙**: 기간에서 가장 긴 날을 **정시 단위로 올림(최소 2시간)**한 값이 기둥 최대 높이(주 2.1, 월 1.25 타일)입니다. 각 날은 정확한 시간에 비례합니다. 올림을 하면 가장 긴 날이 늘 같은 높이에 닿지 않고 눈금이 정시에 떨어지며, 2시간 하한 덕에 30분뿐인 주가 가득 찬 것처럼 보이지 않습니다.
- **캡슐 표현**: 캡슐 1개 = 30분을 유지합니다. 캡슐은 기둥 안을 가로질러 눕고 높이를 고르게 나눠 아래부터 쌓입니다. 30분 한 칸이 누운 캡슐보다 높으면 모두 같은 방향으로 최대 34°까지 기울이고 하나씩 조금씩 돌려 나선처럼 정돈해 빈틈을 줄입니다. 한 칸이 너무 얇아 캡슐이 0.17타일보다 작아지면 「채워진 빛 + 맨 위 캡슐 3개(+기념 캡슐)」로 단순화합니다. 기둥 안의 빛은 연결(「전체」는 메이트별, 메이트 하나는 시간대별) 층으로 나뉩니다. 윗면에는 밝은 링을 둬 높이 끝이 또렷합니다.
- **주 보기**: 보드 뒤쪽 벽에 정시 눈금선 2~3개와 「n시간」 라벨, 그리고 「가장 긴 날」 칩.
- **월 보기**: 「가장 긴 날」 칩만 둡니다. 기둥별 눈금 링은 복잡해 보여 쓰지 않습니다. 가림 완화로 기둥을 더 가늘게(반지름 0.22 → 0.19) 하고 더 낮게(1.25) 하며, 카메라를 4° 더 내려다보게 합니다. 유리·빛이 모두 가산 혼합이라 앞줄이 뒷줄을 덮어 가리지 않습니다.
- **가장 긴 날**: 기둥 위에 「가장 긴 날」 칩(코멘트 강조와 같은 보라)을 붙이고 윗면 링을 더 밝게 합니다. 그 날에 마우스를 올리면 칩 대신 기존 툴팁이 나오고, 2D로 바꾸면 칩이 사라집니다. 기간 모핑 중에는 칩을 숨겼다가 기둥이 자리를 잡으면 다시 띄웁니다.
- **기간 모핑**(0.85초): 주↔월, 기간 이동 때 같은 날의 기둥은 이전 기간의 높이·굵기에서 새 기간의 높이·굵기로, 그 안 캡슐도 위치·크기·기울기를 함께 바꾸며 자연스럽게 이어집니다(`mixPillar`). 단순화 여부가 바뀌어 한쪽에서만 보이는 캡슐은 커지거나 작아지며 나타나고 사라집니다. 새로 생긴 날은 그 자리에서 자라고 빠지는 날은 이전 모양대로 줄어듭니다. 주 눈금선은 주로 들어갈 때 서서히 나타나고 주에서 나갈 때 서서히 사라집니다. 모핑 도중 다시 기간을 바꾸면 날짜 위치와 마찬가지로 기둥 높이·굵기·캡슐과 눈금선 세기도 화면에 보이던 중간 상태에서 이어집니다(`pillarFormAt`, `planGuides`). 직전 목표 모양으로 순간 이동하지 않습니다.
- **유지**: 2D/2.5D 전환(기둥이 바닥으로 가라앉으며 캡슐이 칩으로 눕습니다), 날짜 클릭으로 기록 카드 열기, 키보드, 움직임 줄이기(등장 없이 바로), WebGL 없음 대체, 코멘트 강조(요일·연속·가장 긴 날의 기둥·빛이 함께 밝아짐), 첫 등장 순서(새틴 리본보다 먼저 기둥이 섬).
- **성능**(2026-11-25, 1440×900 Metal, 「많은 기록」 더미): 주 2.5D·월 2.5D 모두 120fps(p95 9.0ms), 주↔월 모핑을 1초마다 반복하는 동안 114fps(p95 9.3ms, 가장 긴 프레임 41ms)였습니다.
- **연 2.5D의 세운 기둥**: 연 2.5D는 여전히 세운 캡슐 기둥(`capsule-board-layout.ts`의 `capsule.y`·`tile.height`, 장면의 `upright` 경로)을 씁니다. 그래서 이 경로는 지우지 않았습니다.

### 2026-11-25 배경 「새틴 리본」

사용자 결정으로 내 기록의 배경(헤더 아래, 콘텐츠 뒤)에 보라 리본이 아주 느리게 흐릅니다. 유리 블록 너머로 은은하게 비치는 것이 목적입니다.

- **출처**: Originkit 「Satin Ribbon」을 개조했습니다. 상업 서비스 사용은 가능하고 재배포·판매는 금지입니다([REFERENCE_COMMERCIAL_USE.md](REFERENCE_COMMERCIAL_USE.md)). 파일 머리에 출처 주석이 있습니다.
- **모듈**: `src/features/records/satin-backdrop/`
  - `satin-config.ts`: 색·밴드·속도·해상도·fps·빛의 모든 수치와 대비 계산(테스트 `tests/satin-backdrop.test.ts`)
  - `satin-renderer.ts`: WebGL1, 전체 화면 삼각형 하나
  - `SatinBackdrop.tsx`, `satin-backdrop.css`
- **색**
  - 바탕은 canvas `#0F0E17`입니다.
  - 리본 3줄은 로고 v2 보라 `#8053F2`~`#D4C3FA` 사이 톤(0.55·0.85·0.3)입니다.
  - 리본은 바탕 위에 0.24배로만 더해져 어둡게 유지됩니다. 흰 광택(스펙큘러 0.08, 시스루 광택 0.05)과 라벤더 실선(`#D9CEFB`, 0.06)도 아주 약하게만 둡니다. 금색·무지개색은 없습니다.
- **배치**: 리본 밴드는 화면 위(0.3·0.43)와 아래(−0.36)에 대각선으로 놓았습니다. 화면 가운데(보드)는 35% 어둡게 합니다. 보드 무대는 불투명 캔버스라 리본이 보드 위를 지나가지 않습니다.
- **움직임**
  - 출렁임 한 번이 약 35초입니다(0.18rad/s, 두 번째 물결은 −0.6배).
  - 마우스 hover 반응은 없앴습니다. 광원만 포인터 쪽으로 아주 조금(±0.18) 아주 천천히(초당 0.5) 따라옵니다.
  - 움직임 줄이기 설정에서는 정지된 한 장면입니다.
- **등장**(2026-11-25 사용자 피드백): 내 기록에 들어오면 리본이 바탕에서 서서히 떠오릅니다(`satin-config.ts`의 `reveal`).
  - 셰이더의 리본 밝기(gain)를 0에서 목표값까지 ease-out(cubic)으로 올립니다. 캔버스 opacity를 바꾸지 않아 바탕 `#0F0E17`은 처음부터 그대로입니다.
  - 그동안 각 밴드는 자기 쪽 화면 바깥으로 0.12만큼 물러나 있다가 제자리로 흘러 들어오고, 폭은 75%에서 100%로 넓어집니다. 크게 쓸고 들어오지 않도록 이 정도로만 둡니다.
  - 타이밍: 콘텐츠는 기다리지 않고 바로 보이고, 보드 기둥은 약 1.3초에 걸쳐 올라옵니다. 리본은 0.45초 뒤에 시작해 2.6초에 걸쳐 떠올라, 보드가 다 선 뒤에 자리를 잡습니다(진입 후 약 3초).
  - 다시 들어올 때(같은 페이지 로드에서 다른 탭에 갔다가 돌아와 재마운트될 때)도 매번 떠오르되, 짧게 0.15초 뒤 1.4초입니다. 이미 본 장면이라 길게 기다리게 하지 않고, 그렇다고 갑자기 켜지지도 않게 했습니다. 로딩 화면에서 기록 화면으로 바뀔 때는 같은 배경이 이어져 다시 시작하지 않습니다.
  - 진행 시간은 그린 프레임 기준이라, 탭이 숨겨진 동안에는 멈췄다가 돌아오면 이어집니다. 30fps 상한·화면 밖 정지는 그대로입니다.
  - 움직임 줄이기: 등장 없이 정지 장면이 바로 보입니다. WebGL이 없을 때는 CSS 그라데이션 층이 같은 지연·길이로 opacity 0→1로 나타납니다(움직임 줄이기에서는 바로).
- **성능**
  - 그리는 버퍼는 CSS 크기의 0.4배입니다(devicePixelRatio 무시, 1440×900 → 576×360). 최대 30fps입니다.
  - 탭이 숨겨지거나 화면 밖이면 정지합니다. 언마운트 때 버퍼·프로그램·셰이더를 정리하고, 컨텍스트 손실과 복구를 처리합니다.
  - 2026-11-25 측정(1440×900 Metal): 「올해 매일」 연 2.5D 1,593캡슐 보드가 리본이 있어도 없어도 120fps(p95 8.9ms 대 8.7ms)였습니다. 리본은 초당 30회 그립니다.
- **대비**: 한 번 출렁이는 동안 측정한 가장 밝은 리본 픽셀은 `rgb(60,55,79)`였습니다. 그 위에 유리가 덮인 블록에서 가장 옅은 `subtle` 글자도 6.5:1 이상이었습니다(측정 중앙값). 테스트는 유리 없이 계산해도 4.5:1 이상인지 확인합니다.
- **WebGL 없음**: 같은 보라의 정지 CSS 그라데이션으로 대체합니다(등장 때 opacity로 서서히).
- **겹침 순서**: 배경은 `position: fixed; z-index: -1`입니다. 내 기록에서만 `.app-shell`을 쌓임 맥락으로 만들어(`isolation: isolate`), 셸의 캔버스 색 위·콘텐츠 아래에 놓입니다. 헤더는 불투명이라 리본이 비치지 않습니다.

## 공부 종료와 캡슐카드

종료 화면은 룸 이름을 제목 아래에, 완료 시각과 대화 옵션을 별도 메타 정보 행에 표시합니다. 장식용 CAPSULE 문구, 얼굴 관측 시간 설명과 인물 하단의 관계 배지는 표시하지 않습니다. 집중률·집중·미감지·복귀는 실제 기록 값을 유지하며 미측정은 `—`입니다.

함께 공부한 친구별로 이번에 더한 시간을 표시합니다. `reportRelationship`은 해당 공부 이전 기록만 합산하고, 기존 친구별 시간 배분과 600분 단위 레벨 규칙을 사용합니다. 진행 바는 이전 값에서 실제 증가량까지 움직이며, 레벨을 넘으면 끝까지 채운 뒤 축하 효과와 새 레벨 진행도를 표시합니다. 최대 Lv.5는 완전히 채워진 상태를 유지합니다. 움직임 줄이기에서는 최종 값과 정적인 안내만 표시합니다.

채린·수아·다희의 완료 전용 이미지 (2026-11-25 정리에서 삭제)를 리포트와 캡슐카드에서 함께 사용합니다. 해당 공부에 참여한 친구만 선택할 수 있으며 선택은 `friend` 쿼리로 이어집니다. 다른 친구는 기존 장면을 유지합니다.

캡슐카드의 공식 로고와 왼쪽 위 투명 제목은 기존 홈 에셋을 재사용합니다. 미리보기와 실제 720×1200 PNG에 동일한 선택 인물·로고·제목을 합성합니다. PNG는 카드 색 선택을 반영하고 다음 공부 약속과 저장·공유 흐름을 유지합니다.

로고의 흰 바탕은 제거했습니다. `CapsuleCardBrand`는 보라·검정 카드의 글자 부분에만 밝은 색을 입히고 밝은 카드에서는 원래 보라색을 사용합니다. 캡슐 아이콘의 색·입체감·투명 여백은 유지하며 은은한 그림자로 구분합니다. PNG에도 같은 글자 색과 투명 배경을 반영합니다.

이미지 저장·스토리 공유는 실제 포인터 위치와 관계없이 정중앙 호버의 색감을 고정합니다. `capsule-card-material.ts`가 미리보기의 그라데이션·호버 강도와 Canvas의 배경 합성을 공유하며, 반짝임과 빛 반사를 콘텐츠 뒤에 그립니다. 터치·움직임 줄이기에서도 같은 정적 PNG를 생성하고 저장·공유·공유 미지원 시 다운로드에 동일한 파일을 사용합니다.

왼쪽 미리보기의 `CapsuleCardSurface`는 포인터 위치에 맞춰 카드 기울기·홀로그램 반사·반짝임을 갱신합니다. 사진·로고·공부 시간을 서로 다른 깊이에 놓고, 키보드 초점에서는 고정된 기울기를 사용합니다. 터치 스크롤을 유지하며 움직임 줄이기 설정에서는 정적인 카드로 표시합니다. 오른쪽 설정에서는 안내 문단 두 개와 오늘·내일·모레 바로가기를 제거하고 날짜·시간 휠로 약속을 정합니다.

이 절이 앞의 2D(누운 칩)·기본값·캡슐 달력·연 2.5D 세운 기둥·「최근 연결」 설명보다 우선합니다.

  - 마우스·포커스 툴팁: 날짜, 함께한 시간, 「전체」에서 메이트가 2명 이상이면 메이트별 시간. 누르면 그날 기록 카드가 열립니다(실제 연결이 있는 날). 방향키 이동(연 ↑↓ 하루·←→ 한 주, 월 ←→ 하루·↑↓ 한 주, 주 ←→, Home/End), 칸마다 화면 읽기 레이블.
  - 범례는 「적음 ▢▢▢▢▢ 많음」 하나입니다. 「캡슐 1개 = 30분 · 색은 만난 시간대」와 「칩 1개 = 30분 …」 문구는 지웠습니다.
  - WebGL이 없을 때도 이 잔디를 씁니다(토글 숨김). 장면의 2D(누운 칩) 경로는 이제 쓰이지 않지만 장면 전체에 얽혀 있어 남겨 두었습니다.
- **기본 보기 2D**: 저장된 선택이 없으면 주·월·연 모두 2D입니다(`defaultBoardView`). 이미 2.5D를 고른 사용자의 저장값(`capsule-records-board-view:v2`)은 그대로 둡니다.
- **연 2.5D도 유리 기둥**: 연만 예전 세운 캡슐 기둥(캡슐 1개 = 30분, 4시간 상한 압축)이라 주·월과 다르게 보였습니다(`pillarsApply('year')`가 false). 38 연동(연 = MONTH 12번 읽기)과는 무관하고, 2026-11-25 유리 기둥 결정 때 연을 일부러 제외한 것이 원인이었습니다. 이제 연도 같은 규칙(기간의 가장 긴 날을 시간 단위로 올림한 높이, 캡슐은 기둥 안에 눕힘)을 쓰고, 기둥은 더 가늘고 낮습니다(`pillarDims('year')`). 「올해 매일」 더미(365칸·캡슐 1,603개)에서 120fps(p95 9.3ms).
- **「최근 연결」 섹션 삭제**: 38 `recent[]`는 보드에서 실제 연결 기록 카드를 여는 데만 씁니다. 선택한 날 목록의 `RecordConnectionRow`는 남기고 날짜 표시 분기(`when='date'`)와 섹션 CSS를 지웠습니다.
- **메이트 칩**: 연결한 메이트가 2명 이상일 때만 보이는 조건은 그대로입니다.
- **전환 연출 되살리기**(2026-11-26, 사용자 요청): [grid-morph.ts](../src/features/records/grid-morph.ts) · [BoardViewSwitch.tsx](../src/features/records/BoardViewSwitch.tsx)
  - 주·월·연 전환(2D): 날짜를 key로 한 FLIP입니다. 같은 날짜 칸은 새 자리·크기로 움직이고, 새 칸은 내려앉을 때 페이드인, 사라지는 칸은 제자리에서 페이드아웃합니다. 잔디 높이도 함께 바뀝니다(잔디는 내용 높이라 `--board-ratio` 대신 같은 850ms·같은 곡선의 높이 애니메이션). 기간 라벨은 칸이 내려앉을 때 나타납니다. 이전·다음 화살표는 240ms 가로 슬라이드입니다.
  - 2D ↔ 2.5D: DOM 잔디(주 열·요일 행)와 WebGL 장면(월 보드·기둥)은 칸 배치가 달라 완전한 morph 대신 **기울기 + 크로스페이드 근사**(520ms)입니다. 2D→2.5D는 잔디가 원근으로 뒤로 기울며 사라지고 장면이 올라오며, 반대는 장면이 사라지고 잔디가 그 각도에서 펴집니다. 장면은 숨긴 채 먼저 만들고 첫 프레임이 그려진 뒤 전환을 시작하며, 잔디가 보이는 동안 장면 청크를 미리 받아 둡니다.
  - 줄인 동작: 모두 즉시 바뀝니다. 전환 중 선택한 날은 유지하고, 포커스는 누른 탭·토글에 남습니다.
  - 성능(1440×900, 「records」 리뷰 더미): 7가지 전환 모두 50ms 넘는 프레임 0, 평균 8.3~8.6ms입니다. 월→연에서 나던 50~70ms 프레임은 `dayKey`가 호출마다 `Intl.DateTimeFormat`을 새로 만들던 비용(한 번 전환에 약 160ms)이었고, 포매터를 재사용해 없앴습니다(결과 동일).
