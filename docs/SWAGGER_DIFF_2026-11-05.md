## 현재 프런트

헤더의 내 프로필 메뉴에서 로그아웃 아래에 회원탈퇴 버튼을 연결했다. `HeaderAccount` → `AccountWithdrawalDialog` → `DemoProvider.withdrawAccount` → 공통 API client의 `DELETE /me` 순서로, 브라우저에서는 `/api/backend/me`, 백엔드에서는 `/api/me`로 전달된다. bearer 인증을 포함하며 본문은 보내지 않는다.

확인 창은 삭제 범위를 안내하고 취소 버튼에 먼저 초점을 준다. 취소는 요청을 보내지 않으며, 전송 중 중복 클릭·Escape·배경 클릭을 막는다. 409는 진행 중인 공부를 마치라는 안내를 표시하고, 다른 실패도 계정을 유지해 재시도할 수 있다. 성공하면 토큰·계정 메모리 캐시·해당 사용자의 공부 복구 정보와 로그인 임시 정보를 비우고 로그인 화면에 완료 안내를 표시한다. 별도 로그아웃 API는 호출하지 않는다. 이전 계정의 지연된 401 응답이 새 계정의 토큰으로 탈퇴 요청을 재시도하지 못하도록 공통 client도 보호했다.

브라우저에서 모든 API를 모의 응답으로 가로채 409·500·빈 본문 200, 취소 시 미호출, 처리 중 닫기 방지, 완료 안내, 다음 계정 로그인 시 이전 일정 미노출을 확인했다. 데스크톱 1280px·모바일 390px에서 확인했으며 JavaScript 오류는 없었다. 린트·빌드 및 단위 테스트 219개가 통과했다. 실제 계정의 탈퇴 요청은 실행하지 않았으며, 실제 백엔드의 삭제·쿠키 폐기 동작은 미검증이다.
