# 현재 API 계약 대조와 프런트 수정 · 2026-11-22

## 기준과 결과

사용자의 **“API를 자세하게 대조하고 API에 맞춰”** 요청에 따라 최종 베타 화면의 데이터 계약을 가정하지 않고, 현재 제공되는 API의 요청·응답·오류를 기준으로 수정했다.

- 배포 [OpenAPI](https://api.capsule.ai.kr/v3/api-docs): **24개 경로 / 27개 작업 / 69개 스키마**. 앞선 11/22 스냅샷과 JSON 전체 내용이 같다. 원본은 `.temp/api-audit-openapi-2026-11-22.json`.
- 공개 백엔드 `develop`: 재조회한 커밋은 **`de5aa98f352a173c9ba11c72b0eb27dfce281b15`**. [컨트롤러·서비스·DTO·설정·API 테스트](https://github.com/LIKELION-CAPSULE/Backend_lab/tree/de5aa98f352a173c9ba11c72b0eb27dfce281b15/src)를 함께 읽었다. 개발 소스의 커밋을 확인한 것으로, 배포 바이너리의 동일 버전을 증명한 것은 아니다.
- 로컬 `API관련/API 최종`의 개별 요청 문서도 대조했다. 공부 시작 문서는 `targetMinutes` 필수·기본 **50분**, heartbeat 문서는 두 시간 값 필수로 설명한다. 다만 이 자료에는 새 공통 성공 envelope·SSE·비밀번호 재설정·탈퇴의 최신 내용이 모두 반영돼 있지 않으므로 현재 OpenAPI와 소스를 우선했다.
- TypeScript 객체 타입 **50종 / 195개 필드**의 이름·primitive/ref/array/enum·필수 여부를 기계 대조했다. 설명되지 않은 필드/타입 차이는 **0개**다. 서비스에서 요구하는 필드 **20개**와 이벤트 enum 제한은 OpenAPI보다 엄격하게 반영했다. 전체 결과·27개 작업의 요청/응답 정의는 [API_AUDIT_2026-11-22.json](API_AUDIT_2026-11-22.json).

## 발견한 문제와 수정

| 문제 | 실제 서버 조건 | 수정 |
|---|---|---|
| 새 연결이 HTTP 400 | OpenAPI는 `targetMinutes` 선택이지만 `SessionService.start`는 누락을 `INVALID_TARGET_MINUTES`로 거절 | `roomId`, `characterId`, `targetMinutes`를 함께 보낸다. 직접 연결은 기존 기본값 **50** 사용. 명시한 값은 **3 또는 5~180의 5분 단위**만 허용하고, 유효하지 않으면 POST 전에 거절 |
| 이력 없는 복구 뒤 heartbeat 400 | 본문이 없거나 두 시간 값 중 하나라도 없으면 `INVALID_STUDY_TIME`. 생존 신호만 갱신한 뒤 400을 반환 | 이력이 없는 복구도 보수적으로 계산한 `studySeconds`, `presentSeconds`를 항상 보낸다. 이전 미측정 구간을 자리 있음으로 만들지 않음 |
| 인증번호 재전송 버튼이 너무 빨리 열림 | `AuthService.requestVerification`의 제한은 이메일당 **1분에 1회** | 화면의 30초 제한을 **60초**로 변경. 서버의 `expiresInSeconds`를 계속 사용. 보관 미리보기의 10분 유효시간·30초 재전송도 실제 기본값 **5분·60초**로 정정 |
| 유효한 이모지 닉네임 거절 | `User.validNickname`은 Unicode code point 기준 1~20자. JS `.length`와 HTML `maxlength`는 UTF-16 단위 | 검증을 code point 수로 변경. 가입·온보딩·프로필 입력의 HTML 상한은 40 UTF-16 단위로 두고, 최종 유효성은 20 code point로 검사 |
| 오류 코드 자체가 화면에 나타나거나 원인 구분이 안 됨 | 서버의 `message`는 보통 `code`와 동일. HTTP 200인 SSE에서도 `error` 이벤트의 `code`로 판단해야 함 | 공개 API 오류의 읽을 수 있는 안내를 보완. 알 수 없는 코드에는 기본 안내를 사용하며 **status/code/detail은 그대로 보존**. SSE의 전용 오류 안내와 재시도 규칙 유지 |
| 검토 서버가 실제 API에서 실패할 요청도 성공시킴 | 목표 시간·heartbeat 필수 조건, 일부 응답 상태, raw SSE `done`과 차이 | 검토 transport에도 독립적인 필수 값 검증 추가. 회원가입 **201**, 탈퇴 **204**, 로그인 잠금 **429**, SSE `done`의 raw DTO를 반영 |

목표 시간은 **현재 API에 필요한 호환 입력**이다. 베타 화면의 카운트다운·자동 종료 조건으로 되살리지 않았다. 기존 서버는 이 값을 종료 대사의 `GIVE_UP` 판단에 전달하므로, 50분을 보내는 현재 호환 구현을 **새 무제한 연결 정책의 서버 구현 완료**로 볼 수 없다. 목표 없는 생성·저장·종료 판단 변경은 REQUEST R09에 남긴다. 이전의 “백엔드가 바뀔 때까지 새 연결을 시작할 수 없다”는 판정은 이번 사용자 요청에 따른 호환 수정으로 갱신한다.

### OpenAPI에 충분히 표현되지 않은 계약

- 요청 필수 여부: StartRequest 1개, HeartbeatRequest 2개, EventRequest 2개, EndRequest 2개, KakaoRequest 2개, PasswordResetRequest 2개, EmailRequest 1개, ConfirmRequest 2개, SignupRequest 4개, LoginRequest 2개. 이 **20개 필드**는 서비스/실제 요청 검증에 맞춰 필수 타입으로 강화했다.
- 이벤트 type의 8개 허용값은 `SessionEvent.TYPES`에서 확인했다. OpenAPI는 단순 string으로 표시한다.
- 회원가입 201 / 로그아웃 204 / 탈퇴 204 / 이벤트 201 또는 200은 컨트롤러의 실제 상태와 OpenAPI 표기가 다르다. 클라이언트는 특정 200만 강제하지 않고 성공 범위·본문 유무로 처리한다.
- 응답의 Java nullable 값은 실제로 `null`일 수 있다. 어댑터/optional chaining/빈 값 처리도 함께 읽고, 브라우저 모의 응답에 `email`, `profileImage`, `activeSessionId`, `activeSession`의 null을 넣어 확인한다. 기계 대조만으로 nullability가 증명된다고 주장하지 않는다.

## 검증과 한계

- 수정 전, 실제 서비스와 같은 목표 시간 검증을 넣은 provider 계약 테스트가 **400 INVALID_TARGET_MINUTES**로 실패하는 것을 재현했다. Unicode 닉네임 경계 테스트도 실패했다. 수정 후 통과했다.
- 전체 단위 테스트 **421개**, 린트, 타입 검사 포함 운영 빌드, `git diff --check` 통과.
- Chromium·WebKit에서 각각 **6개, 총 12개 브라우저 흐름 통과**: 신규 연결→SSE 채팅→heartbeat→종료→기록, 이전 이력 없는 복구, 이력 있는 복구, heartbeat 401→refresh→동일 본문 재전송, 이모지 20자 프로필 저장, 인증번호 재전송 30초 차단/60초 허용. 기록 화면의 모듈 로딩까지 확인했다.
- 브라우저 검증은 실제 앱/provider/화면을 사용하고 API transport와 Live2D 제작물만 격리한다. 외부 API mutation을 차단하며 운영 계정 생성·로그인 시도·세션 생성·메일 발송·차감·탈퇴를 수행하지 않는다.
- 실제 네트워크 확인은 OpenAPI/약관 GET 200과 비인증 홈 GET 401이다. 실제 계정의 인증 후 생성→재개→종료 왕복, 물리 장치·Live2D·음성·새 베타 정산은 검증 완료로 표시하지 않는다.
- 타입 대조는 `.temp/api-contract-shapes-2026-11-22.mjs`, 단위/린트/빌드 로그는 `.temp/api-alignment-*-2026-11-22.log`, 브라우저 스크립트/결과는 `.temp/api-alignment-browser-2026-11-22.mjs`와 `.temp/api-alignment-browser-results-*.json`에 보관한다.
- 브라우저 검증 서버는 `.temp/api-audit-vite.config.ts`의 별도 캐시를 사용했다. 단위 검사와 개발 서버의 기본 Vite 캐시 공유에 따른 504, 빌드 후 붙은 엔트리 쿼리 때문에 검토 모델 대신 실제 모델을 불러오던 테스트 설정을 수정한 뒤 최종 실행했다. 제품의 API 실패로 계산하지 않는다.
