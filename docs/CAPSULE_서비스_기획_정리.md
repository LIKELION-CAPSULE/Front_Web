### 제품의 두 가지 의미

- **집중 캡슐:** 공부를 시작하면 딴짓을 줄이고 사용자와 캐릭터가 함께하는 공간이 만들어진다는 의미.
- **시간 캡슐:** 함께한 공부 시간이 누적되어 관계·기억·에피소드가 된다는 의미.

### 제품의 핵심 루프

```text
스터디룸/캐릭터 선택
  → 공부 시작(웹캠·캐릭터 동반)
  → 공부 상태 추정 및 캐릭터 반응
  → 공부 시간 적립
  → 호감도 증가·대사/에피소드 해금
  → 쉬는 시간 AI 대화·공부 약속
  → 다음 날 재방문
```

**성공 기준:** 사용자가 매일 더 오래 화면을 켜두는 것만이 아니라, **혼자라면 공부를 시작하지 않았을 시간에도 다시 책상에 앉도록 만드는 것**.

## 1. 해결하려는 문제와 시장 포지셔닝

### 1.1 문제 정의

대학생은 시험과 과제로 공부해야 하지만 혼자 장시간 앉아 있기 어렵다. 스마트폰·유튜브·SNS로 주의가 새기 쉽고, 함께 공부하려고 해도 기존 수단에 제약이 있다.

| 기존 대안 | 장점 | CAPSULE 기획서에서 지적한 한계 |
|---|---|---|
| 혼자 공부 | 언제든 시작 가능 | 심심하고 딴짓으로 이탈하기 쉬움 |
| 유튜브 스터디위드미 | 무료, 분위기 조성 | 녹화 영상은 사용자를 인지하거나 반응하지 않음 |
| 디스코드·줌 모각공 | 사람과 함께한다는 감각 | 시간 조율 필요, 대화가 잡담으로 흐를 수 있음 |
| Focusmate 등 매칭 서비스 | 동반감·책임감 | 예약·매칭 필요, 낯선 사람에게 카메라를 켜는 부담 |
| 공부 타이머·랭킹 앱 | 기록·경쟁 | 타이머만 켜놓은 상태와 실제 공부를 구분하기 어려움 |
| AI 캐릭터 채팅 | 캐릭터와 애착·관계 | 공부와 직접 연결되지 않음 |

> **핵심 문제:** “새벽 2시, 혼자 공부하는 대학생에게는 언제든 함께 있고, 나를 보고 반응하며, 함께한 시간이 관계로 쌓이는 공부 메이트가 없다.”

### 1.2 경쟁·참고 서비스

- **하마하마:** 카메라 기반 공부 상태 감지의 참고 사례.
- **Focus Friend:** 집중 활동과 캐릭터 애착을 결합한 참고 사례.
- **열품타:** 기록·순위 중심 공부 앱의 대표 사례.
- **Focusmate:** 사람을 매칭해 함께 공부하는 대안.
- **크랙·제타:** AI 캐릭터와의 대화 및 관계 기반 과금 사례.

CAPSULE의 차별화 주장은 개별 감지 모델의 독창성보다는 **감지 결과를 캐릭터 반응으로 연결하고, 다시 공부 시간·관계 성장으로 잇는 제품 경험**에 있다. 원본의 경쟁사 성과 수치와 시장 통계는 작성 시점의 인용·추정으로서, 최신 사실 확인을 완료한 값은 아니다.

## 2. 목표 사용자와 사용 맥락

### 2.1 1차 타깃

- 디스코드/줌에서 친구와 각자 공부하거나 스터디위드미를 틀고 공부하는 **대학생**.
- 고강도 경쟁형 학습 관리보다 **동반감, 재미, 지속성**을 중시하는 사용자.
- 노트북 이용에 익숙하고 AI 캐릭터·웹툰·웹소설·게임·숏폼 콘텐츠에 친숙한 집단.
- 원본은 예시 타깃을 **학점 B 안팎의 ‘적당히 공부하는’ 학생층**으로 제시함. 이는 실제 성적 검증 기준이 아니라 마케팅을 위한 페르소나 설명임.

### 2.2 사용자 페르소나

| 구분 | A. 디코 모각공러 | B. 스터디위드미 혼공러 |
|---|---|---|
| 예시 | 경영학과 3학년, 동아리 활동 | 공대 2학년, 자취 |
| 공부 방식 | 친구들과 밤 10시~새벽 1시 디스코드 | 시험 1~2주 전 스터디위드미·로파이 영상 |
| 불만 | 친구가 안 들어오면 공부 시작이 어렵고, 접속하면 잡담도 함 | 영상 속 사람은 자신을 보지 않고, 결국 스마트폰을 보게 됨 |
| 기대 | 언제 접속해도 있는 공부 메이트, 쉬는 시간 대화 | 조용히 함께 있어 주고 딴짓하면 가볍게 반응하는 존재 |
| 과금 가설 | 좋아하는 캐릭터와 깊게 대화할 때 유료 등급 사용 | 출석 크레딧 사용 및 시험기간 응원 패스 구매 |

### 2.3 확장 타깃

성인 공시생·자격증 준비생, 혼자 작업하는 프리랜서·개발자, 일본 대학생. 원본은 **미성년자를 관계형 콘텐츠의 타깃에서 제외**하는 방향을 명시함.

## 3. 핵심 사용자 경험(UX)

### 3.1 한 세션의 전체 여정

| 단계 | 사용자 행동 | 캐릭터/시스템 반응 | 결과 |
|---|---|---|---|
| 시작 | 스터디룸·캐릭터 선택, 상호작용 등급 선택 | 시험 일정·지난 약속 등 기억을 반영한 인사 | 세션 생성, 카메라 보정 |
| 공부 50분 | 화면을 보거나 책 읽기·필기 | Live2D 캐릭터도 필기·책 넘기기·기지개·음료 마시기 등의 모션 수행 | 공부 상태 추정·시간 적립 |
| 딴짓 의심 | 스마트폰 사용·장시간 자리 비움·졸음 등 | 지속된 행동에만 캐릭터가 성격대로 반응 | 공부 복귀 유도 |
| 공부 복귀 | 다시 공부 상태로 돌아옴 | 복귀 칭찬, 원래 공부 모션으로 전환 | 정상 상태 유지 |
| 쉬는 시간 10분 | 캐릭터와 AI 대화 | 기억·시험 일정·관계 단계에 맞춰 답변 | 관계·몰입 강화 |
| 종료 | 세션 종료 및 결과 확인 | 집중 리포트, 공유용 캡슐 카드, 호감도·에피소드 처리 | 다음 공부 약속 및 재방문 유도 |

### 3.2 핵심 기능 명세

| 기능 | 사용자에게 보이는 동작 | 내부 요구사항 |
|---|---|---|
| **스터디룸** | 캐릭터와 나의 캠이 나란히 보이는 공부 공간 | 카메라 권한·미리보기·캐릭터 렌더링 |
| **Live2D 공부 동작** | 캐릭터가 계속 공부하는 자연스러운 모습 | 기본 모션 루프, 표정·모션 간 보간, 반응 후 복귀 |
| **딴짓 반응** | 집중 이탈 시 캐릭터가 성격에 맞게 말을 검 | 온디바이스 감지, 지속시간 판단, 반응 디렉터 |
| **복귀 반응** | 공부로 돌아오면 칭찬 | 복귀 이벤트 감지, 중복 반응 방지 |
| **휴식 중 AI 대화** | 쉬는 시간에 대화하며 관계 형성 | LLM, 캐릭터 페르소나, 기억 요약, TTS |
| **호감도** | 공부 시간에 따라 관계 단계 상승 | 유효 공부 시간 기반 누적·해금 규칙 |
| **에피소드** | 새로운 대사·장면 해금 | 캐릭터별 콘텐츠 관리, 관계 단계 연동 |
| **공부 약속** | “내일 2시에 같이 하자” 예약 | 약속 저장, 다음 접속 시 인사·반영 |
| **집중 리포트** | 공부·딴짓 시간 확인 | 세션 요약 및 결과 계산 |
| **캡슐 카드** | SNS에 공유할 세션 결과 카드 | 공유 이미지/카드 생성 |
| **카메라 없는 모드** | 웹캠 없이도 이용 | 감지 결과가 없는 상태를 구별하는 정책 필요 |

### 3.3 캐릭터와의 관계 설계

- 호감도는 **검증된 공부 시간**으로만 상승하는 것이 원칙.
- 결제나 단순 대화 횟수로 호감도·엔딩을 구매할 수 없도록 설계.
- 관계가 발전하면 **존댓말 → 반말·이름 부르기** 등 대사·태도 변화.
- 캐릭터는 사용자의 시험 일정·공부 약속·지난 대화를 기억에 반영.
- 딴짓 대응은 **훈육·처벌보다는 가벼운 놀림·재미·복귀 유도**를 목표로 함.

## 4. 딴짓 감지와 반응 엔진

> 이 절은 특히 프론트엔드 구현과 직접 연결된다. **원본 사업계획서의 설계**를 먼저 정리했으며, 현재 대화에서 논의 중인 개선 방향은 맨 아래 **「추가 검토 메모」**에 분리했다.

### 4.1 원본 문서의 감지 정책

- 사용자의 **노트북 웹캠**으로 영상 수집.
- **브라우저 내부 Web Worker**에서 프레임 처리. 초기 설계 빈도 **초당 5회**.
- **MediaPipe Face Landmarker**로 얼굴 특징점·머리 방향·눈 감김 등을 추정.
- **객체 탐지**로 휴대폰 확인. 원본의 선택 기술은 **MediaPipe Object Detector**이며, Ultralytics YOLO는 라이선스 이슈가 있는 대안으로 표기되어 있음.
- 원본 영상은 브라우저 메모리 안에서만 사용 후 폐기, **서버에 영상 전송·저장하지 않음**.
- 단일 프레임의 추정값이 아니라 **여러 프레임의 지속시간**을 기반으로 이벤트 판정.
- 사용자별 차이를 줄이기 위해 세션 시작 **5초 캘리브레이션** 계획.

### 4.2 원본의 초기 이벤트 기준

| 이벤트 | 원본의 초기 기준 | 대응 |
|---|---|---|
| 휴대폰 사용 | **3초 이상** | 캐릭터 딴짓 반응 |
| 자리 비움 | **10초 이상** | 자리 비움 반응 |
| 졸음(눈 감김) | **5초 이상** | 졸음 관련 반응 |
| 복귀 | 별도 수치 미정 | 공부 복귀 칭찬 |
| 같은 행동 반복 | 반복 횟수 활용, 구체적 기준 미정 | 눈치 → 말 걸기 → 서운함으로 강도 상승 |

**주의:** 이 값은 문서에 나온 **설계값**이지 검증된 정확도나 권장 안전 임계값은 아니다. 특히 ‘고개를 숙이고 휴대폰이 보이지 않으면 필기’라는 초기 가정은 웹캠 각도에 따라 휴대폰이 애초에 보이지 않을 수 있으므로 검증해야 한다.

### 4.3 반응 디렉터(Reaction Director)

```text
카메라 프레임
  → 얼굴/눈/휴대폰 등 신호 추출
  → 시간 기반 행동 상태 판정
  → 이벤트 확정(휴대폰·자리 비움·졸음·복귀)
  → 반복 횟수·쿨다운·현재 호감도 확인
  → 캐릭터 성격에 맞는 대사/모션 선택
  → Live2D 표정·동작 전환 + 음성 재생
  → 기본 공부 상태 복귀
```

- 동일 이벤트가 반복되면 반응 강도를 높이는 설계.
- 반응 사이에 **쿨다운**을 넣어 잦은 간섭 방지.
- 최근 사용한 대사는 가능한 한 피하고, 캐릭터의 페르소나·호감도 단계에 맞게 선택.
- 공부 중에는 자유 AI 채팅을 열지 않고, 정해진 반응 대사를 활용해 집중 방해 및 API 비용을 낮춤.

### 4.4 감지 품질 측정 목표

| 지표 | 원본 수치 | 구분 |
|---|---:|---|

## 6. AI 캐릭터, 대화, 음성

### 6.1 대화 시스템 역할

LLM은 다음에만 사용하도록 설계됨.

1. 쉬는 시간(10분)의 자유 대화.
2. 세션 시작·종료 시 개인화된 멘트.
3. 이전 대화의 요약과 장기 기억.

공부 50분 동안의 일반 딴짓 반응은 **미리 준비한 대사·음성**을 사용하며, 매번 LLM·TTS를 호출하지 않는 비용·지연 최적화 방향.

### 6.2 프롬프트 구성(4층)

```text
캐릭터 페르소나
  + 호감도 단계별 말투·행동 규칙
  + 오늘의 공부 맥락(과목, 시험 일정, 약속)
  + 사용자 기억 요약과 최근 대화
  → LLM 답변 → 필요 시 TTS
```

대화 종료 후 기억을 요약해 저장함으로써 매번 전체 대화 기록을 프롬프트에 싣지 않도록 계획.

### 6.3 두 가지 음성 경로

| 종류 | 예시 | 생성 방식 | 목표 |
|---|---|---|---|
| **사전 제작 반응 음성** | 딴짓 반응, 복귀 칭찬, 기본 인사 | 대본 확정 후 TTS/녹음 파일을 만들어 배포 | 재생 시 추가 생성비·지연 최소화 |
| **실시간 대화 음성** | 쉬는 시간 자유 대화, 개인화 문장 | LLM 응답 후 TTS API 스트리밍, 재사용 문장 캐시 | 유료 등급의 대화 경험 차별화 |

원본은 Live2D MotionSync를 사용해 음성과 입 모양을 맞추는 방향을 제시함.

### 6.4 세션 원가 가정(원본 추정)

| 등급 | AI·음성 품질 방향 | 1세트(1시간) 추정 원가 |
|---|---|---:|
| 베이직 | 사전 제작 음성, 쉬는 시간 대화 하루 3턴 | **1원 미만** |
| 스탠다드 | Claude Haiku, 기본 TTS | **약 53원** |
| 프리미엄 | Claude Haiku + 장기 기억, 고품질 캐릭터 보이스 | **약 100원** |
| 스페셜 | Claude Sonnet 등 상위 모델, 고품질 음성·기념 보이스 | **약 211원** |

가정: 공부 50분 + 휴식 10분, LLM 시간당 12회(입력 2,000토큰/출력 150토큰 가정), 기억 요약 1회, 음성 840자, 환율 1달러=1,400원. **예산 편성을 위한 내부 추정치**로, 실제 API 요금표·호출량·캐시 적중률 기준 재산출이 필요함.

## 7. Live2D 캐릭터 제작 및 UGC

### 7.1 캐릭터 제작 파이프라인(원본 계획)

```text
사용자 이미지 입력·검수
  → 레이어 분해(See-through)
  → PSD 파츠 분석·가림 보완
  → 자동 리깅(psd2live 기반 검토)
  → 메시·디포머·물리 처리
  → 품질 점검 및 필요 시 재보정
  → Live2D 모델 생성
  → 스터디룸 배포
```

- 반복 작업 자동화, 캐릭터별 품질 보정은 반자동.
- 기본 모델 생성은 수십 분, 검수 포함 1캐릭터 **1일 이내 제작 목표**.
- 서버리스 GPU를 요청 시에만 사용, **1건당 500~900원 추정**.
- 모델 생성 이후 렌더링은 사용자 브라우저에서 실행하는 방향.

### 7.2 2027년 UGC의 핵심 흐름

1. **제작:** 사용자가 캐릭터 외모·성격·말투·딴짓 반응·세계관을 설정해 스터디룸 생성.
2. **검수·공개:** 검수를 통과한 스터디룸을 공개.
3. **이용:** 다른 사용자가 무료로 공부하고, 더 깊은 대화·음성을 위해 크레딧 사용.
4. **인기 순위:** 대화량보다 **누적 공부 시간·이용자 수**를 중시.
5. **보상:** 해당 스터디룸에서 쓰인 크레딧의 **20%**를 제작자에게 배분하는 모델(정산 조건은 추가 확정 필요).
6. **성장:** 제작자 유입 → 룸 증가 → 이용자 증가 → 새로운 제작자 유입.

### 7.3 단계별 공개 범위

- 초기 UGC는 **공식 외모 중 선택**, 성격·말투·대사·세계관 커스텀부터 시작.
- 생성 파이프라인이 안정되면 **사용자가 외형을 직접 생성**하는 기능을 단계적으로 개방.
- 원본의 정책: 실존 인물 사진, 미성년자 설정, 선정적 콘텐츠 등록 금지 및 공개 전 전수 검수 계획.
- UGC의 이미지·음성 권리, Live2D SDK 이용 조건, 제작자 정산·신고·제재 정책을 서비스화 전 확정할 필요가 있음.

| 캐릭터 선물 | 간식·커피 선물과 전용 반응(호감도 상승 없음) | **100~1,000크레딧** |
| 보상형 광고(2027 상반기 계획) | 쉬는 시간/종료 후 자발적 30초 광고 → 스탠다드 10분, 하루 최대 3회 | 광고 기반 |

### 8.4 결제 경험(원본 예시)

- 세션 시작: 캐릭터가 개인화된 응원 멘트를 하고 등급별 보이스 미리듣기 제공.
- 베이직 대화 3턴 소진: 등급 올리기 제안.
- 호감도 단계 직전: 프리미엄 음성 미리듣기 등 콘텐츠 미리보기.
- 세션 종료: 집중 결과·캡슐 카드 및 기념 보이스 제안.

지나치게 압박하거나 죄책감을 주는 과금 유도 표현은 사용하지 않는 것이 원본의 제품 원칙.

1. **판정/연출 튜닝:** 감지 결과 → 캐릭터 반응으로 자연스럽게 연결되는 세부 경험.

3. **쌓이는 관계:** 누적 공부 시간·호감도·에피소드로 생기는 전환 비용.
4. **UGC 네트워크 효과:** 캐릭터 창작자와 이용자가 서로를 끌어오는 구조.

| **카메라 개인정보** | 사용자 거부감·법적 우려 | 영상 미전송·미저장, API 스키마 제한, 카메라 없는 모드 |
| **클라이언트 시간 조작** | 호감도·UGC 순위·정산 악용 | 토큰·세션·탭 가시성 검증; 완전한 증명은 어려움 |
| **LLM/TTS 원가 증가** | 무료 유저 확대 시 수익성 악화 | 공부 중 정적 음성, 유료 대화 제한, 기억 요약, TTS 캐시 |
| **UGC 권리·유해 콘텐츠** | 저작권·초상권·연령·정산 리스크 | 단계적 외형 개방, 공개 전 검수, 정책·법률 검토 |
| **상용 오픈소스 라이선스** | 라이선스 위반 가능성 | Live2D, 감지 모델, 리깅 자동화 구성요소 별도 확인 |
| **수요·매출 예측의 불확실성** | 출시 계획·마케팅 투자 위험 | 랜딩 전환율, 첫 세션 완료율, D7, 실제 결제 전환율 검증 |

## 15. 원본 문서에서 확인·결정이 필요한 항목

원본의 상충·미확정 정보는 임의로 하나로 정정하지 않았다.

1. **스터디룸 투표 인원:** 수요 검증 표에는 **84명**, 시장 진입 문단에는 **16명**으로 기재되어 있음. 기준일·집계 범위 확인 필요.
2. **휴대폰 반응 기준:** 일반 설명은 **3초**, 데모의 보수적 설정은 **5초**로 기재. 데모/출시 기준을 따로 정할지 확인 필요.
3. **화면을 내려다보는 행동:** 원본은 휴대폰이 보이지 않으면 필기로 보는 방향이나, 휴대폰 자체가 카메라 시야 밖일 수 있음. `휴대폰 미검출 ≠ 휴대폰 미사용` 원칙이 필요.
4. **휴대폰 탐지 모델:** 원본 선정은 **MediaPipe Object Detector**, 최근 구현 논의는 **YOLO 병행**. 최종 모델과 상용 라이선스 확정 필요.
5. **유저 추적:** 여러 사람 등장, 자리 이탈 후 복귀, 전방·측면 얼굴 등 상황별 사용자 선정·재선정 정책 미정.
6. **북극성 지표 명칭:** ‘월간 캡슐 이용일수(MAU)’는 통상적인 MAU 정의와 다름. 실제 KPI 계산식 합의 필요.
7. **정식 출시와 결제 일정:** 12월 결제 개시로 적힌 부분과 ‘크레딧 결제는 12월 출시 이후’라는 범위 설명이 함께 존재함. 어느 범위가 12월 필수인지 확정 필요.
8. **카메라 미사용 모드:** 공부 시간 검증·호감도 적립·랭킹에 어떤 제한을 둘지 정의 필요.
9. **API 원가와 마진:** 수치가 추정값이고 모델·음성 단가·환율에 의존. 실제 이용량 기준으로 재산출 필요.
10. **성능 vs 정확도:** M4에서의 FPS·지연 실측이 감지 정확도 90% 달성을 뜻하지 않음. 별도 라벨링 평가 필요.
11. **Live2D 모델 자동 생성:** 품질·권리·라이선스·GPU 비용 가정이 정식 검증 완료된 것은 아님.
12. **UGC 제작자 수익:** 크레딧의 20% 배분과 현금 정산의 적용 범위, 기준 금액, 환불·세금·미성년자 제외 정책 등을 명확히 해야 함.
13. **카메라 캘리브레이션:** 원본의 ‘5초 초기 보정’ 외에 힌지 각도/거리 변동·카메라 교체 시 재보정 정책이 필요.
14. **국내/일본 시장 수치 및 경쟁사 실적:** 원본의 사업 가정·인용은 **외부 검증을 별도로 하지 않았음**. 대외 발표·투자 문서에서는 최신 자료 확인 필요.

## 16. 추가 검토 메모 — 최근 딴짓 감지 기술 논의

> **주의:** 이 절은 **첨부 HWP의 확정 설계가 아니라**, 이 대화에서 논의한 개선 아이디어를 정리한 것이다. 공식 기획에 반영하려면 팀 합의와 실측이 필요하다.

### 16.1 주 사용자 선택과 재인식

- YOLO 등으로 사람을 탐지할 경우 **가장 큰 객체**만 매 프레임 선택하기보다, **좌석 영역(Seat ROI) + 사용자 추적**을 사용.
- 일시적으로 인식이 안 되는 상황과 **실제로 자리를 비우는 상황**을 별도 상태로 구분.
- 자리를 비운 뒤 돌아온 경우 **기존 추적 ID에 의존하지 않고 재선정**. 다수 인물 등장 시에는 자동 판정을 보류하거나 사용자가 직접 선택.
- 카메라만으로 복귀한 사람의 신원을 완전히 증명할 수는 없음.

### 16.2 휴대폰 사용 판단

- **사람과 휴대폰 박스의 IoU가 높다**는 조건만으로 사용 여부를 판정하지 않음. 사람이 크고 휴대폰은 작아 IoU 자체가 작을 수 있음.
- 휴대폰이 **손 근처에 있는가**, 사용자가 **휴대폰 방향을 보는 듯한가**, 그 상태가 **지속되는가**를 조합.
- 책상 위에 놓인 휴대폰이 탐지됐다는 이유만으로 딴짓이라고 간주하지 않음.
- 필요 시 MediaPipe Hand Landmarker를 추가하되, MVP에서 먼저 얼굴+휴대폰 탐지의 성능을 확인.

### 16.3 의심 점수와 관측 불가능 상태

```text
관측 신호(머리 각도·눈 위치·휴대폰·손)
  → 신뢰도/관측 가능 여부 판단
  → 행동별 위험 신호 계산
  → 시간에 따라 누적(EMA 등)
  → 서로 다른 진입/해제 임계값(히스테리시스)
  → 강한 증거가 있을 때만 반응 이벤트
```

- 단일 각도·단일 프레임으로 ‘딴짓 확정’하지 않음.
- **정상 학습 / 강한 의심 / 판단 불가 / 자리 비움**을 구분.
- 화면을 많이 젖혀 책상이 안 보이는 경우에는 휴대폰을 **미사용**이 아니라 **관측 불가**로 취급.
- 손목·휴대폰 근접 및 시선 방향은 보조 신호이며, 카메라 밖의 휴대폰 사용은 검출 불가.
- 오탐 피드백을 기록해 임계값을 보정하되, 사용자 피드백 1회로 자동 정책이 크게 변하지 않도록 제한.

### 16.4 후속 실험 추천(원본 외 제안)

1. 기기별 **카메라 각도·높이·화각**과 실제 관측 가능한 책상 영역 기록.
2. 화면 응시 / 책 필기 / 태블릿 필기 / 휴대폰 사용 / 휴식 / 이탈 / 재착석으로 테스트 데이터 수집.
3. **딴짓 탐지율**과 함께 **정상 공부 1시간당 오반응 수**를 주요 지표로 측정.
4. 모델 조합별 추론 지연·CPU/GPU 메모리·배터리 사용 측정.
5. 3초·5초 판정 임계값, EMA 시간상수 및 쿨다운에 대한 비교 테스트.

## 17. 요약 — 개발 판단의 우선순위

**필수 경험(MVP):**

1. 카메라 권한·정상 동작·중단을 안전하게 관리한다.
2. 사용자가 공부하는 동안 캐릭터가 부드럽게 공부 동작을 이어간다.
3. 딴짓 증거가 충분한 경우에만 캐릭터가 자연스럽게 반응한다.
4. 정상 공부(특히 필기·독서)를 딴짓으로 오판하는 빈도를 낮춘다.
5. 사용자는 공부·휴식·세션 종료와 결과 확인까지 한 번에 경험한다.

**그다음:** 대화·음성 품질, 기억·호감도, 리텐션, 결제, 캐릭터 다양화.

**중장기:** UGC 제작/검수/정산, 캐릭터 생성 자동화, 일본·북미 현지화.

> **핵심 제품 철학:** CAPSULE은 ‘사용자를 감시하는 공부 타이머’가 아니라, **사용자가 자발적으로 다시 공부하게 만드는 AI 캐릭터 공부 메이트**다. 감지는 그 관계를 자연스럽게 만드는 보조 기능이며, 잘못된 판정으로 정상적인 학습을 방해하지 않는 것이 중요하다.
